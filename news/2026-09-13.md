## 1. Microsoft 9月定例パッチで973件の脆弱性を修正、うち2件は既にゼロデイ攻撃で悪用

**概要**: Microsoftは2026年9月8日（米国時間）の月例セキュリティ更新（Patch Tuesday）で、Windows・Office・SQL Server等にまたがる973件の脆弱性を修正した。うち113件が「緊急（Critical）」評価であり、2件（CVE-2026-85880、CVE-2026-81963）は公開前から既に実際の攻撃で悪用が確認されていた。CVE-2026-85880はWindows ALPC（Advanced Local Procedure Call）のヒープベースバッファオーバーフロー（CWE-122）で、低権限のAppContainer内で任意コードを実行できる攻撃者がサンドボックスを脱出しSYSTEM権限まで昇格できる欠陥（CVSS 7.8）。発見はVolexityとProofpointによるもので、悪用は確認されているが公開PoCは9月9日時点で未確認とされる。CVE-2026-81963はWindows Update Stackにおけるリンク解決不備（CWE-59／CWE-284）で、同様にローカル権限昇格が可能。両者ともCISAのKEV（Known Exploited Vulnerabilities）カタログに追加された。さらにOfficeでは22件の緊急パッチのうち12件がプレビューウィンドウ（Reading Pane）経由で悪用可能とされ、ファイルを開かずプレビューするだけでコード実行に至るリスクが指摘されている。日本国内でもJPCERT/CCおよびIPAが9月9日付でこの月例更新に関する注意喚起を発行している。

**関連CBKドメイン**: ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン6（セキュリティの評価とテスト）、ドメイン7（セキュリティ運用）

**コラム**: 権限昇格の脆弱性は単体では「低リスク」に見えがちだが、初期侵入後の水平展開・権限奪取の“最後のピース”として悪用される典型例であり、CBKドメイン3が扱う最小権限・サンドボックス分離設計の限界を示す事例と言える。プレビューウィンドウ経由でユーザー操作なしにコード実行が成立する点は、パッチ適用の優先順位付け（ドメイン7の脆弱性管理・パッチマネジメント）において「ユーザー操作の要否」を評価基準に含める必要性を再認識させる。CISSP実務者はCVSS基本値だけでなく、KEVカタログ収載の有無や悪用の実態（Exploit Prediction Scoring System等）を踏まえた優先度判断を行うべきである。

## 2. SonicWall SMA1000にCVSS10.0の未認証SSRFとOSコマンドインジェクションの連鎖攻撃、悪用済み

**概要**: SonicWallはリモートアクセス製品SMA1000シリーズにおいて、CVE-2026-83548（Appliance Work Placeインターフェースの未認証SSRF、CVSS 10.0）とCVE-2026-83549（Appliance Management Console＝AMCにおけるOSコマンドインジェクション、CVSS 7.8）の2件を公表した。SSRF脆弱性はWork Placeインターフェースの想定外の代替アクセス経路に起因し、これを起点にAMCの認証済み管理者権限を要するコマンドインジェクション脆弱性を連鎖させることで、未認証のリモート攻撃者が任意のOSコマンドを実行できる。両脆弱性は既に実環境での悪用が確認されており、CISAのKEVカタログに追加済み。SonicWall SMA1000は昨年12月以降、既に複数回ゼロデイの連鎖攻撃を受けており、今回で3件目の悪用チェーンとなる。企業のリモートアクセス基盤（VPNゲートウェイ）を狙う攻撃は、境界防御の要となる機器そのものが侵害される点で影響が大きい。

**関連CBKドメイン**: ドメイン4（通信とネットワークセキュリティ）、ドメイン3（セキュリティアーキテクチャとエンジニアリング）

**コラム**: リモートアクセスゲートウェイはネットワーク境界の要衝であり、ここが侵害されると内部ネットワーク全体への足がかりを与えてしまう。SSRFとコマンドインジェクションを連鎖させる手口は、単一の脆弱性評価だけでは見落とされやすく、攻撃チェーン全体を俯瞰した脅威モデリング（ドメイン3）の重要性を示す。同一製品シリーズで短期間に複数のゼロデイ悪用が繰り返されている点は、境界防御機器への継続的な監視（ログ・異常検知）とベンダーのセキュリティアドバイザリの即時追跡（ドメイン7の脆弱性管理）が不可欠であることを裏付けている。

**コラム**: 本件は技術的な脆弱性の悪用ではなく、ソーシャルエンジニアリングと国際的な資金洗浄インフラを組み合わせた詐欺スキームであり、CBKドメイン1が扱う規制動向・コンプライアンス（AML／BSA関連の報告義務）と密接に関連する。金融機関に限らず、一般企業においても取引先や顧客からの送金要求に対する多要素での本人確認プロセスの徹底が、こうした詐欺の被害抑止に直結する。CISSP実務者は、技術対策（MFA、異常検知）だけでなく、規制当局が求める報告義務やガバナンス体制の整備がリスクマネジメントの重要な一部であることを、本件を通じて再確認すべきである。なお本件は米財務省の一次情報に基づくが、被害総額の内訳や国別詳細については報道によって表現に幅があるため、数値は概算として扱うべきである。

## 用語解説

- **CVE（Common Vulnerabilities and Exposures）**: 公開された個々の脆弱性に付与される共通識別番号。ベンダーや製品を横断して同一の脆弱性を一意に特定するために用いられる。
- **CVSS（Common Vulnerability Scoring System）**: 脆弱性の深刻度を0〜10のスコアで表す業界標準の評価基準。攻撃条件や影響範囲などの要素からスコアが算出される。
- **KEV（Known Exploited Vulnerabilities）カタログ**: 米国CISA（サイバーセキュリティ・インフラセキュリティ庁）が管理する、実際に悪用が確認された脆弱性の一覧。連邦機関には収載脆弱性への優先的な対応が求められる。
- **ゼロデイ（0-day）**: ベンダーが修正パッチを提供する前に、脆弱性が発見・悪用されている状態、またはそのような脆弱性自体を指す。
- **SSRF（Server-Side Request Forgery）**: サーバー側の処理を悪用し、本来アクセスできないはずの内部リソースやサービスに対して攻撃者が意図した通信を行わせる攻撃手法。
- **RCE（Remote Code Execution）**: リモートの攻撃者が対象システム上で任意のコードを実行できる状態を指す、影響度の高い脆弱性区分。
- **OSコマンドインジェクション**: アプリケーションの入力処理の不備を突き、OSのコマンドを不正に実行させる攻撃手法。
- **ALPC（Advanced Local Procedure Call）**: Windows内部でプロセス間通信を行うための仕組み。ここでの脆弱性はローカルでの権限昇格に悪用され得る。
- **バッファオーバーフロー**: プログラムが確保したメモリ領域を超えてデータを書き込んでしまう不具合。攻撃者に悪用されるとコード実行や権限昇格につながる。
- **サンドボックス（AppContainer）**: アプリケーションの実行環境を隔離し、万一侵害されても影響範囲を限定する仕組み。Windowsではローコード権限で動作するアプリの隔離に用いられる。
- **WAF（Web Application Firewall）**: Webアプリケーションへの不正な通信パターンを検知・遮断するセキュリティ製品。
- **FIM（File Integrity Monitoring／ファイル完全性監視）**: 重要なファイルへの不正な改ざんを検知する仕組み。
- **AI エージェント**: 与えられた目標に対し、外部ツールや情報を自律的に活用してタスクを遂行する生成AIベースのソフトウェア。近年、攻撃の自動化にも悪用され始めている。
- **TTPs（Tactics, Techniques, and Procedures）**: 攻撃者が用いる戦術・技術・手順の総称。脅威インテリジェンス分析やMITRE ATT&CKなどのフレームワークで用いられる分類概念。
- **二重恐喝（Double Extortion）**: ランサムウェア攻撃において、データの暗号化に加え窃取したデータの公開を脅すことで支払いを強要する手口。
- **イミュータブルバックアップ**: 一定期間、変更・削除ができないよう保護されたバックアップ。ランサムウェアによる暗号化・削除からの復旧を担保する。
- **SAR（Suspicious Activity Report／疑わしい取引報告）**: 金融機関が資金洗浄やその他の不正が疑われる取引を規制当局に報告する制度上の書類。
- **AML（Anti-Money Laundering／マネーロンダリング防止）**: 犯罪収益の資金洗浄を防止するための法規制・体制の総称。
- **多要素認証（MFA）**: パスワードに加え、ワンタイムコードや生体情報など複数の要素を組み合わせて本人確認を行う認証方式。
- **サプライチェーンリスク**: 自組織だけでなく、取引先・委託先・利用製品／サービスのベンダーを経由して発生するセキュリティリスク。
- **構成管理（Configuration Management）**: システムやネットワークの設定を正しい状態に保ち、変更を記録・統制するプロセス。意図しない設定変更や露出を防ぐ。
- **シークレット管理**: APIキーやパスワードなどの機密情報を、コードや設定ファイルに直書きせず安全に保管・利用するための仕組みや運用。
