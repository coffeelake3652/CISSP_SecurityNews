## 1. Ivanti Connect Secure: 認証バイパス＋RCE＋権限昇格の3段チェーンが悪用（CVE-2026-104935）— 完全パッチ済み環境でも侵害、権限昇格の修正は未提供

**概要**
Volexityは2026年10月13日、Ivanti Connect Secureに対する3つの脆弱性を連鎖させた攻撃を報告した。最初の2つ（CVE-2026-104935、Ivanti評価CVSS 8.6、CISAのCVEエントリでは悪用「active」・技術的影響「total」）で未認証の攻撃者が `cgi-server` ユーザ権限でコードを実行でき、3つ目の権限昇格（CVE番号は記事上未記載）でrootを奪取する。Volexityが確認した被害者は1組織で、悪用は10月3日に開始。被害機器は22.8R2.4（完全パッチ済みとされる）で動作していた。侵害後、攻撃者は保存された資格情報（LDAPドメイン認証情報を含む）を窃取し、Active Directoryからパスワードを探索、パスワードスプレーを実行した。特筆すべきは永続化手段（バックドア/Webシェル）を残さず、コマンドごとにチェーン全体を再実行した点で、メモリ上のライブラリのみを改変して設定データを元に戻すため、Ivanti Integrity Checker Toolでは検知できなかった。修正版は25.1.3.0以降（22.8R2.5、25.1.3.1も非影響）で、2件は修正済みだが権限昇格の修正は「今後数週間のリリース」予定でありパッチは未提供（公開予定日は未確定）。Volexityは攻撃者をUTA0576として追跡し、低い確度で金銭目的と評価している。なお、The Hacker Newsの10/31付け見出しでは、CISAが「Ivanti Connect Secureの2件の脆弱性」をKEVに追加したと伝えている（本文は未確認のため単一情報源扱い）。同時にIvantiはXtraction（CVE-2026-106042, CVSS 9.9）とNeurons Patch for Intune（CVE-2026-109412, CVSS 9.9）も修正したが、悪用は未確認とされている。

**関連CBKドメイン**: ドメイン7（セキュリティ運用）、ドメイン4（通信とネットワークセキュリティ）、ドメイン5（アイデンティティおよびアクセス管理）

**コラム**
境界VPN機器は「パッチを当てれば安全」という前提が崩れやすい資産であり、整合性検査ツールをすり抜けるメモリ内改変は、ホストベースの完全性検証だけに依存するリスクを示す（ドメイン7）。VPN装置に保存されたLDAP資格情報が横展開の起点になるため、サービスアカウントの最小権限化・資格情報のローテーション・AD側のパスワードスプレー検知（ドメイン5）が補完統制となる。権限昇格の修正が未提供の間は、管理インターフェースの露出制限、ログの外部転送とアノマリ検知、侵害前提でのAD監視（ドメイン4/7）で時間を稼ぐ判断が必要だ。

## 2. WordPress Core にwp-content/upgrade経由の未認証RCE — WordPress 7.1.4で修正、公開24時間で約63,000件の攻撃試行

**概要**
WordPress 7.1.4が2026年10月28日にリリースされ、WordPress Core自体（プラグインではない）の未認証リモートコード実行の脆弱性が修正された。CVSS 8.1、CVE番号は記事執筆時点で未割当、研究者Umut Bayramの報告による。影響範囲は4.7〜7.1.3で、4.7系までバックポートされたが4.6以前は修正対象外である。コア更新時にファイルが `wp-content/upgrade` 配下の予測可能なステージングディレクトリに展開され、Web経由でアクセス可能な短時間にインストーラへリクエストするとPHPコード実行に発展する。公開される時間は数秒のため、攻撃者はポーリングで狙う。Wordfenceによると、ファイアウォールルール公開後最初の24時間で62,969件のエクスプロイト試行をブロックし、最初の一致はルール公開から9分後だった。確認された侵害は報告されていない（10/30時点、techaeris記載・Wordfence情報）。The Hacker Newsの見出しでも同脆弱性が「in the wild」で悪用されていると伝えている。

**関連CBKドメイン**: ドメイン8（ソフトウェア開発セキュリティ）、ドメイン7（セキュリティ運用）

**コラム**
自動更新機構そのものが攻撃面になる事例であり、「更新処理中の一時状態」はレースコンディション系の設計レビュー対象となる（ドメイン8）。運用面では、自動更新の有効化に加え、`wp-content/upgrade` のWeb直接アクセス拒否（WAF/Webサーバ設定）を多層防御として実装できる。修正公開から攻撃開始まで9分という速さは、パッチ適用SLAを「日」単位でなく「時間」単位で設計すべきクラスの資産（インターネット公開CMS）が存在することを意味する（ドメイン7）。PHP2Shellとの重なりで、PHP/CMS基盤の棚卸しも並行したい。

## 3. Drupal Commerce Core の認可不備（CVE-2026-118539）が悪用中 — 「Highly critical」

**概要**
Drupalは2026年10月（The Hacker News記事は10月30日付）、Commerce Coreモジュールの重大な認可不備CVE-2026-118539が実環境で悪用されていると警告した。ルートやエンティティフィールドの保護が不十分でアクセス制御をバイパスできる「Missing Authorization」で、影響は Commerce Core 0.0.0〜2.41、および3.0.0〜3.3.13。修正は3.x系で3.3.13、旧系統で8.x-2.41へのアップグレード。CVSSは記事上N/A、悪用の規模や攻撃者に関する詳細は公開されていない。報告者はDan Puccetti、Marcus Johansson、Robert Snyderと記載。SecurityWeekは「オンラインストアに対して悪用」と報じており、ECサイトが標的になっている。同時期にDrupalは39件のアドバイザリを公開したとされる（The Droptimes、単一情報源）。

**コラム**

## 4. BlackX UEFIブートキット: Baton Drop（CVE-2022-21894）でSecure Bootを回避、APT41関与を示唆

**概要**
Kaspersky発の報告（BleepingComputer/The Hacker News、2026年10月23日）によると、UEFIブートキット「BlackX」がCVE-2022-21894（Baton Drop、CVSS 4.4）を悪用してSecure Bootを回避している。管理者権限を得た後、`C:\ProgramData\Intel\` に `inst.exe` と暗号化ファイルを配置し、システム/UEFIパーティションへの書き込みでMachine Owner Key（MOK）を登録、任意のEFIファイルを読み込めるようにする。UEFIペイロードは悪意あるカーネルドライバを注入し（署名証明書は発行元により失効済み）、エンドポイントセキュリティ製品を妨害したうえで、Google Drive/OneDrive/Yandex.DiskをC2に使うRATや、Rust製プラグインローダ（OxiDLLRunner）を展開する。Kasperskyは2026年初頭にタジキスタン・ウズベキスタン・トルクメニスタンの外交機関を狙った活動でAPT41を疑い、BlackLotusの改良版と評価。ESETはAPT41傘下とされるFishMongerとの類似を指摘するが断定は避けている。Microsoftの修正は存在するが不完全で、Windows Production PCA 2011証明書（2026年10月19日に期限切れ）をDBXに追加する手動の失効手順を実施しない限り、パッチ適用済みでも侵害され得る。

**関連CBKドメイン**: ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン7（セキュリティ運用）

**コラム**
ハードウェアベースの信頼の起点（Root of Trust／Secure Boot）が破られると、OS上のEDRは「見られる側」になるため、信頼境界の設計（ドメイン3）が根本から問われる。証明書の失効（DBX更新）は自動で完結しないため、構成管理とファームウェア/ブート構成の資産管理が運用側の責任となる（ドメイン7）。実務では、DBX適用状況の棚卸し、BitLocker/TPMのPCR測定ベースの構成監視、管理者権限の特権アクセス管理（PAM）の徹底が鍵となる。証明書期限切れは「失効の好機」でもあり、期限管理と失効計画を連動させたい。

## 用語解説

- **CVE**: 脆弱性に付与される共通識別子。製品や情報源をまたいで同じ脆弱性を指すために使う。
- **CVSS**: 脆弱性の深刻度を0〜10で表す共通評価指標。9.0以上は「緊急」とされる。
- **KEV（Known Exploited Vulnerabilities）**: CISAが管理する「実際に悪用が確認された脆弱性」の一覧。連邦機関に修正期限が課される。
- **ゼロデイ**: 修正パッチが提供される前から悪用されている脆弱性。
- **RCE（リモートコード実行）**: ネットワーク越しに攻撃者が任意のコードを実行できる脆弱性。
- **認証バイパス**: ログインなどの認証手順を回避して不正にアクセスできてしまう欠陥。
- **権限昇格**: 低い権限で得たアクセスから、管理者（root）などより高い権限へ引き上げる攻撃。
- **パスワードスプレー**: 多数のアカウントに対し、少数のよくあるパスワードを試す総当たり攻撃。ロックアウトを避けやすい。
- **LDAP / Active Directory（AD）**: 組織内のユーザやPCを一元管理するディレクトリサービスとその問い合わせ手段。
- **VPN**: 外部ネットワークから社内ネットワークへ安全に接続するための仕組み。境界機器として狙われやすい。
- **Integrity Checker Tool**: 機器内のファイルが改ざんされていないかを確認する整合性検査ツール。
- **Webシェル**: Webサーバに設置され、遠隔から操作するための不正スクリプト。
- **CMS**: Webサイトの更新・管理を行うソフトウェア（WordPress、Drupalなど）。
- **WAF**: Webアプリケーション向けのファイアウォール。攻撃的なリクエストを遮断する。
- **認可不備（Broken Access Control）**: 認証済みでも「許可されていない操作」ができてしまう制御の欠陥。
- **SDLC**: ソフトウェア開発ライフサイクル。設計・実装・テスト・運用の各段階を指す。
- **UEFI / Secure Boot**: OS起動前のファームウェアと、署名済みのソフトだけを起動させる保護機能。
- **ブートキット**: OSより前の起動段階に潜み、セキュリティ製品より先に動作するマルウェア。
- **MOK（Machine Owner Key）**: 利用者が登録する起動用の信頼鍵。悪用されると不正なEFIファイルを読み込ませられる。
- **DBX**: Secure Bootで読み込みを禁止する署名・証明書の失効リスト。
- **BlackLotus**: Secure Bootを回避する先行のUEFIブートキット。
- **APT41**: 中国関連とされる、諜報と金銭目的の双方を行う攻撃グループ。
- **C2（コマンド&コントロール）**: 攻撃者が感染端末を遠隔操作するための通信基盤。
- **EDR**: 端末上の不審な挙動を検知・対応するセキュリティ製品。
- **PAM（特権アクセス管理）**: 管理者権限などの特権アカウントを厳格に管理・監査する仕組み。
- **TPM / PCR**: 起動状態の測定値を安全に記録するハードウェアチップと、その記録領域。
- **AOS-8 / AOS-10**: HPE Arubaのネットワーク機器向けOSの世代。
- **SQLインジェクション**: 入力値を通じて不正なデータベース命令を実行させる攻撃。
- **コマンドインジェクション**: 入力値を通じてOSコマンドを不正に実行させる攻撃。
- **バッファオーバーフロー**: メモリ領域を超えて書き込み、動作を乗っ取る不具合。
- **PoC**: 脆弱性が実際に悪用可能であることを示す概念実証コード。
- **クレデンシャルスタッフィング**: 漏えいしたID・パスワードの組を他サービスに試す攻撃。
- **フィッシング**: 偽のメール等で情報を盗む詐欺手法。
- **ランサムウェア**: データを暗号化して身代金を要求するマルウェア。
- **サプライチェーン攻撃**: 委託先や取引先など、関連組織を経由して標的を侵害する攻撃。
- **BIA / RTO / RPO**: 事業影響分析、目標復旧時間、目標復旧時点。事業継続計画の基本指標。
- **SBOM**: ソフトウェアの構成部品を一覧化した部品表。脆弱性の影響範囲特定に役立つ。
- **SEC開示**: 米国上場企業が証券取引委員会へ行う重要事象の報告。
- **PCI DSS**: カード情報を扱う組織向けの国際的なセキュリティ基準。
