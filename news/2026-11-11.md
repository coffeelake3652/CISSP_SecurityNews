## 1. Microsoft 2026年11月 Patch Tuesday：悪用済み Outlook ゼロデイ（CVE-2026-124194）と1,000件超の修正

**概要**
Microsoft は 2026-11-10（米国時間）に月例セキュリティ更新を公開した。Tenable の集計では修正CVEは1,093件（Critical 63、Important 1,029、Moderate 1）で、BleepingComputer の見出しは1,235件としており、集計範囲（Chromium系Edge・サードパーティ由来CVEや再発行分を含むか否か）の違いとみられるが、差の理由は確認できていない。悪用が確認されたゼロデイは Microsoft Outlook のなりすまし脆弱性 CVE-2026-124194（CVSS 6.5、深刻度Moderate）1件で、細工された Office ファイルを開かせることで標的の NTLMv2 ハッシュを外部へ送出させ、後続のなりすまし（リレー／オフライン解析）攻撃に利用できる。Microsoft のアドバイザリでは、LLM（Claude）を利用した研究者による報告とクレジットされている。Critical の中では、Active Directory ドメインサービスのRCE（CVE-2026-118146、CVSS 8.8、認証済み攻撃者・「悪用の可能性が高い」）、Exchange Server のRCE（CVE-2026-118207、CVSS 8.8）、Schannel のタイミング差を突く未認証RCE（CVE-2026-119952、CVSS 8.1）、Windows NAT のRCE（CVE-2026-113862、CVSS 8.1）が注目される。また SharePoint Server の権限昇格 CVE-2026-120002 は CVSS 9.9 ながら Important 評価とされており（Tenable記載のまま）、スコアと深刻度の不整合に注意が必要。製品別では Word 65件、Excel 64件、SQL Server 53件が多い。攻撃グループ名は公表されていない。

**関連CBKドメイン**: ドメイン7（セキュリティ運用）、ドメイン5（アイデンティティおよびアクセス管理）、ドメイン4（通信とネットワークセキュリティ）

**コラム**
1か月で1,000件超という件数は、全件を同じ優先度で処理する運用がもはや成立しないことを示しており、KEV掲載・悪用確認・EPSS・資産重要度によるリスクベースのパッチ優先順位付け（ドメイン7）が不可欠である。今回のゼロデイは NTLM ハッシュ窃取型で、パッチ適用と並行して SMB 送信（TCP 445）の外部遮断、NTLM 制限ポリシー、SMB署名／LDAP署名・チャネルバインディングの強制といった多層防御（ドメイン4・5）で被害を局限できる。AD DS と Exchange の Critical は「認証済み攻撃者」が前提だが、フィッシングで得た一般ユーザー資格情報からドメイン全体へ横展開される典型経路であり、ドメインコントローラを最優先で適用すべきである。AI支援による脆弱性発見が増えると月次パッチ件数はさらに膨らむ前提で、テスト・段階展開のプロセス自体を見直す時期にある。

## 2. Google Chrome、2026年8件目の悪用済みゼロデイ CVE-2026-125350（XML の Use-After-Free）を緊急修正

**概要**
Google は 2026-11-09（月）に Chrome の安定版更新を公開し、XML 処理コンポーネントの Use-After-Free 脆弱性 CVE-2026-125350（深刻度High、CVSSは未公表）を修正した。Google は「この脆弱性のエクスプロイトが実環境に存在することを認識している」としており、2026年に悪用が確認された Chrome ゼロデイとしては8件目となる（これまでに CVE-2026-2441、-3909、-3910、-5281、-11645、-85046、-87491）。報告者は匿名の研究者で、報告日は 2026-11-06 と、報告から3日で修正版が出た計算になる。修正版は Windows/macOS 向け 157.0.8103.50/.51、Linux 向け 157.0.8103.50 で、今回の更新では合計9件の脆弱性が修正された。攻撃者や標的、悪用手法の詳細は、利用者の大半が更新するまで非公開とされている。Edge・Brave・Opera など Chromium ベースのブラウザにも順次波及する見込み。

**関連CBKドメイン**: ドメイン7（セキュリティ運用）、ドメイン8（ソフトウェア開発セキュリティ）、ドメイン3（セキュリティアーキテクチャとエンジニアリング）

**コラム**
ブラウザは最も攻撃面の大きいクライアントアプリであり、自動更新が有効でも「再起動されるまで旧版のまま」という運用上のギャップが残る。エンドポイント管理ツールで実行中バージョンを可視化し、強制再起動の猶予期限をポリシーで設定することが実効的な対策となる（ドメイン7）。Use-After-Free は C/C++ のメモリ安全性問題の典型で、Google が Rust 等メモリ安全言語への移行やサンドボックス強化を進める背景でもある（ドメイン8・3）。詳細非公開の期間は検知シグネチャが乏しいため、ブラウザ分離やEDRの振る舞い検知といった補完統制の価値が高まる。

## 3. CISA KEV に FreeSWITCH・GPUStack・IBM Aspera Faspex を追加（対応期限 11/12、いずれも CVSS 9.8）

**概要**
CISA は 2026-11-09、OpenSSH「SSHole」（前日版で詳報）とともに3件を既知の悪用された脆弱性（KEV）カタログに追加し、連邦民間機関に 2026-11-12 までの対応を求めた（報道によれば BOD 26-04 に基づきフォレンジックトリアージも要求）。①SignalWire FreeSWITCH の CVE-2026-116779（CVSS 9.8）は、SIP MESSAGE の処理に起因するコマンドインジェクションで、細工したメッセージが内部のAPIコマンドインタフェースに到達し、FreeSWITCH プロセス権限でOSコマンド実行・設定や資格情報の窃取・通話操作が可能となる。影響は 1.11.2 以前、修正は 1.11.3 で、既定プロファイルでは `enable-chat=false` を設定しない限り到達可能とされ、SignalWire 自身が実環境での悪用を確認している。②AI推論基盤 GPUStack の CVE-2026-102895（CVSS 9.8）は、同一ホスト上のリバースプロキシ経由（送信元が 127.0.0.1 になる）や偽装した `X-GPUStack-Real-IP` ヘッダでループバック扱いとなり、組み込み管理者として認証をバイパスできる。永続的な管理APIキーの作成、シークレット窃取、`/v2/inference-backends/from-yaml` 経由のコード実行が可能で、2.2.0 未満が影響（2026-07-31 に GHSA 公開済み）、2.1.1 環境で悪意ある推論バックエンドからリバースシェルが起動された事例が報告されている。③IBM Aspera Faspex 5 の CVE-2026-123218（CVSS 9.8）は認可不備により管理者権限を取得できるもので、5.0.0〜5.0.19 が影響、5.0.19 PL1 で修正（IBM 公表は 2026-11-07）、回避策はない。悪用の具体的な観測者・攻撃者名は公表されておらず、露出インスタンス数も不明。

**コラム**
GPUStack の事例は「送信元IPがループバックなら信頼する」という暗黙の信頼が、リバースプロキシ配置やヘッダ偽装で容易に崩れることを示す典型で、ゼロトラストの原則（場所ではなく認証・認可で判断）をAIインフラにも適用すべきである（ドメイン5・8）。GHSA 公開から3か月以上経って KEV 入りしており、AI/ML 基盤が従来の脆弱性管理の対象外に置かれがちな現状を反映している。FreeSWITCH は VoIP 基盤がIT資産台帳から漏れやすい点、Aspera はファイル転送製品（MOVEit・GoAnywhere 等と同系統）が恒常的に狙われる点が教訓であり、外部公開資産の棚卸しとKEV連動の即時パッチ手順を整備しておきたい（ドメイン7）。

## 5. SAP 2026年11月セキュリティパッチデー：CVSS 10.0 が4件（NetWeaver ICM・Web Dispatcher・Gateway・SAML2）

**概要**
SAP は 2026-11-10 に月例のセキュリティパッチデーを実施し、RedRays の集計では38件のノート（新規35、更新3／HotNews 9、High 13、Medium 15、Low 1）を公開した（GBHackers は新規35件＋GitHubアドバイザリ4件と報じ、件数は情報源により差異あり）。CVSS 10.0（ネットワーク経由・権限不要・ユーザー操作不要）は4件で、NetWeaver AS ABAP の ICM WebSocket におけるメモリ破損（CVE-2026-76964、Note 3778530）、Web Dispatcher のメモリ破損（CVE-2026-89126、Note 3778556）、SAP Gateway のアクセス制御不備（CVE-2026-89103、Note 3798345）、AS ABAP/ABAP Platform の SAML2 サービスプロバイダにおける認証欠如（CVE-2026-120017、Note 3849308）である。CVSS 9.9（低権限が必要）には SAPFTP/ABAP の OSコマンドインジェクション（CVE-2026-76965）、Knowledge Management XML Forms のコードインジェクション（CVE-2026-109803）、S4CRM の認可チェック欠如（CVE-2026-109795）が含まれる。このほか Web Dispatcher/ICM の CSRF（CVE-2026-89119、-120014、CVSS 9.6）、BusinessObjects Web Intelligence の XXE（CVE-2026-109798、CVSS 9.1）も修正された。現時点で実環境での悪用は報告されていない。

## 6. Ivanti、EPM の未認証SQLインジェクション（CVE-2026-121653、CVSS 9.8）など13件を修正

**概要**
Ivanti は 2026-11-10 に5件のセキュリティアドバイザリを公開し、計13件の脆弱性を修正した。最も深刻なのは Endpoint Manager（EPM）Core の SQL インジェクション CVE-2026-121653（CVSS 9.8）で、未認証の攻撃者がリモートコード実行に至る可能性がある。影響は EPM 2024 SU7 以前、修正は 2024 SU8。次いで Cloud Services Appliance（CSA）5.0.8 の認証欠如 CVE-2026-121683（CVSS 9.4）は、未認証で EPM Core の信頼済み証明書エントリを追加・削除でき、エージェントとの信頼関係を改ざんされるおそれがある（CSA 5.0.8.1 で修正）。また EPMM（旧MobileIron Core）と Sentry には管理者権限が必要な OSコマンドインジェクション CVE-2026-105425（CVSS 7.2）があり、EPMM 12.11.0.0／12.10.0.1／12.9.0.3、Sentry 11.0.0／10.8.3／10.7.4 で修正された。中程度として EPM のエージェント通信の中間者攻撃（CVE-2026-18128）、UWM の平文セッショントークン（CVE-2026-105813）なども含まれる。Ivanti は悪用を認識しておらず、いずれも KEV 未掲載。

**関連CBKドメイン**: ドメイン8（ソフトウェア開発セキュリティ）、ドメイン7（セキュリティ運用）、ドメイン3（セキュリティアーキテクチャとエンジニアリング）

**コラム**
Ivanti 製品は過去に EPMM・Connect Secure・CSA などで繰り返しゼロデイ悪用されてきた経緯があり、「現時点で悪用なし」は数日〜数週間で覆る可能性が高い前提で扱うべきである（ドメイン7）。エンドポイント管理基盤は全端末への特権配布チャネルを持つため、#4 の RMM と同様に、侵害時の影響範囲を考慮した管理ネットワークの分離と管理コンソールの非公開化が重要（ドメイン3）。SQLインジェクションや認証欠如といった古典的欠陥が2026年でも CVSS 9 台で出続けている事実は、SDLC におけるパラメータ化クエリ・認証の必須化を設計段階で担保することの重要性を改めて示す（ドメイン8）。

## 7. 米 Vanderbilt 大学にランサムウェア攻撃、グループ「BYOD」が100万件超のSSN等窃取とドメインコントローラ掌握を主張

**概要**
米テネシー州の Vanderbilt 大学で 2026-11-09（月）、大学支給端末にランサムノートやポップアップが表示され、一部ファイルが `.byod` 拡張子に改名されて研究データにアクセスできなくなるなど、ランサムウェア攻撃とみられる事象が発生した。大学は利用者に対し端末を直ちにシャットダウンし、自分で調査・トラブルシュートしないよう指示し、学内Wi-Fiの利用も避けるよう呼びかけた。授業は予定通り実施としたが、休講にした教員もいた。犯行を名乗る「BYOD」（"Bring Your Own Device" をもじった名称）は、ransomware.live 上で「100万件超の社会保障番号（SSN）、氏名、メールアドレス、電話番号、学生・職員記録」を窃取し「ドメインコントローラを完全に掌握した」と主張している。同グループは過去に Michigan State University や University of New Mexico Health System への攻撃も主張している。窃取件数・内容は攻撃者側の主張で、大学による確認は得られておらず、既に集団訴訟の調査を表明する法律事務所も現れている。

**コラム**
「端末を即時シャットダウン」という指示は、暗号化の拡大を止める封じ込めとしては有効だが、メモリ上の証拠（暗号鍵・プロセス情報）を失うトレードオフがあり、インシデント対応計画で事前に判断基準を定めておくべき論点である（ドメイン7）。ドメインコントローラ掌握の主張が事実なら、全アカウントのパスワード・Kerberos（krbtgt）リセットを含む AD の再構築が必要となり、Tier モデルによる特権分離（ドメイン5）の有無が復旧期間を大きく左右する。大学は研究データ・学生記録・医療情報が混在しBYOD端末も多い高リスク環境であり、データの法的保持義務と通知義務（ドメイン1）を踏まえた対応体制の整備が欠かせない。

## 用語解説

- **Patch Tuesday**: Microsoft が毎月第2火曜日（米国時間）に定例のセキュリティ更新を公開する日の通称。
- **ゼロデイ（0-day）**: 修正パッチが提供される前、またはベンダーが把握する前に悪用される脆弱性。
- **CVE**: 公開された脆弱性に付与される世界共通の識別番号（例: CVE-2026-124194）。
- **CVSS**: 脆弱性の深刻度を0.0〜10.0で数値化する共通評価基準。9.0以上が「Critical」。
- **KEV（Known Exploited Vulnerabilities）カタログ**: CISA が管理する「実際に悪用が確認された脆弱性」の一覧。米連邦機関には対応期限が課される。
- **BOD（Binding Operational Directive）**: CISA が米連邦民間機関に対して出す拘束力のある運用指令。
- **CISA**: 米国サイバーセキュリティ・社会基盤安全保障庁。
- **NTLM / NTLMv2 ハッシュ**: Windows の旧来型チャレンジレスポンス認証方式と、その過程で得られる認証情報。窃取されるとリレー攻撃やパスワード解析に使われる。
- **リレー攻撃（NTLMリレー）**: 窃取した認証のやり取りを別のサーバへ中継し、被害者になりすまして認証を通す攻撃。
- **SMB署名／LDAP署名・チャネルバインディング**: 通信の改ざんや中継を防ぐための署名・TLS結び付け機能で、NTLMリレー対策となる。
- **Active Directory（AD）／ドメインコントローラ（DC）**: Windows 環境の認証・ディレクトリ基盤と、その中核サーバ。DCを掌握されると組織全体の権限を奪われる。
- **krbtgt**: Kerberos チケットの署名に用いる AD の特別なアカウント。DC 侵害後は2回のパスワードリセットが推奨される。
- **Tierモデル**: AD 管理者権限を階層（Tier 0/1/2）に分け、上位権限の資格情報が下位端末に露出しないようにする設計手法。
- **RCE（Remote Code Execution）**: 遠隔から任意のコードを実行できる脆弱性。
- **EoP（Elevation of Privilege）／権限昇格**: 本来より高い権限を不正に得られる脆弱性。
- **Schannel**: Windows の TLS/SSL 実装コンポーネント。
- **タイミング差（Observable Timing Discrepancy）**: 処理時間の違いから秘密情報を推測できてしまう欠陥。サイドチャネル攻撃の一種。
- **NAT**: ネットワークアドレス変換。プライベートIPとグローバルIPを相互変換する機能。
- **Use-After-Free（UAF）**: 解放済みのメモリを再利用してしまうバグ。任意コード実行につながりやすい。
- **メモリ安全言語**: Rust など、UAF やバッファオーバーフローを言語仕様で防ぎやすいプログラミング言語。
- **サンドボックス**: プログラムを隔離された環境で実行し、侵害されても外部への影響を抑える仕組み。
- **ブラウザ分離（RBI）**: Web コンテンツを端末外の隔離環境で実行し、描画結果だけを利用者に届ける対策。
- **EDR**: 端末上の振る舞いを監視して脅威を検知・対応する製品。
- **SIP**: VoIP の呼制御に使われる通信プロトコル。SIP MESSAGE はテキストメッセージ送信に用いられる。
- **コマンドインジェクション**: 入力値に OS コマンドを紛れ込ませ、サーバ上で実行させる攻撃。
- **コードインジェクション**: 入力値を通じてアプリケーションに任意のプログラムコードを実行させる攻撃。
- **リバースプロキシ**: クライアントからの要求を受けて背後のサーバへ中継する装置。送信元IPが書き換わるため、IPベースの信頼判断を誤らせる原因になる。
- **リバースシェル**: 侵害されたサーバから攻撃者側へ接続を張り、遠隔操作用のシェルを提供させる手法。
- **GHSA**: GitHub Security Advisory。GitHub 上で公開される脆弱性アドバイザリの識別子。
- **ゼロトラスト**: ネットワーク上の位置を信頼の根拠にせず、すべてのアクセスを都度認証・認可する設計思想。
- **RMM（Remote Monitoring and Management）**: MSP 等が多数の顧客端末を遠隔監視・管理するためのツール。
- **MSP**: マネージドサービスプロバイダー。顧客の IT 運用を受託する事業者。
- **PoC（Proof of Concept）**: 脆弱性が実際に悪用可能であることを示す実証コード。
- **フルディスクロージャー／調整された開示（CVD）**: 脆弱性情報をベンダー修正前に全面公開する方式と、ベンダーと調整し修正後に公開する方式。
- **XSS（クロスサイトスクリプティング）**: Web ページに不正なスクリプトを埋め込み、閲覧者のブラウザで実行させる攻撃。
- **XXE（XML外部実体参照）**: XML の外部実体機能を悪用し、ファイル読み取りや内部通信を行わせる攻撃。
- **OGNL インジェクション**: Java の式言語 OGNL に不正な式を評価させ、コード実行に至る攻撃。
- **ディレクトリトラバーサル**: `../` などを使い、本来アクセスできないファイルを読み書きする攻撃。
- **スタックオーバーフロー（スタックバッファオーバーフロー）**: スタック領域の境界を越えてデータを書き込み、制御を奪う脆弱性。
- **BCP（事業継続計画）**: 障害や災害時にも重要業務を継続・早期復旧するための計画。
- **SAP Note / HotNews**: SAP が公開する修正情報の単位と、そのうち最重要（CVSS 9.0以上相当）の区分。
- **ICM / Web Dispatcher / SAP Gateway**: SAP システムの HTTP 通信処理、負荷分散・入口ゲートウェイ、RFC 通信の中継を担うコンポーネント。
- **SAML2 / IdP / SP**: シングルサインオン用の認証連携規格と、認証を行う側（IdP）・認証結果を受け入れる側（SP）。
- **CSRF**: 利用者に意図しないリクエストを送信させ、ログイン中の権限で操作を実行させる攻撃。
- **SQLインジェクション**: 入力値に SQL 文を混入させ、データベースを不正操作する攻撃。
- **パラメータ化クエリ**: SQL 文と入力値を分離して渡し、SQL インジェクションを防ぐ実装手法。
- **EPM / EPMM / CSA**: Ivanti の端末管理製品（Endpoint Manager）、モバイル管理製品、およびインターネット経由で端末管理を中継するアプライアンス。
- **中間者攻撃（MITM）**: 通信経路に割り込み、盗聴や改ざんを行う攻撃。
- **ランサムウェア**: データを暗号化・窃取し、復号や非公開と引き換えに身代金を要求するマルウェア。
- **リークサイト**: ランサムウェアグループが被害組織名や窃取データを公開・暴露するためのサイト。
- **SSN（社会保障番号）**: 米国の個人識別番号。漏えいすると身元詐称に悪用されやすい。
- **BYOD**: 私物端末の業務利用（Bring Your Own Device）。今回は攻撃グループ名にも使われている。
- **封じ込め（Containment）**: インシデント対応で被害拡大を止める段階。
- **第四者リスク（Fourth-party risk）**: 委託先のさらに先の委託先・サービス提供者に起因するリスク。
- **データ最小化**: 目的に必要な最小限の個人データのみを収集・提供する原則。
- **特権ID管理（PAM）**: 管理者権限アカウントの付与・利用・監査を統制する仕組み。
- **MFA（多要素認証）**: 知識・所持・生体など複数の要素を組み合わせる認証方式。
- **APT**: 特定組織を長期間狙う高度な標的型攻撃グループ。
- **RAT（Remote Access Trojan）**: 感染端末を遠隔操作するためのマルウェア。
- **EPSS**: 脆弱性が今後30日以内に悪用される確率を推定する指標。
- **JPCERT/CC CyberNewsFlash**: JPCERT/CC が注意喚起ほど緊急ではないが周知すべき情報を速報する枠。
