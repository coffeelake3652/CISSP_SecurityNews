# CISSP向け サイバーセキュリティニュースダイジェスト（2026年8月26日）

本日は、CISA KEVに追加された最大深刻度のOracle脆弱性、500組織超を侵害したMedusaランサムウェアの合同勧告、Cl0pによるShellへのサプライチェーン型攻撃、Windowsカーネルドライバのゼロデイ悪用、VMware vCenterを起点としたBabuk系ランサムウェア展開、そして国内ではニチレイおよびさくらインターネットへの攻撃を取り上げる。

## 1. Oracle HTTP Server／WebLogic Server Proxy Plugin の最大深刻度脆弱性が実悪用、CISAがKEVに追加

**概要**：米CISAは2026年8月24日、Oracle HTTP ServerおよびWebLogic Server Proxy Plugin（Apache HTTP Server用・Microsoft IIS用の両方を含む）に存在する脆弱性CVE-2026-21962を、実際に悪用が確認されているとしてKnown Exploited Vulnerabilities（KEV）カタログに追加した。CVSSスコアは最大値の10.0で、認証なしでリモートから悪用可能なリモートコード実行（RCE）／重要データへの不正アクセス・改ざんにつながる欠陥とされる。パッチ自体はOracleが2026年1月のCritical Patch Updateで公表済みだったが、SOCRadarは2026年7月時点で中国系とみられる脅威アクターが政府機関のインフラを狙って本脆弱性を悪用していたと報告しており、公表から半年以上経過した現在も未パッチ環境が攻撃対象になっている。CISAは連邦機関に対し2026年8月27日までの対応完了を義務付けた。被害組織数や具体的な侵害範囲は本稿執筆時点で公開情報が限られており、単一情報源に基づく内容を含む。

**関連CBKドメイン**：ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン6（セキュリティの評価とテスト）、ドメイン7（セキュリティ運用）

**コラム**：本件は「パッチが出ていても適用されていなければ意味がない」という、CISSP実務における最も基本的かつ最も繰り返される教訓を体現している。CVSS 10.0・認証不要という条件が揃うと攻撃対象として即座に狙われるため、脆弱性管理（Vulnerability Management）ではCVSSスコアだけでなく「実悪用の有無（KEV収載）」を優先順位付けの主要指標とすべきである。半年以上前のパッチが未適用のまま放置されていた事実は、パッチ管理プロセスと資産管理（どのシステムにどのコンポーネントが存在するかの棚卸し）の連携不足を示唆しており、ドメイン6のセキュリティテスト（脆弱性スキャン）の定期実施の重要性を再確認させる事例である。

**参照**：[CISA Warns of Exploited Oracle WebLogic Vulnerability - SecurityWeek](https://www.securityweek.com/cisa-warns-of-exploited-oracle-weblogic-vulnerability/)、[CISA Adds One Known Exploited Vulnerability to Catalog | CISA](https://www.cisa.gov/news-events/alerts/2026/08/24/cisa-adds-one-known-exploited-vulnerability-catalog)

## 2. Medusaランサムウェア、500組織超を侵害——FBI・CISA・HHSが合同勧告を更新

**概要**：FBI、CISA、米保健福祉省（HHS）は、Medusaランサムウェアが2021年6月の初観測以来500組織超を侵害したとする合同サイバーセキュリティ勧告を更新した。本勧告は2025年3月発表分の更新版で、2026年4月まで実施されたFBIの捜査に基づく。被害はヘルスケア、防衛、製造、政府サービス、IT、金融サービスを中心に、教育・保険・法律事務所など多岐にわたるセクターに及ぶ。技術的には、Medusaは2023年初頭以降クローズド運用からRansomware-as-a-Service（RaaS）モデルへ移行し、アクセスブローカー経由の侵入・フィッシング・未パッチの公開脆弱性の悪用で初期侵入し、正規ツールを悪用する「Living off the Land」技術やRDP等のリモートアクセスサービスを用いて水平展開する。暗号化処理は「gaze.exe」と呼ばれるコンポーネントが担い、バックアップおよびセキュリティサービスを停止させたのち、ファイルを「.medusa」拡張子で暗号化する。二重恐喝（データ窃取＋暗号化）の運用も特徴で、被害者には48時間の初期回答猶予が与えられ、応じない場合はリークサイトにカウントダウンタイマー付きで公開、1万ドルの暗号資産支払いごとに猶予が1日延長される仕組みが確認されている。

**関連CBKドメイン**：ドメイン1（セキュリティとリスクマネジメント）、ドメイン7（セキュリティ運用）

**コラム**：RaaSモデルの拡大により、単一グループの技術力だけでなく「アフィリエイトの数」が被害規模を左右する時代になっている点は、リスクアセスメント（ドメイン1）において脅威主体のビジネスモデルまで理解する必要性を示す。ヘルスケアや重要インフラが標的の中心である点は、事業継続計画（BCP）・インシデント対応計画の実効性がそのまま人命や社会機能に直結することを意味し、バックアップの分離保管（イミュータブルバックアップ）と復旧訓練の重要性を改めて裏付ける。またLiving off the Landの多用は、EDR等の振る舞い検知や特権アカウント監視（ドメイン7の運用監視）がシグネチャベース検知だけでは不十分であることを示している。

**参照**：[Medusa ransomware gang has hit over 500 organizations, CISA warns - Help Net Security](https://www.helpnetsecurity.com/2026/08/19/medusa-ransomware-cisa-warning/)、[CISA: Medusa ransomware hit over 500 critical infrastructure orgs - BleepingComputer](https://www.bleepingcomputer.com/news/security/cisa-medusa-ransomware-hit-over-500-critical-infrastructure-orgs/)

## 3. Cl0pランサムウェア集団、PTC Windchillの脆弱性を突きShellなど43組織を新規被害者としてリークサイトに掲載

**概要**：Cl0pランサムウェア集団は、PLM（製品ライフサイクル管理）プラットフォームPTC WindchillおよびFlexPLMに存在する重大な入力検証不備の脆弱性CVE-2026-12569を悪用し、石油大手Shellを含む43組織を新規被害者としてリークサイトに掲載したと主張した。窃取されたと主張するデータは89GB相当に及び、エンジニアリング図面、施設写真、プロジェクトロードマップ、試験報告書などが含まれるとされる。Cl0pは暗号化を伴わずデータ窃取のみで恐喝する手法（二重恐喝の窃取特化型）を用いており、Windchill環境に独自開発のWebシェルを設置し、機密性の高いvaultデータのマッピングや認証情報の復号が可能な、いわば「フル装備の恐喝プラットフォーム」を構築していたことが判明している。Shellは2026年8月14日前後にこの主張を把握し、社内インシデント対応手続きを発動して外部専門家とともに調査中で、本稿執筆時点では主張内容を独自に検証できておらず、精製・掘削・基幹ITシステムへの支障は確認されていない。General ElectricやPhilipsなど他の大手企業も同一キャンペーンの被害者リストに含まれている。

**関連CBKドメイン**：ドメイン1（セキュリティとリスクマネジメント）、ドメイン7（セキュリティ運用）、ドメイン8（ソフトウェア開発セキュリティ）

**コラム**：本件はPLMという「設計データを扱う業務システム」がサプライチェーンリスクの新たな標的になっていることを示す典型例であり、サードパーティ製ソフトウェアの脆弱性管理を自社の主要システムと同列に扱う必要性を突きつける。暗号化を伴わない窃取特化型の恐喝は検知が難しく、DLP（データ漏洩防止）やアウトバウンド通信の監視といった運用面の統制（ドメイン7）がより重要になる。また、設計図面や試験報告書という知的財産の流出は、資産分類（Data Classification）において「機密性の高い非個人情報」も個人情報と同等以上に保護対象とすべきことを再認識させる。

**参照**：[Shell Investigates Data Breach After Cl0p Ransomware Group Claims 89 GB Data Theft - CyberPress](https://cyberpress.org/shell-investigates-data-breach-cl0p-ransomware-group/)、[Shell investigates 'potential incident' after Clop data theft claims - BleepingComputer](https://www.bleepingcomputer.com/news/security/shell-investigates-potential-incident-after-clop-data-theft-claims/)

## 4. Windowsカーネルドライバ（afd.sys）のUse-After-Freeゼロデイ、Lazarusが悪用——8月Patch Tuesdayで修正

**概要**：Microsoftは2026年8月のPatch Tuesdayで421件（一部報道では398件）の脆弱性を修正したが、その中でもCVE-2026-68820は公式パッチ提供前から実際に悪用されていたゼロデイとして注目された。本脆弱性はWindows Sockets APIの基盤となるカーネルモードドライバ「Ancillary Function Driver for WinSock（afd.sys）」に存在するUse-After-Free（解放済みメモリ使用）の欠陥で、CVSSスコアは7.0、既にローカルで足がかりを得た攻撃者がSYSTEM権限まで昇格できる特権昇格（Elevation of Privilege）型の脆弱性である。CISAは2026年8月11日、本脆弱性をKEVカタログに追加した。Check Point Researchの分析によれば、悪用は北朝鮮系とされるLazarusグループによる長期活動「Operation Dream Job」の一環として確認されており、同グループが求人詐欺等でターゲットに接触し初期侵入した後、本脆弱性で権限昇格を図る攻撃連鎖が想定される。追加のユーザー操作なしに侵害端末の完全掌握につながる点が実務上の脅威度を高めている。

**関連CBKドメイン**：ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン7（セキュリティ運用）

**コラム**：特権昇格系のゼロデイは単体では侵入経路にならないため過小評価されがちだが、初期侵入（フィッシング等）とチェーンされることで被害の深刻度が跳ね上がる点をCISSP実務者は理解しておく必要がある。国家支援型アクターによるOperation Dream Jobのような長期偵察キャンペーンは、技術的統制だけでなく従業員向けセキュリティ意識向上（ソーシャルエンジニアリング対策）を含む多層防御（ドメイン3の設計原則）の必要性を示す。パッチが未提供の段階での悪用が確認されたことは、EDR等によるカーネルレベルの異常検知や最小権限の徹底（ローカル管理者権限の制限）が、パッチ適用と並ぶ重要な緩和策であることを裏付ける。

**参照**：[Microsoft Patches 398 Flaws Including a Windows Driver Zero-Day Under Active Attack - The Hacker News](https://thehackernews.com/2026/08/microsoft-patches-398-flaws-including.html)、[CVE-2026-68820: Windows AFD.sys Zero-Day - SOC Prime](https://socprime.com/blog/cve-2026-68820-actively-exploited-windows/)

## 5. VMware vCenterの重大パストラバーサル脆弱性、公表5日で実悪用——中国系アクターがBabuk系ランサムウェアを展開

**概要**：Broadcomは2026年7月29日、VMware vCenterに存在するパストラバーサル脆弱性CVE-2026-59310（CVSSスコア9.8）を修正した。しかし公表からわずか5日後の8月3日には、侵害されたシステムが攻撃者ドメインへの通信を開始していることが確認され、以降47カ国361件のユニークな被害IPアドレスが観測される大規模な悪用キャンペーンへと発展した。攻撃連鎖は、ネットワークアクセス可能な攻撃者が認証なしでコードを実行し、悪意あるcronジョブを設置してオープンソースツール「reverse_ssh」による持続的なリバースSSHアクセスを確立、その後アカウント作成やESXi環境の制御権奪取を経て、Babukランサムウェア派生型を展開するという流れである。CISAはKEVカタログへの追加とともに緊急パッチ適用を強く呼びかけている。攻撃主体については中国語話者によるものと推定されているが、断定的な帰属情報は本稿執筆時点で確認されておらず、単一情報源に基づく分析である点に留意されたい。

**関連CBKドメイン**：ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン4（通信とネットワークセキュリティ）、ドメイン7（セキュリティ運用）

**コラム**：仮想化基盤管理コンソール（vCenter）は「管理者以外は触れない」という理由で外部公開・境界防御が手薄になりがちだが、本件はまさにその管理プレーンが直接の侵入口となった事例である。パッチ公表から悪用開始までわずか5日という速度は、脆弱性情報の公開＝攻撃準備完了の合図であることを意味し、緊急パッチ適用のSLAを「月次」から「日次〜週次」に見直す必要性を突きつける。またリバースSSHによる持続的アクセスの確立は、アウトバウンド通信の監視・制限（ネットワークセグメンテーション、ドメイン4）が仮想化基盤特有の防御策として不可欠であることを示している。

**参照**：[Attackers Exploit VMware vCenter Vulnerability to Gain Persistent Remote Access - The Hacker News](https://thehackernews.com/2026/08/attackers-exploit-vmware-vcenter.html)、[vCenter Flaw Exploited Just Five Days After Disclosure - Infosecurity Magazine](https://www.infosecurity-magazine.com/news/vcenter-cve-2026-59310-exploited/)

## 6. ニチレイへのサイバー攻撃、RansomHouseが窃取データ20万件超を公開——従業員個人情報漏洩の可能性

**概要**：食品大手ニチレイは2026年7月13日、不正アクセスによるシステム障害を公表し、出荷・受注業務が一時停止した。当初は侵入経路や攻撃元、被害範囲について詳細を明らかにしていなかったが、ロシア系とされる恐喝集団「RansomHouse（ランサムハウス）」が2026年8月10日、窃取したと主張するデータ（20万件超のファイル）をダークウェブ上に公開した。これを受けニチレイは8月14日、従業員の氏名・生年月日・社用メールアドレス・従業員番号・人事労務情報などの個人情報が漏洩した可能性があると正式に発表した。公開データには従業員・取引先の電話番号等の個人情報も含まれるとされる。なお、ニチレイはRansomHouseの関与、ランサムウェアによる暗号化の有無、実際のデータ窃取の事実そのものについては本稿執筆時点で公式に確認しておらず、攻撃者の主張が唯一の情報源である点には注意が必要である。

**関連CBKドメイン**：ドメイン1（セキュリティとリスクマネジメント）、ドメイン7（セキュリティ運用）

**コラム**：初報から1カ月遅れで個人情報漏洩の可能性が公表された事実は、インシデント対応におけるフォレンジック調査の難しさと、暫定情報のみで説明責任を果たすコミュニケーション戦略の重要性を示している。攻撃者側の主張のみでは被害の全容が確定できない状況は珍しくなく、CISSP実務者はインシデント対応計画（IRP）において「攻撃者の主張」と「自組織の技術的確認」を明確に区別し、段階的に開示する情報公開プロセスをあらかじめ設計しておく必要がある。食品製造という物理的サプライチェーンを持つ業界での業務停止は、サイバー攻撃が事業継続（BCP/DRP）に直結することを改めて示す事例である。

**参照**：[ニチレイのサイバー攻撃、ハッカー集団が盗難データ公開 社内情報など - 日本経済新聞](https://www.nikkei.com/article/DGXZQOUC101ZU0Q6A810C2000000/)、[ニチレイグループへのサイバー攻撃まとめ - セキュリティ対策Lab](https://rocket-boys.co.jp/security-measures-lab/nichirei-cyberattack-summary/)

## 7. さくらインターネット「さくらのレンタルサーバ」に不正アクセス、583アカウントで不正ログイン——調査進展で対象最大136万563アカウントに拡大

**概要**：さくらインターネットは2026年8月17日、レンタルサーバーサービス「さくらのレンタルサーバ」において、第三者が同社の管理環境を経由して一部ユーザー環境に不正アクセスしていたことを公表した。同社は8月9日にサーバー環境における異常を検知して調査を開始し、583アカウントへの不正ログインおよび一部サーバーへのマルウェア設置を確認、攻撃者がサーバー領域内の保存データや利用者識別子など、通信の秘密に該当する情報にアクセス可能な状態だったことも判明した。さらに8月19日の第二報では、販売管理システムへの不正アクセスの可能性が新たに確認され、影響を受けた可能性のある会員情報の対象が最大136万563アカウントにまで拡大した。管理環境という「顧客環境の外側」からの侵害である点が本件の特徴で、個々の顧客側のセキュリティ対策では防ぎきれない性質の攻撃だった。

**関連CBKドメイン**：ドメイン4（通信とネットワークセキュリティ）、ドメイン5（アイデンティティおよびアクセス管理）、ドメイン7（セキュリティ運用）

**コラム**：本件はホスティング事業者という「多数の顧客を代理で守る立場」の管理環境が侵害された場合、被害が指数関数的に拡大することを示す典型例であり、クラウド・ホスティングサービス選定時にはベンダー自身の内部統制（管理コンソールの多要素認証、特権アクセス管理）を評価する重要性を裏付ける。583アカウントから136万アカウントへと調査進展に伴い規模が拡大した経緯は、初動のスコープ判断がいかに困難かを示しており、インシデント対応では「判明している事実」と「調査中の範囲」を明確に区別した段階的開示が求められる（ドメイン7）。また「通信の秘密」に該当する情報への影響は、日本の電気通信事業法上の観点からも法的・規制対応（ドメイン1）が絡む点に留意が必要である。

## 用語解説

- **CVE（Common Vulnerabilities and Exposures）**：個々の脆弱性に付与される世界共通の識別番号。「CVE-年-連番」の形式で管理され、脆弱性情報を組織間で一意に特定・共有するために使われる。
- **CVSS（Common Vulnerability Scoring System）**：脆弱性の深刻度を0.0〜10.0の数値で評価する業界標準の指標。攻撃条件（認証要否、攻撃元区分など）と影響（機密性・完全性・可用性）を基にスコアが算出される。
- **KEV（Known Exploited Vulnerabilities）カタログ**：米CISAが公開する「実際に悪用が確認された脆弱性」の一覧。理論上のリスクだけでなく現実の悪用実績に基づくため、パッチ適用の優先順位付けの重要な指標となる。
- **RCE（Remote Code Execution／リモートコード実行）**：攻撃者がネットワーク経由で対象システム上に任意のコードを実行できる状態を指す。多くの場合、システムの完全な制御を許してしまう最も深刻な脆弱性区分の一つ。
- **パストラバーサル（Path Traversal）**：ファイルパスの指定を操作することで、本来アクセスが許可されていないディレクトリやファイルに不正にアクセスする攻撃手法。「../」のような相対パス表記の不備を突くことが多い。
- **ランサムウェア（Ransomware）**：データを暗号化またはデータの窃取・公開を材料に金銭を要求するマルウェア。近年は暗号化と情報窃取の両方を行う「二重恐喝」型が主流。
- **RaaS（Ransomware as a Service）**：ランサムウェアの開発者が攻撃基盤をアフィリエイト（実行犯）に貸与し、身代金の一部を得るビジネスモデル。攻撃の分業化・大規模化を促進している。
- **ゼロデイ（Zero-Day）**：ベンダーによる修正パッチが提供される前の段階で、脆弱性が発見・悪用されている状態を指す。防御側が対応する猶予がほぼない点が特徴。
- **特権昇格（Elevation of Privilege / Privilege Escalation）**：攻撃者が本来持たない高い権限（管理者・SYSTEM権限など）を不正に取得する行為。初期侵入後の被害拡大に直結する。
- **Use-After-Free（解放済みメモリ使用）**：一度解放（free）されたメモリ領域を誤って再利用してしまうプログラムの不具合。攻撃者に悪用されるとコード実行や権限昇格につながることがある。
- **サプライチェーンリスク（Supply Chain Risk）**：自組織が直接管理していない委託先・取引先・利用ソフトウェア等を経由して生じるセキュリティリスク。第三者の脆弱性が自組織の被害に直結する。
- **APT（Advanced Persistent Threat）**：国家支援を受けるなど高度な技術力・資金力を持ち、長期間にわたり特定の標的に対して執拗に攻撃を継続する脅威主体（グループ）を指す。
- **リバースシェル／リバースSSH（Reverse Shell / Reverse SSH）**：侵害した内部端末側から外部の攻撃者サーバーへ能動的に接続を確立する手法。ファイアウォールのインバウンド制限を回避しやすく、持続的な遠隔操作に悪用される。
- **Living off the Land（LotL）**：マルウェアを新規に持ち込むのではなく、対象環境に元々存在する正規のOS機能や管理ツールを悪用して攻撃を行う手法。セキュリティ製品による検知を回避しやすい。
- **ダークウェブ（Dark Web）**：通常の検索エンジンやブラウザではアクセスできない匿名性の高いネットワーク領域。窃取データの売買や公開、ランサムウェアのリークサイト運用などに利用される。
