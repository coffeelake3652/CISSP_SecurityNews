## 1. Palo Alto PAN-OS GlobalProtect認証バイパス(CVE-2026-0257):VPN突破からESXi/VMDK経由の認証情報窃取、ランサムウェア展開まで(10/19更新)

**概要**: Unit 42は2026年10月19日、PAN-OSのGlobalProtectポータル/ゲートウェイの認証バイパス脆弱性CVE-2026-0257に関する脅威ブリーフを更新し、最近のランサムウェア活動を追記した。この欠陥により、未認証の攻撃者がセキュリティ制御を回避してVPNセッションを確立でき、MFAも迂回される。CISAのKEV登録は2026年5月13日、PoC公開は5月29日、Unit 42の対応調査は6月初旬から継続している(CVSSおよび影響バージョンは同記事に記載がなく、ベンダーアドバイザリー参照)。観測された攻撃では、初期侵入後にデュアルユースのRMMツールで内部偵察を行い、RDP/SMBで横展開し、認証情報窃取・持ち出し・ランサムウェア用ツールを配置している。特に注目すべき事例として、VPNゲートウェイからvCenterアプライアンスへ到達し、ESXiホストの`execInstalledOnly`を無効化したうえで、ドメインコントローラーのVMDKに対してオフラインで認証情報をダンプしており、ゲスト内EDRを回避している。ランサムウェア運用者としてSpikey Scorpius(Qilin)とTarnished Scorpius(Inc)が挙げられ、Veeam CVE-2023-27532との連鎖利用も確認されている。被害は教育、金融、医療、政府、製造、エネルギー等に及ぶが、総被害数は非公表で、Unit 42は「プローブされた機器のうちVPNセッション確立に至ったのは一部」としている。初期侵入の主体は未特定。

**関連CBKドメイン**: ドメイン5(アイデンティティおよびアクセス管理)/ドメイン4(通信とネットワークセキュリティ)/ドメイン7(セキュリティ運用)

**コラム**: 境界のVPN機器が認証の単一障害点になり、MFAもその機器の健全性に依存する点を再認識させる事例である(ドメイン5)。さらに攻撃者は仮想化基盤の管理プレーン(vCenter/ESXi)に到達し、ゲストOS内のEDRが見えない層で認証情報を奪っている。仮想化管理系を別セグメント・別認証基盤に置き、ESXiのロックダウン設定の変更を監視する設計が要る(ドメイン3/4)。運用面ではKEV登録から5か月近く経っても被害が出続けており、パッチ適用の遅れと、VPN機器のログ・ベースライン監視の不足が主因とみられる(ドメイン7)。

**参照**: [Unit 42: Active Exploitation of PAN-OS CVE-2026-0257](https://unit42.paloaltonetworks.com/active-exploitation-of-pan-os-cve-2026-0257/)

## 2. Atlassian製品群のpre-auth任意ファイル読取(CVE-2026-21589):PoC公開から2時間以内に悪用試行

**概要**: Atlassianは2026年10月5日、Data Center/セルフホスト版の8製品に影響する重大脆弱性CVE-2026-21589(Atlassian評価9.3)を公表した。未認証の攻撃者が、正確なファイルパスを知っていればWebルート配下のファイルを1リクエストで取得できる(ディレクトリ列挙は不可)。対象はBitbucket DC、Confluence DC、Jira Software/Service Management DC、Bamboo DC、Crowd DC、Crucible、Fisheyeで、例として修正版はBitbucket 9.4.26/10.2.8/10.5.1、Confluence 9.2.26/10.2.19、Jira Software 9.12.40/10.3.26/11.3.12などである。公表直後にwatchTowrが技術解析とPoC、検査ツールを公開し、公開から2時間以内にPrevidianのハニーポットで悪用試行が検出された。CISA KEVには10月15日に追加されている(別集計による)。Jiraのwebルート設定ファイルからCrowdの保存済み認証情報が取得され、管理者作成に悪用されうる点も指摘されている。攻撃者は未特定で、被害件数も非公表。Atlassian Cloudは対応済みで顧客対応は不要。

**関連CBKドメイン**: ドメイン7(セキュリティ運用)/ドメイン8(ソフトウェア開発セキュリティ)/ドメイン6(セキュリティの評価とテスト)

**コラム**: 「公表→PoC→悪用」の間隔が時間単位になった典型例で、パッチ管理SLAを重要度とインターネット露出で層別する必要がある(ドメイン7)。パス・トラバーサル系の欠陥は入力検証とファイルアクセス制御の基本(ドメイン8)に帰着し、WebルートにシークレットがあるとSSOやCI/CD基盤まで連鎖する。設定ファイルから認証情報を排除しシークレット管理基盤へ移す、露出資産を継続的にスキャンして自社でPoC相当の検査を回す(ドメイン6)といった対策が実務的である。暫定緩和としてのWAF/リバースプロキシ規則は、パッチ適用までの補償的統制として位置づけられる。

**参照**: [eSecurityPlanet: Critical Atlassian File Access Flaw](https://www.esecurityplanet.com/news/news-atlassian-cve-2026-21589-file-read-flaw/) / [KEV週次集計(DEV Community)](https://dev.to/devaland/actively-exploited-this-week-9-new-cisa-kev-entries-12-october-to-18-october-2026-3dno)

## 3. 国際共同捜査「Operation KillSwitch」:RaaS「KillSec」を摘発、疑われる主犯は16歳

**概要**: ドイツ主導の捜査「Operation KillSwitch」により、ランサムウェア・アズ・ア・サービス(RaaS)のKillSec(Kill Security/k1llsec)が摘発された(報道は10月4日)。9月30日にリークサイトが押収され、同日に英国でオランダ国籍のFouad Eltibrizi(通称「Archduke」)が逮捕された。米検察は不正アクセス、損害、恐喝関連で起訴し、身柄引き渡しを待っている。暫定逮捕は3人で、スペインのGuardia Civilはアリカンテで16歳のルーマニア人少年(主犯の疑い)を確認した。スペイン、ギリシャ、ルーマニア、英国で8か所を捜索し、リークサイトと中核サーバー5台を押収、少なくとも110TBの盗取データを保全した。捜査当局は約1,000件の攻撃を疑い、うち約500件が成功とみる。Group-IBは公開された被害274組織を追跡しており、約35%が米国、17%がインドで、金融と医療が最多である。手口はソフトウェア脆弱性と脆弱なアクセス点(特にクラウドストレージ)の悪用、データ窃取後の公開脅迫で、AIをインフラ保守や被害者選定に使っていたとされる。主犯の年齢等は当局発表に基づく報道で、一部は単一情報源の可能性がある。

**関連CBKドメイン**: ドメイン1(セキュリティとリスクマネジメント)/ドメイン7(セキュリティ運用)/ドメイン2(資産のセキュリティ)

**コラム**: 法執行機関の国際連携は、脅威モデルにおける攻撃者の持続性見積りに影響する一方、RaaSは役割分担(管理者・開発者・交渉役・アフィリエイト)で再編されやすく、摘発後の報復や模倣を前提にリスク評価する必要がある(ドメイン1)。押収データの保全が示すように、盗取データが法執行側に渡る場合も含め、データ分類と保持期間の最小化が被害の大きさを左右する(ドメイン2)。手口が「クラウドストレージの設定不備」である点は、CSPM、公開設定の継続監査、アクセスログ保全といった運用統制(ドメイン7)で直接に低減できる。また、法執行から被害組織への通知が来た場合のインシデント対応手順(法務・広報連携)を事前に定めておくべきである。

**参照**: [eSecurityPlanet: Police Take Down KillSec Ransomware Network](https://www.esecurityplanet.com/news/news-killsec-ransomware-takedown/) / [BleepingComputer](https://bleepingcomputer.com/news/security/police-dismantle-killsec-ransomware-gang-allegedly-led-by-16-year-old) / [The Record](https://therecord.media/killsec-ransomware-raas-arrests-europe)

## 4. デンマークCPR(国民登録簿):正規の検索権限を持つ民間企業経由で約880万人分が自動検索で露出

**概要**: デンマーク当局は2026年10月2日にCPR(国民ID・住民登録簿)への異常なアクセスを検知し、9月に遡って調査した結果、約880万人の氏名、住所、CPR番号に関わる自動検索が行われていたと発表した(報道は10月6日)。CPRは約1,100万件の記録を保有し、氏名住所保護の登録者は対象から除外されていた。データ保護庁は「有効なCPR番号を特定することを狙った、非常に多数の自動検索」と報告し、検索は特定の民間企業が持つ正規の検索権限を通じて行われた。登録簿そのものへの直接侵害は報告されておらず、権限の侵害経緯は未公表である。他報道では「10日間で約1,400万回の検索、請求書から発覚」とする記事もあるが(The Next Web、未検証)、当該数字は要確認。CPR管理者は同社のアクセスを遮断し、警察が捜査、登録簿アクセス全体のセキュリティ見直しが始まった。住民には、想定外の連絡は既知の窓口で確認する、MitIDの情報やパスワードを共有しない、CPRに信用警告を設定することが案内された。収集データの行方は非公表。

**関連CBKドメイン**: ドメイン5(アイデンティティおよびアクセス管理)/ドメイン2(資産のセキュリティ)/ドメイン1(セキュリティとリスクマネジメント)

**コラム**: 認証された正規ユーザーによる大量・自動アクセスは、境界防御では防げず、権限設計とレート制御、行動分析で検知すべき領域である(ドメイン5)。最小権限の原則と、検索目的に応じた粒度(完全一致のみ許可、列挙を許さない、クエリ上限)の技術的強制が要る。また第三者に委ねたアクセス権は、契約と監査だけでなくサプライチェーンリスクとして継続評価する必要がある(ドメイン1)。ID番号は漏えい後に変更できない「恒久識別子」であり、データ分類上の最上位として扱い、二次利用(なりすまし・フィッシング)を前提にした周知と補償統制が欠かせない(ドメイン2)。

**参照**: [eSecurityPlanet: Denmark CPR](https://www.esecurityplanet.com/news/news-denmark-cpr-data-breach-8-8-million-emea/) / [The Hacker News](https://thehackernews.com/2026/10/denmark-says-attackers-accessed-cpr.html) / [CSO Online](https://www.csoonline.com/article/4231797/denmarks-national-id-system-breach-exposes-personal-data-of-8-8m.html)

## 用語解説

- **CVE(Common Vulnerabilities and Exposures)**: 公開された脆弱性に付与される共通識別番号。製品や報道をまたいで同一の脆弱性を指し示すために使う。
- **CVSS(Common Vulnerability Scoring System)**: 脆弱性の深刻度を0〜10で表す共通指標。9.0以上は「Critical」とされる。
- **CISA KEV(Known Exploited Vulnerabilities)**: 米CISAが管理する「実際に悪用が確認された脆弱性」の一覧。連邦機関には修正期限が課され、民間でも優先度判断の基準になる。
- **認証バイパス**: 認証手順を飛ばして正規の認証なしにアクセスできてしまう欠陥。VPNや管理APIで起きると影響が大きい。
- **MFA(多要素認証)**: パスワードに加え、所持物や生体情報など別種の要素で本人確認する方式。ただし機器側の欠陥があると迂回されうる。
- **VPN / GlobalProtect**: 外部から社内ネットワークに安全に接続する仕組み。GlobalProtectはPalo Alto Networksの製品。
- **RMMツール**: 遠隔監視・管理ソフト。正規の管理用途でも使われるため(デュアルユース)、攻撃者の偵察や遠隔操作に悪用されると検知しにくい。
- **横展開(ラテラルムーブメント)**: 侵入後に別の端末やサーバーへ移って権限と到達範囲を広げる行動。
- **RDP / SMB**: Windowsのリモート接続(RDP)とファイル共有(SMB)のプロトコル。横展開によく使われる。
- **vCenter / ESXi / VMDK**: VMwareの仮想化基盤の管理サーバー(vCenter)、ハイパーバイザー(ESXi)、仮想ディスクファイル(VMDK)。VMDKを直接読むと、ゲストOS内のEDRを回避して認証情報を抜き出せる。
- **EDR(Endpoint Detection and Response)**: 端末上の不審な挙動を検知・調査・対処する製品。
- **ランサムウェア / RaaS**: データを暗号化・窃取して身代金を要求するマルウェア。RaaSはその「サービス化」で、開発者がアフィリエイトに提供して分け前を得る。
- **パス・トラバーサル / 任意ファイル読取**: 入力されたパスを十分検証しないために、想定外のファイルを読ませてしまう脆弱性。
- **PoC(Proof of Concept)**: 脆弱性が実際に悪用可能であることを示す実証コード。公開されると攻撃が急増しやすい。
- **ハニーポット**: 攻撃を誘い込み観測するためのおとりシステム。
- **WAF(Web Application Firewall)**: Webアプリへの不正リクエストを検査・遮断する装置。パッチ適用までの暫定対策として使う。
- **SSO / IDフェデレーション**: 1回の認証で複数のサービスを使う仕組みと、組織やサービス間でID情報を連携する仕組み。
- **サプライチェーンリスク**: 委託先や取引先、連携サービスを経由して自社が被害を受けるリスク。
- **最小権限の原則**: ユーザーやシステムに業務上必要な最小限の権限だけを与える考え方。
- **データ最小化 / データ保持期間管理**: 収集・保管するデータを必要最小限にし、不要になれば廃棄することで、侵害時の被害を減らす考え方。
- **KYC(本人確認)**: 顧客の身元確認手続き。免許証画像などの機微な書類が集まるため、保管と廃棄の設計が重要になる。
- **ハッシュ化パスワード**: パスワードを元に戻せない形に変換して保存する方式。強度の高い方式と適切なソルトが前提となる。
- **フォレンジック**: 事件後に証拠を保全・解析して、侵入経路や被害範囲を特定する調査。
- **CSPM(Cloud Security Posture Management)**: クラウドの設定不備を継続的に検査・是正する仕組み。
- **個人情報保護委員会**: 日本の個人情報保護法を所管する行政機関。漏えい時には報告と本人通知が求められる。
