## 1. Cl0pランサムウェア集団、PTC Windchill／FlexPLMの脆弱性（CVE-2026-12569）を悪用しサプライチェーン規模でデータ窃取

**概要**：ランサムウェア集団Cl0pが、PTC社の製品ライフサイクル管理（PLM）ソフトウェア「Windchill PDMLink」および「FlexPLM」に存在する深刻な脆弱性CVE-2026-12569（CVSSスコア9.8）を悪用し、Shell、Philips、General Electricを含む40社以上をリークサイトに掲載しました。脆弱性は信頼できないデータのデシリアライズに起因するリモートコード実行（RCE）で、FlexPLMのWSDLエンドポイントに存在する認証前情報漏洩の欠陥と連鎖させることで未認証のまま悪用可能でした。Cl0pは2026年6月上旬にゼロデイとしてこの脆弱性を悪用し始めたとみられ、PTCは6月17日に修正パッチを公開、その翌日には野放しでの悪用が確認され、CISAは6月25日に既知の悪用された脆弱性（KEV）カタログへ追加しました。攻撃者は侵害後、PLMプラットフォーム専用に作られたJSP Webシェルを設置し、Windchillキーストア内の全認証情報を復号したうえで、独自のJavaクラスローダーを介して追加コードを実行する手口を用いています。7月末時点で脅威インテリジェンス企業ReliaQuestは「大規模な悪用」を確認しており、Shellは89GBの企業データが窃取されたとみられる侵害の調査を継続しています。

**関連CBKドメイン**：ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン8（ソフトウェア開発セキュリティ）、ドメイン6（セキュリティの評価とテスト）

**コラム**：デシリアライズ脆弱性は設計・実装段階のセキュアコーディング不備に起因するものであり、ドメイン8で学ぶ入力検証やセキュアな開発ライフサイクル（SDLC）の重要性を改めて示す事例です。また、PLMのような業務基盤ソフトウェアはサプライチェーン上の共通コンポーネントとなりやすく、単一ベンダーの脆弱性が多数の大企業へ波及する構造的リスクを浮き彫りにしています。CISSP実務者としては、KEVカタログの監視とパッチ適用のSLA（サービスレベル合意）を平時から定めておくこと、そして境界防御だけでなくアプリケーション層の異常検知（Webシェル設置の検知等）を組み合わせた多層防御が不可欠であることを再認識すべきでしょう。

## 2. Microsoft 2026年8月Patch Tuesday、北朝鮮系ラザルスが悪用したWindowsカーネルドライバのゼロデイ（CVE-2026-68820）を修正

**概要**：Microsoftは2026年8月11日のPatch Tuesdayで421件の脆弱性（うち62件をCriticalに分類）を修正し、そのうち1件（CVE-2026-68820）はすでに実際の攻撃で悪用されていたゼロデイでした。CVE-2026-68820はWindowsのAncillary Function Driver for WinSock（AFD.sys）に存在するUse-After-Free（解放済みメモリ使用）の欠陥で、ローカルで実行中のコードが競合状態（レースコンディション）を引き起こしてカーネルメモリへアクセスし、権限をSYSTEMへ昇格させることが可能でした（CVSSスコア7.0）。北朝鮮を背景とするLazarus（ラザルス）が「Operation Dream Job」と呼ばれる偽求人を用いた標的型攻撃キャンペーンの一環として、少なくとも2026年7月上旬からこの脆弱性を防衛関連企業への攻撃に悪用し、カーネルモードのルートキット「FudModule」の新版にこのエクスプロイトを組み込んでいたことをCheck Point Researchが確認しています。タイムラインとしては、Check PointがMicrosoftへ7月28日に報告、7月31日に問題を確認、8月5日にCVE採番、8月11日に修正パッチが公開されました。CISAは本脆弱性をKEVカタログへ追加し、連邦機関に対し2週間以内のパッチ適用を求めています。同月のPatch Tuesdayでは他にもCVE-2026-62815（Microsoft QUIC、CVSS 9.8）やCVE-2026-62893（Windows Deployment Services、CVSS 9.8）などのRCE脆弱性も修正されています。

**関連CBKドメイン**：ドメイン7（セキュリティ運用）、ドメイン6（セキュリティの評価とテスト）

**コラム**：本件は「悪用は攻撃の最終段階だけでなく、初期侵入後の権限昇格フェーズでも起こる」ことを示す好例であり、ドメイン7で扱うパッチマネジメントと脆弱性管理プロセスの実効性が問われます。国家関与とみられる攻撃者が求人偽装というソーシャルエンジニアリングの初期侵入手法とゼロデイ悪用を組み合わせている点は、技術的対策だけでなく人的要因への教育（フィッシング耐性訓練）も併せて必要であることを示唆します。CISSP実務者は、CVSS基本値だけでなく実際の悪用状況（KEV登録の有無、APTグループとの関連性）を踏まえた優先順位付け（リスクベースパッチ管理）を行うべきです。

## 3. ShinyHunters、米医薬品卸大手McKessonへの侵害を主張し約74億円（5,523万ドル）の身代金要求

**概要**：データ恐喝集団ShinyHuntersは、米医薬品卸最大手McKesson社への侵入を主張し、患者2億8,400万人分に及ぶとする医療・身元・処方・医療提供者情報を窃取したと発表しました。ShinyHuntersによれば、複数のMcKesson従業員に対してボイスフィッシング（ビッシング）を行い、Okta経由のシングルサインオン（SSO）アカウントを乗っ取ったうえで、SalesforceおよびSnowflake環境へ横展開し、8月21日から25日にかけて約1テラバイトのデータを窃取したとされています。窃取されたと主張されるデータには、氏名、住所、社会保障番号（SSN）、病歴、処方・請求データ、医療提供者情報、医師と患者間のやり取りなどの機微情報が含まれます。McKessonは8月25日にインシデントを検知したと発表しており、調査は初期段階としています。ShinyHuntersはMcKessonに対し5,523万6,150ドルの身代金を要求し72時間の回答期限を設けたものの、同社からの交渉の申し出はなかったと主張しています。

**関連CBKドメイン**：ドメイン5（アイデンティティおよびアクセス管理）、ドメイン1（セキュリティとリスクマネジメント）、ドメイン7（セキュリティ運用）

**コラム**：本件はMFA（多要素認証）やSSOがあっても、ヘルプデスクを狙ったビッシングによりリセット・迂回されれば無力化されるという、IAM運用面の脆弱性を象徴する事例です。ドメイン5で学ぶ「本人確認プロセスの強化」「フィッシング耐性のある認証方式（FIDO2等）の採用」の重要性が改めて浮き彫りになりました。またSalesforceやSnowflakeのようなSaaS/クラウドデータ基盤への正規アクセス経路が悪用された点は、第三者・クラウドサービスにおけるアクセス制御とログ監視（ドメイン7）、サードパーティリスク管理（ドメイン1）の観点からも重要な教訓です。医療情報という機微性の高いデータを扱う組織では、通常時からインシデント対応計画（IRP）と身代金交渉方針を事前に定めておくことが求められます。

## 4. FBI・CISA・HHSがMedusaランサムウェアに関する合同勧告を更新、被害組織500以上に拡大

**概要**：米FBI、CISA、保健福祉省（HHS）は2026年8月18日、ランサムウェアアズアサービス（RaaS）型の「Medusa」に関する共同勧告「#StopRansomware」を更新しました。2021年6月に初めて確認されたMedusaは、二重恐喝（データ窃取＋暗号化、支払わない場合はリークサイトで公開すると脅迫）の手口を用いており、FBIの捜査によれば2026年4月時点で被害組織は500超に達し、2025年2月時点の300超から大幅に増加しています。被害は医療・教育・法律・保険・製造業・技術分野など重要インフラの多岐にわたるセクターに及び、今回の更新版では特に医療・公衆衛生セクターへの標的化に関する戦術・技術・手順（TTP）情報が追加され、HHSが初めて共同署名機関として名を連ねました。Medusaの攻撃者はセキュリティツールの無効化やネットワーク全体の暗号化を行うことで知られ、病院など可用性が生命に直結する組織への攻撃が特に懸念されています。

**関連CBKドメイン**：ドメイン7（セキュリティ運用）、ドメイン1（セキュリティとリスクマネジメント）

**コラム**：政府機関による合同勧告の更新頻度と対象拡大は、RaaSエコシステムの活動が継続的に進化していることを示しており、CISSP実務者はCISAやFBIが公開するTTP情報を定期的に確認し、自組織の検知ルール（EDR/SIEM）へ反映するプロセス（脅威インテリジェンスの運用への統合）を構築しておく必要があります。特に医療分野は可用性（Availability）が人命に直結するため、事業継続計画（BCP）・災害復旧計画（DRP）の実効性検証がドメイン1・7の実務として一層重要になります。二重恐喝への対策としては、バックアップの暗号化耐性・オフライン保管に加え、機密データの持ち出しを検知するDLP（データ漏洩防止）の強化が有効な選択肢となります。

## 5. CISAがmacOS・SharePoint・vCenter・Windows IKEの4件の脆弱性を「悪用確認済み」としてKEVカタログに追加

**概要**：米CISAは、実際に悪用が確認されたとして4件の重大脆弱性をKnown Exploited Vulnerabilities（KEV）カタログへ追加しました。対象は、（1）Apple macOSの認証不備（CVE-2026-65400）：ネットワーク経由で正当な認証情報なしに画面共有機能へ認証できてしまう欠陥で、Moneroのクリプトマイナー配布に悪用されたことが確認されています。（2）Microsoft SharePointの認証不備（CVE-2026-55040）：セキュリティ機能をネットワーク越しにバイパスできる欠陥で、概念実証（PoC）コードの公開後に不明な攻撃者による悪用が確認されました。（3）Broadcom VMware vCenterのパストラバーサル（CVE-2026-59310）：vCenterへのネットワークアクセス権を持つ攻撃者が任意コードを実行できる欠陥です。（4）Microsoft IKE（Internet Key Exchange）拡張のダブルフリー（CVE-2026-33824）：ネットワーク経由で未認証のままコード実行が可能な欠陥で、AI支援による自律型攻撃キャンペーンでの悪用が報告されています。4件はいずれも各ベンダーによりパッチ提供済みですが、KEV登録により米国連邦機関には期限内の緊急パッチ適用が義務付けられています。

**関連CBKドメイン**：ドメイン6（セキュリティの評価とテスト）、ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン4（通信とネットワークセキュリティ）

**コラム**：仮想化基盤（vCenter）、コラボレーション基盤（SharePoint）、エンドポイントOS（macOS）、VPN関連プロトコル（IKE）という異なるレイヤーの脆弱性が同時期にKEV登録された点は、攻撃対象領域（アタックサーフェス）がインフラのあらゆる層に広がっていることを示しています。ドメイン6で学ぶ脆弱性スキャン・KEVベースのパッチ優先順位付けの実践に加え、AI支援型の自動攻撃キャンペーンが既に現実の脅威として観測され始めている点は、防御側もAIを活用した検知・対応の高速化を検討すべき局面に来ていることを示唆します。境界だけでなく仮想化基盤・認証基盤への多層的な監視（ネットワークセグメンテーション、特権アクセス管理）がドメイン3・4の実務として引き続き重要です。

## 用語解説

- **CVE（Common Vulnerabilities and Exposures）**：ソフトウェアやハードウェアに存在する既知の脆弱性に対して付与される、世界共通の識別番号。「CVE-2026-XXXXX」の形式で管理され、脆弱性情報の共有や対応の追跡を容易にします。
- **CVSS（Common Vulnerability Scoring System）**：脆弱性の深刻度を0.0〜10.0のスコアで数値化する業界標準の評価基準。スコアが高いほど悪用時の影響や悪用の容易さが大きいことを示し、パッチ適用の優先順位付けに用いられます。
- **KEV（Known Exploited Vulnerabilities）カタログ**：米CISAが管理する、実際に野放しで悪用が確認された脆弱性の一覧。米連邦機関には期限内のパッチ適用が義務付けられ、民間企業でもパッチ優先度判断の参考指標として広く使われます。
- **ゼロデイ（Zero-Day）**：ベンダーが修正パッチを提供する前（あるいは脆弱性の存在を把握する前）に、攻撃者が悪用を開始する脆弱性・攻撃のこと。防御側の準備が整う前に攻撃が行われるため被害が拡大しやすい特徴があります。
- **RCE（Remote Code Execution／リモートコード実行）**：攻撃者がネットワークを通じて標的システム上で任意のコードを実行できてしまう脆弱性の種類。多くの場合、深刻度が非常に高く分類されます。
- **デシリアライズ（Deserialization）脆弱性**：シリアライズ（直列化）されたデータをプログラムが復元（デシリアライズ）する処理に不備があり、攻撃者が細工したデータを渡すことで任意コード実行等につながる脆弱性。安全でない入力データの検証不足が主な原因です。
- **Use-After-Free（UAF）**：一度解放（free）されたメモリ領域に対して、プログラムが誤って引き続きアクセスしてしまう脆弱性。攻撃者はこの隙を突いてメモリ内容を書き換え、コード実行や権限昇格につなげることがあります。
- **ランサムウェアアズアサービス（RaaS）**：ランサムウェアの開発者が攻撃ツールやインフラを「サービス」として提供し、実行役（アフィリエイト）が攻撃を行って収益を分配するビジネスモデル。攻撃の専門知識がなくても参入できるため、脅威の裾野を広げています。
- **二重恐喝（Double Extortion）**：ランサムウェア攻撃において、データを暗号化するだけでなく事前に窃取したデータを「支払わなければ公開する」と脅す手口。バックアップからの復旧のみでは対処できない点が特徴です。
- **ビッシング（Vishing）**：Voice（音声）とPhishing（フィッシング）を組み合わせた造語で、電話や音声通話を用いて標的から認証情報などを聞き出すソーシャルエンジニアリング手法。ヘルプデスクを騙ってパスワードリセットを行わせる手口が典型例です。
- **SSO（Single Sign-On）**：一度の認証で複数のシステム・サービスへアクセスできるようにする仕組み。利便性が高い一方、SSOの認証情報自体が侵害されると被害範囲が一気に拡大するリスクがあります。
- **MFA（Multi-Factor Authentication／多要素認証）**：パスワードに加えてワンタイムコードや生体認証など複数の要素を組み合わせて本人確認を行う認証方式。単一要素のみの認証に比べ不正アクセスのリスクを大幅に低減しますが、SIMスワップやビッシングによる回避手口も存在します。
- **パストラバーサル（Path Traversal）**：本来アクセスが許可されていないディレクトリ・ファイルへ、相対パス表記（「../」など）を悪用してアクセスしてしまう脆弱性。設定ファイルや機密ファイルの不正取得・改ざんにつながります。
- **DLP（Data Loss Prevention／データ漏洩防止）**：機密情報の外部への不正な送信・持ち出しを検知・防止するためのセキュリティ技術・運用の総称。二重恐喝型ランサムウェア対策としても重要視されています。
- **BCP／DRP（事業継続計画／災害復旧計画）**：インシデントや災害発生時にも重要業務を継続、あるいは早期復旧するための計画。ランサムウェアによるシステム停止は可用性（Availability）を脅かすため、平時からの計画策定・訓練が不可欠です。
- **単一情報源（Single Source）**：ある情報が一つの報道機関・発表元のみに基づいている状態を指し、事実関係の裏付けが取れていない可能性があることを示す表現。CISSP実務者は一次情報や複数ソースでの確認を心がけるべきです。
