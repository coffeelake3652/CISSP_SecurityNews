## 1. FortiMailのゼロデイ(CVE-2026-104286)が悪用:認証不要の任意ファイル書き込み

**概要:** FortiNetは、メールセキュリティ製品FortiMailのパストラバーサル(CWE-22)およびNULL文字の不適切な無害化(CWE-158)の脆弱性CVE-2026-104286(CVSS 9.8)が実際に悪用されていることを認めた。未認証の攻撃者が細工したHTTP/HTTPSリクエストを送ることで、システム上に任意のファイルを書き込める。影響バージョンはFortiMail 8.0.0〜8.0.1、7.6.0〜7.6.6、7.4.0〜7.4.8、7.2.0〜7.2.9で、修正版(8.0.2、7.6.7、7.4.9以上)は報道時点で一部「公開予定」とされ、7.2系は7.4系以上への移行が案内されている。CISAは2026年10月1日にKEVへ追加し、連邦機関の対応期限を同月4日とした(記事公開は10月2日)。侵害の痕跡として、/data/lib/liblog.so、/data/bin/webconsole、/data/bin/mailservice、/data/etc/ld.so.preload の追加、/bin/smit や /data/etc/httpd.conf の改変、通信元IP(79.141.169.187、45.129.0.192)が公開されている。被害件数・攻撃者の帰属は報じられておらず不明。修正版適用前の回避策は、CLIでIBE機能を無効化(`config system encryption ibe` → `set status disable`)し、管理インターフェースをインターネットから遮断して信頼できる内部網に限定すること。

**関連CBKドメイン:** ドメイン7(セキュリティ運用)、ドメイン3(セキュリティアーキテクチャとエンジニアリング)

**コラム:** 境界に置かれたセキュリティ製品自体が侵入口になる典型例で、パッチ未提供期間の「補償的統制」(機能無効化・管理面の隔離)が実務上の鍵となる。KEVやIOCを資産管理(CMDB)と突き合わせ、悪用確認からの対応期限を運用手順に組み込めているかが問われる。また、ld.so.preloadの改変は永続化の定番手法であり、ファイル完全性監視(FIM)の有効性を示す。セキュリティ製品を「信頼済み」と見なさず、管理プレーンの露出を最小化するゼロトラスト的設計が教訓である。

**参照:**
- [Critical FortiMail Zero-Day Flaw Exploited in Attacks Allows Unauthenticated Arbitrary File Writes - The Hacker News](https://thehackernews.com/2026/10/critical-fortimail-zero-day-flaw.html)

## 2. Cisco Secure Email Gatewayの重大脆弱性(CVE-2026-76519)が悪用、9月のSQLiも悪用確認

**概要:** Ciscoは2026年10月14日、Secure Email Gateway(AsyncOS)のファイル書き込み脆弱性CVE-2026-76519(CVSS 9.8)の勧告を公開し、実際の悪用を把握していると警告した。File Reputation(AMP)が有効でメールポリシーに割り当てられ、かつContent Scanner Toolsが25.3.0.5525より前の機器が対象で、細工した添付ファイル付きメールにより任意ファイル書き込みから、root権限でのコマンド実行に至る可能性がある。修正は15.5.5-014、16.5.0-780、またはContent Scanner Tools 25.3.0.5525以降(再起動不要)で、16.0系には修正版がなく移行が必要、回避策はない。同時に、9月14日に開示・修正されたSQLインジェクション(CVE-2026-76461、メール解析部の欠陥で未認証のroot実行が可能、KEV登録済み)も実際に悪用されていると勧告を更新した。侵害台数は非公表で、Ciscoは2件の攻撃を関連付けていない。2025年12月にはUAT-9686(中国系とされる)が別のゼロデイCVE-2025-20393(スパム隔離機能)を悪用しており、本件とは別事例として扱われている。CISAのKEV登録に伴う連邦機関の期限は10月17日。侵害確認は `grep "System Security" system_logs` の結果("Suspected compromise indicator was found" 等)で行い、侵害時は証拠保全後に新規VMを展開して設定を再構築、認証情報を更新する。

**関連CBKドメイン:** ドメイン7(セキュリティ運用)、ドメイン4(通信とネットワークセキュリティ)

**コラム:** メールゲートウェイは外部からの入力を常時パースする性質上、攻撃面が広く、同一製品で短期間に複数の悪用が出ることも珍しくない。インシデント対応では「アップグレード前にフォレンジックデータを保全する」「攻撃者がrootならログ自体が消されている前提で外部のFW/ネットワークログを確認する」といった手順の順序が重要になる。クラスタ構成でSSH鍵経由の横展開が懸念される点は、鍵管理と信頼関係の最小化(ドメイン5・3)にも通じる。回避策がない場合の影響範囲の特定と、サポート終了系統(16.0)の計画的な廃棄・移行は資産ライフサイクル管理の課題である。

**参照:**
- [Cisco Warns of Active Attacks Exploiting New Critical Secure Email Gateway Vulnerability - The Hacker News](https://thehackernews.com/2026/10/cisco-warns-of-active-attacks.html)
- [Cisco Warns of Exploited Secure Email Gateway Vulnerability - SecurityWeek](https://www.securityweek.com/cisco-warns-of-exploited-secure-email-gateway-vulnerability/)

## 3. 中国系ARMORY CASTLE(旧UNC5221)がBeyondTrust Remote Supportのゼロデイを悪用

**概要:** BeyondTrustは2026年10月15日、Remote Supportの重大脆弱性CVE-2026-102764(アドバイザリBT26-05、CVSS値は報道に記載なし、"critical"と説明)を公表した。未認証のリモート攻撃者がファイル操作(任意アップロードを含む)を行い、ホストレベルの侵害に至り得る。影響は26.2.3までのサポート対象バージョンで、コードを共有するPrivileged Remote Accessにも予防的パッチが出ているが悪用経路は未確認。時系列は、8月29日にホスト型1件・自己ホスト型1件での悪用を報告、9月28日にホスト型の侵害を特定して27分以内に封じ込め、10月15日に公表である。攻撃は中国関連とされるスパイ活動グループARMORY CASTLE(旧UNC5221)によるものと疑われ、難読化PHPのWebシェル「SAWFLY」(mangoapi.php)とWebSocket上のSOCKS5トンネラー「BARECLAW」が使われた。攻撃者はroot権限を得て、bt-secretsユーティリティで保管情報の取得を試み、管理者昇格、内部エンドポイントへのアクセス、ソフトウェアインベントリ等の偵察文書の持ち出しを行ったとされる。大規模なログ削除が見られ、第三者の自動トリアージが検知アラートを誤って「誤検知」と閉じていた点も報告されている。確認された侵害は2件のみで、被害者数・漏えい認証情報数は不明(単一情報源のため断定は避ける)。

**関連CBKドメイン:** ドメイン5(アイデンティティおよびアクセス管理)、ドメイン7(セキュリティ運用)

**コラム:** リモートサポート/特権アクセス製品は特権認証情報の集積点であり、侵害されると全社的な横展開の起点となる。ベンダーが開示まで約1か月半かけた点は、責任ある開示とユーザー保護のバランスの例であり、利用者側は「公表前に侵害されている可能性」を前提にしたハンティングが必要である。自動トリアージの誤クローズは、SOC運用における自動化の品質管理(ドメイン7)と、特権アクセスの保管情報(シークレット)の最小化・ローテーション(ドメイン5)の双方を示唆する。

**参照:**
- [China-Linked Hackers Exploit Critical BeyondTrust Zero-Day to Steal Credentials - Cyberpress](https://cyberpress.org/china-linked-critical-beyondtrust-zero-day)

## 4. Microsoft 10月のパッチで史上最多1,413件、MotW回避ゼロデイ(CVE-2026-96951)が悪用

**概要:** Microsoftは2026年10月14日(米東部時間)の月例更新で、過去最多となる1,413件のCVEを修正した。内訳はWindows 1,102件、Office 134件、開発者ツール61件、SharePoint Server 36件などで、今月だけで2025年1年分を上回り、2026年の累計は4,000件を超えた。件数急増は「AIによる脆弱性発見が主因」と報じられている。悪用が確認されたゼロデイはWindowsシェルのセキュリティ機能バイパスCVE-2026-96951(CVSS 8.8)で、Mark of the Web(MotW)による保護を回避される。報告者はFujitsu、Anthropic、独立研究者で、攻撃の詳細は非公開。CISAは10月13日にKEVへ追加し、連邦機関に10月16日までの対応を求めた。公表済み(修正前開示)の脆弱性として、WDACの強制を回避するCVE-2026-108398、Visual Studio/.NETのMessagePack-CSharpのDoS(CVE-2026-92707)がある。Microsoftは優先順位付けを支援する「リスクコホート」も導入したが、報道は個別CVEの悪用状況・深刻度の確認が必要だとしている。Critical件数は記事に記載なし。

**関連CBKドメイン:** ドメイン7(セキュリティ運用)、ドメイン6(セキュリティの評価とテスト)

**コラム:** 月に1,400件超という量は、「全件を同じ重みで当てる」パッチ管理が破綻しつつあることを示す。KEV・悪用可能性・資産の重要度に基づくリスクベースの優先順位付け(脆弱性管理プロセス)が必須であり、これはドメイン7と6に直結する。MotW回避は、メール添付・ダウンロードファイル経由の初期侵入を防ぐ「多層防御の一層」が崩れることを意味し、WDACやASR等の補完的統制の検証が有効である。AIによる発見の加速は、防御側の検証・テスト能力にも同じ増幅が求められることを示唆する。

## 5. CISAがPAN-OS・Cisco・AhsayCBSの悪用済み脆弱性をKEVに追加

**概要:** CISAは10月15日前後に、Palo Alto Networks PAN-OSの管理インターフェースのRCE(CVE-2026-0322、CVSS 8.6、認証済み攻撃者がrootで任意コード実行、「非常に限定的な悪用」を観測)、前述のCisco CVE-2026-76519、およびAhsay AhsayCBSの認証不備CVE-2026-105133とコマンドインジェクションCVE-2026-105134(SYSTEM権限での実行)をKEVに追加した。AhsayCBSの2件は連鎖されてWebシェルやクリプトマイナーの設置に悪用されており、以前のパッチ(v9.15.2.59、v10.3.4.0)は不完全だったため、v10系はv10.3.4.45ホットフィックス、v7〜v9系はv9.15.2.70の適用と再起動が必要とされる。連邦機関の対応期限はいずれも10月17日。PAN-OSは10.2、11.1、11.2、12.1、12.2に対策版があり(11.2.16は10月15日公開予定)、回避策は管理インターフェースを信頼できる内部IPに限定すること。Cloud NGFWとPrisma Accessは影響を受けない。CVSSの一部は報道に記載がなく「medium/critical」の表現のみ(単一情報源)。

**関連CBKドメイン:** ドメイン7(セキュリティ運用)、ドメイン3(セキュリティアーキテクチャとエンジニアリング)

**コラム:** 不完全なパッチ(AhsayCBS)は「パッチ適用済み=安全」ではないことを示し、適用後の検証スキャンや再テストの重要性を示す。管理インターフェースの露出制限は、PAN-OSでもFortiMailでも共通の第一防衛線である。KEVを脅威インテリジェンスとして取り込み、自組織の資産と自動突合する仕組みは、脆弱性管理の成熟度を測る指標となる。

## 用語解説

- **CVE(Common Vulnerabilities and Exposures):** 公開された脆弱性に付与される共通の識別番号。製品や報道をまたいで同じ脆弱性を指すために使う。
- **CVSS(Common Vulnerability Scoring System):** 脆弱性の深刻度を0〜10で表す共通指標。9.0以上は「緊急(Critical)」とされるが、実際の悪用状況とは別に評価する必要がある。
- **KEV(Known Exploited Vulnerabilities)カタログ:** CISAが管理する「実際に悪用が確認された脆弱性」の一覧。米連邦機関に対応期限が設定され、民間でも優先順位付けの指標になる。
- **ゼロデイ:** パッチが提供される前、または開発元が把握する前から悪用される脆弱性。
- **パストラバーサル(CWE-22):** `../` などでアクセス許可範囲外のディレクトリ・ファイルを操作する脆弱性。任意ファイル書き込みやコード実行につながる。
- **NULL文字の不適切な無害化(CWE-158):** NULL文字(終端文字)の扱いを誤り、入力検証をすり抜けられる欠陥。
- **SQLインジェクション:** 入力に混ぜたSQL文をデータベースに実行させる攻撃。認証回避やコマンド実行まで発展することがある。
- **コマンドインジェクション:** 入力値を経由して、OSコマンドを不正に実行させる攻撃。
- **RCE(リモートコード実行):** 離れた場所から対象システム上で任意のコードを実行できる状態。
- **root / SYSTEM権限:** それぞれLinux・Windowsの最高権限。奪取されると機器の完全な制御を許す。
- **Webシェル:** サーバー上に設置される遠隔操作用スクリプト。攻撃者の足場・永続化に使われる。
- **IOC(Indicators of Compromise/侵害指標):** 侵害の痕跡となるIPアドレス、ファイル名、ハッシュ値など。検知やハンティングに用いる。
- **永続化(Persistence):** 再起動や再ログイン後も攻撃者が侵入状態を維持するための仕組み(例: ld.so.preload改変)。
- **SOCKS5トンネラー:** SOCKS5プロトコルで通信を中継し、内部ネットワークへ到達する経路を作るツール。
- **FIM(File Integrity Monitoring/ファイル完全性監視):** 重要ファイルの改変を検知する仕組み。
- **補償的統制(Compensating Control):** 本来の対策(パッチ等)が使えない間に、リスクを下げるため代替で講じる統制(機能無効化、アクセス制限など)。
- **ゼロトラスト:** 内部・外部を問わず信頼を前提にせず、常に検証してアクセスを許可する設計思想。
- **特権アクセス管理(PAM):** 管理者など強い権限の認証情報・操作を保護・監査する仕組み。リモートサポート製品は特権の集積点になりやすい。
- **MotW(Mark of the Web):** インターネットから取得したファイルに付くマーク。実行時に警告や保護を働かせる仕組みで、回避されると初期侵入が容易になる。
- **WDAC(Windows Defender Application Control):** 許可したアプリ/コードのみ実行させるWindowsの制御機能。
- **DoS(サービス拒否):** 過負荷や不具合の誘発でサービスを使えなくする攻撃。
- **脆弱性管理:** 脆弱性の識別・評価・優先順位付け・対処・検証を継続的に回すプロセス。
- **ランサムウェア:** データを暗号化(または窃取)して身代金を要求するマルウェア。
- **サプライチェーンリスク(サードパーティリスク):** 委託先・クラウド事業者など外部の弱点が自社に波及するリスク。
- **責任共有モデル:** クラウドで、事業者と利用者が守る範囲を分担する考え方。
- **BCP / DR:** 事業継続計画/災害復旧。障害や攻撃時に業務とシステムを復旧させる計画。
- **RTO / RPO:** 目標復旧時間/目標復旧時点。許容できる停止時間とデータ損失の上限。
- **イミュータブルバックアップ:** 一定期間、改変・削除できない設計のバックアップ。ランサムウェア対策の要。
- **DLP(Data Loss Prevention):** 機密情報の持ち出し・誤送信を検知・防止する仕組み。
- **CSPM(Cloud Security Posture Management):** クラウド設定の不備を継続的に検出・是正する仕組み。
- **データ分類:** 情報を機密度で区分し、取り扱いルールを決める手法。ドメイン2の中心概念。
- **JPCERT/CC:** 日本のコンピュータセキュリティインシデント対応チーム。注意喚起や調整を行う。
- **UNC / UAT(攻撃グループ識別名):** 帰属が確定していない脅威活動クラスタに付ける暫定名称。
