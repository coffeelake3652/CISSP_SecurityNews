## 1. CISA、WordPress Core の TOCTOU 競合状態（CVE-2026-119977）をKEVに追加 — コア更新中の一時ファイル経路を突く未認証RCE

**概要**
CISAは2026年11月3日付（アラートURLの日付による）で、WordPress Coreの時間差競合（TOCTOU）脆弱性 CVE-2026-119977 を悪用が確認された脆弱性カタログ（KEV）に追加した。CVSSは8.1（Wordfence CNA評価、攻撃複雑度が高い）で、WordPress側の自己評価は「Low」とされ、評価が割れている。CISAの説明（The Hacker News経由）では、フルパッケージによるコア更新時に使われる「予測可能でWebから到達可能なステージング用パス」が根本原因で、更新ウィンドウ中に未認証の攻撃者がサーバ上でコードを実行できる。Wordfenceは、公開後21時間で `wp-content/upgrade/` 配下のステージング済み `setup-config.php` を狙うリクエストを18,500件超観測したと報告している。修正版は2026年10月28日に公開された7.1.4（7.0.8、6.9.11等のバックポートも提供と報じられている。4.6以前は修正なし）。Previdianのハニーポットは10月30日に英国のIPからの悪用試行3件を最初の悪用として観測した。ブロック数はTHN記事（24時間で12,632件）と別報（62,969件との引用）で食い違っており、確定値としては扱えない。CISAはFCEB機関の対処期限を11月6日に設定した。攻撃者・攻撃グループの特定はされていない。なお本件は前日版で扱った「wp2shell」とは別CVEの案件である。

**関連CBKドメイン**
ドメイン7（セキュリティ運用）、ドメイン8（ソフトウェア開発セキュリティ）

**コラム**
パッチ適用そのもの（更新処理）が攻撃面になるという点で、変更管理・パッチ管理プロセスの設計が問われる事例である（ドメイン7）。「更新を急ぐほどリスクが高まる時間帯がある」ため、更新時はWAFでの一時パス遮断や自動更新のメンテナンスウィンドウ化など補完策が要る。ドメイン8の観点では、予測可能な一時パスと競合状態という典型的な設計欠陥であり、脅威モデリング段階で「更新中の中間状態」を検討する重要性を示している。CVSS 8.1でも悪用が現実化した点は、スコアのみに依存せずKEVを優先度判断に組み込むべき教訓となる。

## 3. Ruby on Rails Active Storage に CVSS 9.8 の重大脆弱性 — 細工した画像アップロードで未認証のサーバファイル書き込み

**概要**
Rails側のアドバイザリ GHSA-f3w6-w445-fwh9（CVEは本稿時点で未採番、CVSS 9.8）は、Active Storageが受け取るSVGがImageMagickのMSLコーダに到達することで、未認証の攻撃者が任意のサーバファイルを書き込める（Diskサービス利用アプリでは読み取りも可能）という内容である。アップロードを添付（attach）するだけで成立し得る。影響は8.0.5.2より前のすべてのActive Storageおよび8.1.4.1より前の8.1系で、修正版は8.1.4.1と8.0.5.2。同時に別の GHSA-v924-7rp8-4mxh（CVSS 8.8）も公表された。発見者はGMO Flatt SecurityのRyotaK氏。2026年11月4日に報じられ、悪用は確認されていない（攻撃チェーンの存在は報告されている）。

**関連CBKドメイン**
ドメイン8（ソフトウェア開発セキュリティ）、ドメイン6（セキュリティの評価とテスト）

**コラム**
画像処理ライブラリ（ImageMagick等）への入力検証は繰り返し狙われる古典的な攻撃面である。ドメイン8として、アップロード機能では許可する形式の厳格なホワイトリスト化、SVGの扱いの分離、ImageMagickのpolicy.xmlによるコーダ無効化が基本対策となる。ドメイン6の観点では、SCA/SBOMで依存関係の脆弱性を継続的に棚卸しし、CVE未採番の段階でもGHSAを監視対象に含める運用が望ましい。

**参照**
- [Critical Rails Flaw Lets Attackers Write Server Files（The Hacker News）](https://thehackernews.com/2026/11/critical-rails-flaw-lets-attackers.html)

## 4. Xenハイパーバイザの XSA-523（CVE-2026-102703／102704）— 悪意あるゲストVMが他VM・dom0のメモリを読み書き可能

**概要**
2026年11月3日に公表されたXen Security Advisory XSA-523は、grant-copyの権限検査が再利用され再検証されないため、悪意あるゲストが他VM（dom0を含む）のメモリを読み書きできるという内容で、CVE-2026-102703とCVE-2026-102704が割り当てられている。影響はXen 4.6以降（4.5以前は影響なし）。Vatesは重大度をCriticalと評価している（記事にCVSSの記載なし）。修正はXCP-ng 8.3（xen-4.17.7-4.2.xcpng8.3、11/3）、Qubes 4.3（Xen 4.19.6-3）、Xen 4.19.x/4.18.x/4.17.xのパッチで提供される一方、4.6〜4.16には修正がない。THNの報道では、発見者はAnthropic（Claude）で、Ada Logicsが検証したとされる（単一情報源）。悪用の報告はない。

**関連CBKドメイン**
ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン7（セキュリティ運用）

**コラム**
ハイパーバイザの境界はマルチテナント環境の信頼の根であり、VMエスケープ級の欠陥はクラウド基盤全体のリスクに直結する（ドメイン3）。修正が提供されない旧系列（4.6〜4.16）を使う環境では、EOL機器と同様にリスク受容・隔離・移行計画の判断が必要となる（ドメイン7）。また、AIによる脆弱性発見が実運用レベルに達しつつあることから、パッチ公開から悪用までの時間短縮を前提とした運用設計が求められる。

**参照**
- [Xen Hypervisor Flaws Let One Malicious VM Read/Write Other VMs' Memory（The Hacker News）](https://thehackernews.com/2026/11/xen-hypervisor-flaws-let-one-malicious.html)

## 5. JPCERT/CC（JVN#12040144）: Airbyteの任意コード実行脆弱性 — 悪用確認済み、Connector Builder経由でRCE

**概要**
JPCERT/CCは2026年11月4日、データ連携基盤Airbyteの任意コード実行の脆弱性をJVNで「緊急」として公表した。CWE-470（不適切なクラスロード）で、「unsafe codeが無効」な設定でもConnector Builderのカスタムコンポーネント経由でコードが実行される。CVSS v4.0は8.7、v3.0は8.8（権限: 低、ネットワーク経由）、JVNのページに悪用確認の記載がある。影響バージョンは1.7.0〜2.1.0、対策は最新版（2.2）への更新で、ベンダーアドバイザリはGHSA-g35w-6r6v-h4r7。実行はAirbyteユーザー権限でConnector BuilderまたはManifestServerコンテナ内に限られる。発見者はZOZO社の担当者（Early Warning Partnership経由）。CVE番号は取得時点のJVNページに記載がなかった。

**関連CBKドメイン**
ドメイン8（ソフトウェア開発セキュリティ）、ドメイン7（セキュリティ運用）

**コラム**
データパイプライン基盤は多数のシステムの認証情報を集約するため、侵害時の影響範囲が広い。ドメイン8として、動的コード読み込み機能の安全設計（サンドボックス化）を、ドメイン7として、パイプライン基盤を外部公開しない・認証情報を最小権限とする運用を押さえたい。悪用確認済みのため、1.7.0〜2.1.0を使う組織は更新とともに侵害調査（コンテナ内の不審プロセス、保存済みシークレットのローテーション）を検討すべきである。

**参照**
- [JVN#12040144 Airbyteにおける任意のコードが実行可能な脆弱性](https://jvn.jp/jp/JVN12040144/)
- [GHSA-g35w-6r6v-h4r7（Airbyte）](https://github.com/airbytehq/airbyte/security/advisories/GHSA-g35w-6r6v-h4r7)

## 用語解説

- **CISSP**: 情報セキュリティ分野の国際的な専門資格。CBK（共通知識体系）に基づく8ドメインで構成される。
- **CBK**: Common Body of Knowledge。CISSPの出題範囲を体系化した知識領域。
- **KEV**: Known Exploited Vulnerabilities。CISAが管理する「悪用が確認された脆弱性」のカタログで、対処優先度の判断材料になる。
- **CISA**: 米国のサイバーセキュリティ・インフラ安全保障庁。
- **FCEB**: 米連邦政府の文民行政機関。KEV掲載脆弱性には対処期限が設定される。
- **JPCERT/CC**: 日本のコンピュータ緊急対応センター。脆弱性情報の調整や注意喚起を行う。
- **JVN**: Japan Vulnerability Notes。JPCERT/CCとIPAが運営する国内向け脆弱性情報データベース。
- **CVE**: 共通脆弱性識別子。個々の脆弱性に付与される一意のID。
- **CVSS**: 共通脆弱性評価システム。脆弱性の深刻度を0〜10で数値化する。
- **GHSA**: GitHub Security Advisory。GitHub上で公表されるセキュリティ勧告のID。
- **CWE**: 共通脆弱性タイプ一覧。脆弱性の種類（原因分類）を示す。
- **CNA**: CVE採番機関。
- **RCE**: Remote Code Execution。遠隔から任意のコードを実行される脆弱性。
- **TOCTOU**: Time-of-check to time-of-use。検査から使用までの間に状態が変わることを突く競合状態の脆弱性。
- **競合状態（Race Condition）**: 処理の順序やタイミング次第で結果が変わる欠陥。
- **ステージング**: 本番反映前に一時的にファイルを置く工程。
- **WAF**: Webアプリケーションファイアウォール。Web攻撃を検知・遮断する。
- **ウォーターホール攻撃**: 標的がよく訪れるサイトを改ざんして感染させる手法。
- **サプライチェーン攻撃**: 取引先や利用ソフト・サービスを経由して標的を攻撃する手法。
- **APT29**: ロシア対外情報庁（SVR）系とされる攻撃グループ。
- **エクスプロイトチェーン**: 複数の脆弱性を連鎖させて権限昇格や端末掌握を行う攻撃手順。
- **CSP**: Content Security Policy。ブラウザが読み込めるスクリプト等の取得元を制限する仕組み。
- **SRI**: Subresource Integrity。外部スクリプトのハッシュ検証で改ざんを検出する仕組み。
- **MDM**: モバイルデバイス管理。端末の設定・更新を一元管理する。
- **ImageMagick**: 画像変換・加工のオープンソースライブラリ。過去に多数の脆弱性が報告されている。
- **MSLコーダ**: ImageMagickのスクリプト形式（Magick Scripting Language）を処理する部分。
- **SBOM**: ソフトウェア部品表。含まれる部品とバージョンの一覧。
- **SCA**: ソフトウェア構成解析。依存ライブラリの脆弱性を検出する。
- **ハイパーバイザ**: 仮想マシンを動かす基盤ソフトウェア。
- **dom0**: Xenの特権管理ドメイン。侵害されると全VMに影響し得る。
- **VMエスケープ**: ゲストVMからホストや他VMに影響を及ぼす攻撃。
- **EOL**: サポート終了。修正が提供されなくなる状態。
- **Early Warning Partnership**: JPCERT/CC等が参加する、脆弱性の調整済み開示のための国内制度。
- **ManifestServer/Connector Builder**: Airbyteでデータコネクタの定義・作成を行う構成要素。
- **キャッシュ汚染（Cache Poisoning）**: 不正な内容をキャッシュに保存させ、他の利用者に配信させる攻撃。
- **HttpOnly**: JavaScriptからCookieを読めなくする属性。
- **LTS**: 長期サポート版。
- **ステーブルコイン**: 法定通貨等に価値を連動させた暗号資産。発行体は資産を凍結できる場合がある。
- **BYOD**: 私物端末の業務利用。
- **AD**: Active Directory。Windows環境のID・認証基盤。
- **個人情報保護法の漏えい等報告**: 一定の漏えい事案で個人情報保護委員会への報告と本人通知を求める制度。
