## 1. PHP2Shell: PHP本体に未認証RCE 2件（CVE-2026-109618 / CVE-2026-109619）— 国内外で悪用観測、FW製品の侵害も

**概要**
The PHP Groupは2026年10月21日、PHP本体の重大な脆弱性2件の緊急修正版を公開した。CVE-2026-109618は「OOM（メモリ不足）時のリクエスト後処理で、部分的にしか初期化されていない内部データが有効として扱われる」ことによるRCE、CVE-2026-109619は「解放後もグローバル状態が残り、同一ワーカーの後続リクエストで再利用される（stale global state）」ことによるRCEである。単一の未認証リクエストでアプリケーションコードの実行前に攻撃が成立し得るとされ、PHP-FPM、Apache mod_php、php-cgi、FrankenPHP、LiteSpeedなどWebリクエストを処理するPHP環境が広く対象となる（CVSSは参照した情報源に明記なし＝未確認、ただし「最も深刻なPHPの脆弱性の一つ」と評価）。修正版は PHP 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 で、EOLの7.4・8.0・8.1には最小限のバックポートが提供された。時系列では、AmazonのMadPotハニーポットが**10月17日**（禁輸＝エンバーゴ期間中）に悪用試行を記録しており、公開の4日前に攻撃者が詳細を把握していた可能性がある。10/22にはPalo Alto NetworksがPAN-OS/Panoramaの全バージョンが影響を受けると発表（当時は未修正）、FortinetとCiscoも多数製品（12製品・31製品）を調査中とされた。JPCERT/CCは10/22に注意喚起（AT-2026-0033）を出し、10/29更新で「あるファイアウォール製品の特定バージョンの侵害の痕跡」「本脆弱性とLinuxカーネルの権限昇格を組み合わせたエクスプロイト」「内部への横展開の痕跡」を報告、さらに別の追加脆弱性CVE-2026-115560（10/23公表、特定設定依存）にも触れている。また10/28時点でWordfenceはWordPress向けに500万サイト超を保護しているが、確認された侵害はないと報告されている。CISAはKEVに追加済みとの二次情報があり、英NCSCは修正できないシステムのオフライン化を促している。

**関連CBKドメイン**: ドメイン8（ソフトウェア開発セキュリティ）、ドメイン7（セキュリティ運用）、ドメイン3（セキュリティアーキテクチャとエンジニアリング）

**コラム**
言語ランタイム自体の脆弱性は、個別アプリの品質管理（ドメイン8）では防げない「共通基盤リスク」であり、ソフトウェア部品表（SBOM）と資産台帳に基づく影響範囲の即時特定能力が問われる。特に、FW・VPN・NAS・管理画面など「PHPを同梱する製品」はベンダー修正待ちとなり、ベンダーが修正を出すまでの間は補完的統制（WAF、アクセス制限、オフライン化の判断）で時間を稼ぐ必要がある（ドメイン7：インシデント対応・パッチ管理）。禁輸期間中の悪用試行という事実は、「公開日＝リスク開始日」ではないことを示しており、侵害調査（異常なPHPSESSID、multipart/form-dataとメモリ上限エラー、ワーカー異常終了の確認）を並行して行うべきである。EOL版（8.1以前）の残存はアーキテクチャ上の負債（ドメイン3）として経営リスクに位置付けたい。

## 2. eMudhra 中間CA 8鍵が脆弱な乱数で生成・計算可能に — 主要ブラウザ/OSが緊急ブロック

**概要**
インドの認証局eMudhraが2025年4月30日に実施したキーセレモニーで、欠陥のあるスクリプトにより「弱い鍵セット」が生成され、中間CA証明書8件（TLS用6件：DV/OV/EV×G3B/G3C、コード署名用2件）の秘密鍵が公開証明書から計算可能な状態になっていた。鍵が256未満の小さな数値で、研究者Scott Helmeは公開証明書から1秒未満で復元できたとされる。研究者「Wayne」が**10月17日**にCommon CA Database確認中に発見し報告、Chromeは同日、Mozillaは10/17〜18にブロックを実施、Appleは10/19、Microsoftは10/20に対応した。eMudhraは10/18に該当証明書を失効し、10/21にプレスリリース、CERT-Inが勧告を出した。Go（CVE-2026-111943）、Node.js、Debian/Ubuntu、Red Hat、Cloudflareなども修正を出し、Mozillaは emSign ECC Root CA - G3 をNSSから削除した。影響は、条件次第で任意ドメインのHTTPS証明書偽造が可能という点にあるが、Chromeは証明書透明性（CT）ログ上で該当中間CA配下の発行証明書を確認しておらず、eMudhraも本番投入は1中間CAのみで顧客証明書は未発行と説明している。一方で顧客証明書約3万件の再発行が必要とされ、同社は世界向けSSL/TLS事業から撤退する方針（同事業は売上の約1%）、10/21にムンバイ市場で株価が約20%下落したと報じられた。失効確認を行わないアプリ・機器は引き続き信頼し続けるリスクが残る（FreeBSD、Bun、macOSのcurl等は修正待ち）。過去に悪用されたかは不明。

**関連CBKドメイン**: ドメイン3（セキュリティアーキテクチャとエンジニアリング／暗号とPKI）、ドメイン4（通信とネットワークセキュリティ）、ドメイン1（リスクマネジメント／サードパーティ）

**コラム**
PKIの信頼は「鍵生成の乱数品質」と「儀式（ceremony）の手順統制」に依存し、人的ミスが1件あるだけで信頼の連鎖全体が崩れることを示す事例である（ドメイン3）。実務者は、①自社資産のルートストア/信頼リスト更新の仕組み（失効・CRLSet・OneCRL・OSバンドル）が機能しているかの確認、②証明書ピンニングや独自CAバンドルを持つ組込機器・コンテナの棚卸し、③CTログ監視による不正証明書の検出、を準備しておくべきである。また、CAという外部サプライヤーの集中リスクと出口戦略（CA事業者撤退時の再発行計画）は、ドメイン1のサードパーティ管理に直結する。

## 3. LiteLLM v1.107.0 がPyPI/Docker Hub/GHCRで汚染 — リリースパイプライン乗っ取りによる認証情報窃取

**概要**
LLMプロキシOSSのLiteLLMで、2026年10月21日（UTC）にバージョン1.107.0が改ざんされ、PyPI（wheel7種、約11:39〜13:23 UTC）、Docker Hub（11:46〜14:20 UTC）、GHCR（〜13:51 UTC）に悪意あるアーティファクトが公開された。ペイロードはクラウド認証情報・パスワード・AIサービス認証情報を狙う情報窃取機能と、リモートコード実行ツールのローダー（`cook.pth`、`sitecustomize.py`、`/tmp/remote_code_loader.lock` を持つデーモン）である。GitHub上の公式v1.107.0タグには悪性ファイルは含まれず、攻撃者管理のリポジトリからビルドされた点が特徴である。同社の初期分析では、GitHub CLIのOAuthトークンが公開状態の内部LiteLLM環境のログから漏えいした可能性、組織オーナーのトークンでブランチ保護を無効化しワークフローを偽リポジトリ（Berri-AI/litellm）に向け直したこと、リリース権限が一時的に拡大されていたこと、複数の開発者認証情報で承認ゲートを回避したことが挙げられている（同社自身が初期の推定の一部は不正確だった可能性を注記）。対処として1.106.2へのピン留め、侵害ホストでは`pip install`を実行せず`.pth`等を削除して環境を再構築、到達可能な全シークレットのローテーション、CloudTrailでの`GetCallerIdentity`確認が推奨され、cosign署名鍵も10/23にローテーションされた。TechCrunchはPHP、Node.js、eMudhraと同日（10/21）に重なった事案として報じた。

**関連CBKドメイン**: ドメイン8（ソフトウェア開発セキュリティ）、ドメイン5（アイデンティティおよびアクセス管理）、ドメイン1（サプライチェーンリスク）

**コラム**
「署名が有効でも信頼できない」点が教訓である。署名鍵やCI/CD権限が奪取されれば正規署名付きの悪性成果物が配布されるため、ビルドの来歴証明（provenance／SLSA）と、ソースタグとアーティファクトの照合が必要になる（ドメイン8）。また、特権トークンの管理（短寿命化、最小権限、ログへの混入防止）と、緊急対応時の一時的な権限拡大の統制は、IAMの典型的な弱点である（ドメイン5）。AI関連ツールは多数のクレデンシャルを集約しがちで、攻撃者にとって高価値の集約点になる点も、リスクアセスメントに反映したい（ドメイン1）。

## 4. BeyondTrust Remote Support のゼロデイ（CVE-2026-102764）— 中国関連APT「ARMORY CASTLE」が8月から悪用

**概要**
BeyondTrust Remote Supportのゼロデイ脆弱性CVE-2026-102764が、疑われる中国関連のスパイ活動グループ「ARMORY CASTLE」（Mandiantが従来UNC5221として追跡、CrowdStrikeはWARP PANDAと呼ぶ同一クラスタ）により、**8月29日**から悪用されていた。対象は26.2.3までのサポート対象バージョンで、ホスト型1件・自社運用型1件のインスタンスで悪用が確認された。BeyondTrustの脅威ハンティングが9月28日に活動を特定し、10月8日にパッチ（BT26-05）を公開、MandiantによればSaaSテナントは10/9までに全て修正済みである。自社運用の顧客は手動適用が必要で、24.3.1より古い版は先にサポート対象版へアップグレードが必要とされる。攻撃者は侵害後、リモートセッション経由で内部システムに到達し、文書やソフトウェアインベントリを収集した。報道では検知から封じ込めまで27分とされる。PRA（Privileged Remote Access）も共通コードのため予防的パッチが出された。CVSSは参照した情報源に明記なし（記事見出しでは管理者権限を数分で取得できると表現、単一の二次情報中心）。

**関連CBKドメイン**: ドメイン5（アイデンティティおよびアクセス管理／特権アクセス）、ドメイン7（セキュリティ運用）

**コラム**
特権リモートアクセス製品は「正規の経路」で内部に入れるため、侵害されると境界防御を素通りされる。ゼロデイの悪用期間が約40日（8/29〜10/8）に及んだ点は、パッチ適用だけでなく脅威ハンティングと侵害前提の運用（ドメイン7）が不可欠であることを示す。特権アクセス管理の観点では、管理系製品のインターネット露出の最小化、セッション記録とアラート、ネットワークセグメンテーション、パッチ公開後の遡及的侵害調査（8月まで遡る）が要点となる（ドメイン5）。

## 5. IDCFクラウドにランサムウェア攻撃 — 495社・自治体に影響、仮想基盤管理者権限を奪取

**概要**
IDCフロンティアのIDCFクラウド（東日本リージョン1、福島データセンター）で、2026年10月7日午前3時40分頃に障害が発生し、同日夕方までに第三者によるランサムウェアが原因と発表された。影響は495社・自治体に及び、官公庁・自治体サイトの停止や物流会社の出荷停止などが報じられた。10/8には4ゾーン（tesla、henry、pascal、joule）のデータ復旧が困難な可能性が示され、顧客は自前バックアップからの復旧が基本となった。10/14時点で、バックアップデータを取得できた顧客は194社、10/20時点で206社に増加。10/27の第7報で調査完了とされ、侵入口は**認証基盤で使われているOSSの脆弱性**（製品・脆弱性名は非公表）、その後に管理コンソール経由で仮想化基盤の管理者権限を取得し、顧客の仮想サーバを停止・暗号化したとされる。ポータルの登録情報が最大71社分不正に参照され、うち最大31社に氏名・メールアドレスが含まれ得る。ログインパスワードが最大4件不正に変更された。データの外部持ち出しは確認されていない。攻撃者は未特定、身代金の支払い・交渉は行っていない。上記の詳細は第三者（ウェステリア）による整理に基づくため、一次情報（idcf.jp）の確認が望ましい。

**コラム**
クラウド事業者の管理プレーンが侵害されると、テナント分離をまたいで大規模影響が出る「集中リスク」の典型である。利用者側は、IaaSでも「責任共有モデル」上バックアップは自責であり、同一事業者内スナップショットだけに依存しない別系統・別事業者のバックアップとRTO/RPOの検証が必須である（ドメイン7）。また、事業者のリージョン単位障害を想定したマルチリージョン／マルチクラウド設計（ドメイン3）と、委託先事業者の事故時の連絡体制・契約条項（ドメイン1）を見直す契機となる。

## 6. JPCERT/CC「国内組織で相次ぐ不正アクセス」注意喚起 — API悪用・Metabase SQLi・AI侵入テストツール悪用

**概要**
JPCERT/CCは2026年10月8日、9月ごろから国内組織で個人情報等の漏えいを伴う不正アクセスが相次いでいるとして注意喚起（AT-2026-0030）を公開し、10/9・10/23に更新した。10/23時点では5類型が整理されている。(A)既知の脆弱性や設定不備（設定・バックアップファイルの窃取）の網羅スキャン、(B)スマホアプリの解析で得たAPIエンドポイント・キーを使った内部API不正操作（権限変更、不正アカウント作成、NoSQLインジェクションによるアカウント情報の抽出）、(C)Metabaseの脆弱性（CVE-2026-72898）を悪用したSQLインジェクション、(D)公開Webサーバから到達可能なアプリケーションサーバへのJSP Webシェル入りWARファイル設置、(E)Cairn、CyberStrikeAI、ARTEXなど**AI侵入テストツール**による公開Webアプリの脆弱性・設定不備のスキャン（公開WSUSサーバへの攻撃を含む）。BIツールや従業員向けシステムなど「一般公開を意図しない内部システム」も侵害対象になる点が強調されている。対策としてレート制限（ログイン・パスワードリセット・SMS・検索等を厳格化）、全エンドポイントのアクセス制御、最小権限、トークンの短寿命化と即時失効、地域制限、保持期間を過ぎたデータの削除などが示された。情報共有が限定的なため断片的な情報に基づく点が注意書きされている。

**関連CBKドメイン**: ドメイン5（IAM）、ドメイン8（ソフトウェア開発セキュリティ／API）、ドメイン2（資産のセキュリティ／データ保持・廃棄）、ドメイン6（評価とテスト）

**コラム**
攻撃の多くは新規の高度な手法ではなく、API認可不備、既知脆弱性の放置、内部システムの不用意な公開という基本の欠陥を突いている。AIツールによって探索が自動化・高速化するため、「見つかりにくい」ことに依存する防御は成立しなくなる。APIのオブジェクト単位認可・クライアント埋め込みキーの扱い（ドメイン8）、データ最小化と保持期間管理による漏えい時の被害縮小（ドメイン2）、自社の外部公開資産を継続的に棚卸しする攻撃面管理と定期的なペネトレーションテスト（ドメイン6）を組み合わせたい。

## 7. 事前予告型: Fortinetの“アドバイザリ前パッチ”（詳細は11/10公開予定）と Next.js / Better Auth の11/3セキュリティリリース

**概要**
Fortinetは2026年10月21日にFortiMail・FortiAuthenticator、10月22日にFortiOS・FortiManager・FortiAnalyzerの修正版を先行公開した。FortiOSは8.0.2 / 7.6.8 / 7.4.13 / 7.2.14、FortiManager/FortiAnalyzerは8.0.2 / 7.6.8 / 7.4.12 / 7.2.13とされる（一部は社会メディア投稿由来の情報）。CVE番号と詳細アドバイザリは**11月10日に公開予定（詳細は未確定・非公開）**で、重大・高の脆弱性を含み、同社の「フロンティアAI支援セキュリティテスト」プログラム（AnthropicやOpenAIとの協業）で見つかった初の成果とされる。watchTowrはパッチ差分解析（patch diffing）で攻撃者が3週間の空白期間にエクスプロイトを開発できると警告しており、同社は公開時点で悪用は未報告としつつ、インターネット公開機器の優先パッチ、管理アクセスの制限、FortiManagerの非公開化、MFAを推奨している。併せて、Next.jsは10/27付で**11月3日（火）**に中程度（medium）の脆弱性7件の修正版を公開予定と事前告知（詳細は当日公開、影響バージョン未確定）、Better Authも10/30付で11月3日に1.7.xと1.8.0-beta.xを対象としたセキュリティリリースを予告している（重大度は未公表）。いずれも「公開予定」であり、内容は推測できない。

**関連CBKドメイン**: ドメイン7（セキュリティ運用／パッチ・変更管理）、ドメイン1（リスクマネジメント）、ドメイン8（ソフトウェア開発セキュリティ）

**コラム**
修正版が出ているのに脆弱性情報が非公開、という状況は、パッチ差分解析のリスクと、情報なしでパッチを当てる運用判断（緊急変更管理）を実務者に迫る。ベンダーの「定期メンテナンスと誤認させない」意図に沿い、通常の月次サイクルではなく緊急変更として境界機器から優先適用するのが合理的である（ドメイン7）。リスクマネジメントの観点では、事前予告日（11/3、11/10）をカレンダー化し、対象製品の棚卸し、検証環境、ロールバック計画を先に整えておくことで、公開直後の悪用競争に備えられる（ドメイン1）。ただしNext.jsは重大度がmediumである点を踏まえ、過剰反応せずリスクベースで優先度を決める。

## 用語解説

- **CBK（Common Body of Knowledge）**: CISSPの出題範囲となる8つのドメインからなる知識体系。
- **RCE（リモートコード実行）**: 攻撃者が遠隔から対象システム上で任意のコードを実行できる脆弱性・状態。
- **CVE / CVSS**: CVEは脆弱性の共通識別番号、CVSSは深刻度を0〜10で表す共通指標。
- **KEV（Known Exploited Vulnerabilities）**: CISAが管理する「実際に悪用が確認された脆弱性」のカタログ。
- **ゼロデイ**: 修正パッチが提供される前、または開発元が認識する前に悪用される脆弱性。
- **エンバーゴ（禁輸）期間**: 脆弱性の詳細を公開前に伏せておく期間。調整された開示の一部。
- **OOM（Out of Memory）**: メモリ不足状態。異常処理の不備が脆弱性につながることがある。
- **mod_php / PHP-FPM / php-cgi / FrankenPHP / LiteSpeed**: PHPをWebサーバ上で動かす各種実行方式・サーバ製品。
- **WAF（Web Application Firewall）**: Webアプリへの攻撃的な通信を検査・遮断する仕組み。
- **PoC（概念実証コード）**: 脆弱性が実際に悪用可能であることを示す実証用コード。
- **SBOM（ソフトウェア部品表）**: ソフトウェアを構成する部品・ライブラリの一覧。影響範囲特定に使う。
- **EOL（サポート終了）**: ベンダーの保守・修正提供が終わった状態の製品・バージョン。
- **PKI / CA（認証局）/ 中間CA / ルートストア**: 電子証明書の信頼を支える仕組み。CAが証明書を発行し、ルートストアが信頼するCAの一覧。
- **キーセレモニー**: CAの秘密鍵を生成・管理するための厳格な手順と立会いを伴う儀式。
- **CRLSet / OneCRL**: ChromeとFirefoxが配信する失効証明書のブロックリスト。
- **CT（証明書透明性）ログ**: 発行された証明書を公開記録し、不正発行を検出可能にする仕組み。
- **サプライチェーン攻撃**: ソフトウェアの開発・配布経路を侵害し、利用者へ悪性コードを届ける攻撃。
- **PyPI / Docker Hub / GHCR**: Pythonパッケージ、およびコンテナイメージの公開レジストリ。
- **CI/CD・SLSA・provenance**: 自動ビルド・配布の仕組みと、その来歴を証明するための枠組み・情報。
- **cosign**: コンテナイメージ等に署名・検証を行うツール。
- **OAuthトークン / IAM**: 権限委譲に使う認可トークン／アイデンティティとアクセス管理。
- **APT / UNC5221 等**: 国家関与が疑われる高度で持続的な攻撃グループ／追跡用の識別名。
- **PRA（Privileged Remote Access）**: 特権アカウントへの遠隔アクセスを管理・制御する製品カテゴリ。
- **ランサムウェア**: データを暗号化し、復旧と引き換えに金銭を要求するマルウェア。
- **IaaS / 責任共有モデル**: 仮想サーバ等を提供するクラウド形態／事業者と利用者の責任分担の考え方。
- **RTO / RPO**: 目標復旧時間／目標復旧時点。事業継続計画で使う指標。
- **NoSQLインジェクション / SQLインジェクション**: 入力値を悪用してデータベース問い合わせを不正操作する攻撃。
- **Webシェル / WARファイル / JSP**: 遠隔操作用のWeb上の不正スクリプト／Javaアプリの配布形式／Javaのサーバサイドページ。
- **WSUS**: Windows更新プログラムを社内に配信するMicrosoftの管理サーバ。
- **BI（ビジネスインテリジェンス）/ Metabase**: データ分析・可視化ツール。Metabaseはその代表的OSS。
- **パッチ差分解析（patch diffing）**: 修正前後のコードを比較して脆弱性を特定し、エクスプロイトを作る手法。
- **SSL-VPN**: SSL/TLSを使う遠隔接続用VPN。境界機器として狙われやすい。
- **MFA**: 多要素認証。知識・所持・生体など複数要素で本人確認を行う。
