## 1. McKesson社、ShinyHunters主張のデータ侵害でヘルスケア患者データ約2.84億件流出の恐れ

**概要:**
米医薬品卸大手McKesson社は2026年8月25日、サードパーティアプリケーションへの不正アクセスとデータ窃取を伴うセキュリティインシデントを検知したとSEC向けForm 8-Kで開示した。恐喝グループShinyHunters（Scattered Spiderとの関連が指摘されるコミュニティ）は、氏名・住所・生年月日・電話番号・社会保障番号（SSN）などの識別情報に加え、患者ID・診療録番号・傷病名・処方薬・担当医情報を含む約2.84億件のレコード（ただしShinyHunters自身は「ユニークな個人数ではなくレコード＝行数」と補足）を窃取したと主張している。攻撃者はヴィッシング（音声フィッシング）でMcKesson従業員2名を騙し、SalesforceおよびSnowflakeのデータ環境から情報を抽出したとされる。ShinyHuntersはMcKessonに対し550万ドル相当（約5,520万ドル）の身代金を要求しているが、McKessonは応じていないと報じられている。調査は初期段階であり、被害範囲の確定には至っていない。

**関連CBKドメイン:** ドメイン1（セキュリティとリスクマネジメント）／ドメイン2（資産のセキュリティ）／ドメイン7（セキュリティ運用）

**コラム:**
本件はSaaS・クラウドデータ基盤（Salesforce、Snowflake）を狙ったソーシャルエンジニアリング型サードパーティリスクの典型例であり、ドメイン1のサードパーティ・サプライチェーンリスク管理、ドメイン2の機密性区分に基づくデータ資産保護と直結する。技術的な脆弱性ではなく人的要素（ヴィッシング）が侵入口となった点は、CISSP実務者に対し、技術統制だけでなくセキュリティ意識向上プログラムとコールセンター/ヘルプデスクの本人確認プロセスの重要性を改めて示している。医療情報（PHI）を含む大規模漏洩は規制上の通知義務（HIPAA等）にも直結し、インシデント対応計画（IRP）の実効性が問われる場面となる。

## 2. Cl0pランサムウェア、PTC Windchill／FlexPLM脆弱性(CVE-2026-12569)を悪用しShell・Philips・GE等40社超を侵害

**概要:**
Cl0p（Clop）ランサムウェア関連の攻撃者集団が、製品ライフサイクル管理（PLM）ソフトウェアPTC WindchillおよびFlexPLMに存在する重大な入力検証不備の脆弱性CVE-2026-12569（デシリアライゼーション起因のRCE）を悪用し、データ窃取型の二重恐喝キャンペーンを展開している。攻撃チェーンは、FlexPLMのWSDLエンドポイントにおける事前認証情報漏洩と、Windchillログインサーブレットのサーバー側欠陥を連結させたもので、未認証のままリモートコード実行が可能となり、`/Windchill/login/`配下に16桁の16進数ファイル名（[0-9a-f]{16}.jsp形式）を持つJSP Webシェルが設置される。PTCは2026年6月17日からパッチ提供を開始し、CISAは6月25日に本脆弱性をKEV（既知の悪用脆弱性）カタログに追加した。しかし8月19日時点でCl0pのリークサイトには、Shell、Philips、General Electric（GE）を含む40社超が被害企業として掲載されており、Shellは自社データ約89GBが窃取されたとの主張について調査中と報じられている。標的業種は製造業、自動車、航空宇宙、小売など多岐にわたる。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン7（セキュリティ運用）／ドメイン8（ソフトウェア開発セキュリティ）

**コラム:**
デシリアライゼーションや事前認証の情報漏洩を連結させる複合的攻撃チェーンは、ドメイン3が扱うセキュアな設計原則（信頼できない入力の検証、安全なデシリアライゼーション）が現場で徹底されていない現実を示す。PTCのパッチ提供からCISAのKEV登録まで約1週間、そこから2か月以上経ってもなお大企業が被害を受けている事実は、ドメイン7のパッチ管理・脆弱性管理プロセスの遅延がいかに深刻な結果を招くかを物語る。CISSP実務者は、インターネットに露出したPLM/ERPなど「見落とされがちな」業務システムの資産棚卸しとKEVカタログの継続的モニタリングを組織のパッチ管理SLAに組み込む必要がある。

## 3. Windows AFDドライバのゼロデイ脆弱性(CVE-2026-68820)、北朝鮮系Lazarusが悪用と判明

**概要:**
2026年8月のMicrosoft Patch Tuesdayで修正されたCVE-2026-68820は、Windows Ancillary Function Driver for WinSock（AFD.sys）に存在するUse-After-Free（解放後使用）の脆弱性で、CVSSスコアは7.0（重要度: Important）。低権限のローカル認証済み攻撃者が特別に細工したアプリケーションを実行し、レースコンディションを制することでSYSTEM権限への昇格が可能になる。攻撃には高度な実行難易度を要するが、ユーザーの操作は不要とされる。影響を受けるのはWindows 10（1607、1809、21H2、22H2）、Windows 11（24H2、26H1）、およびWindows Server各世代（2012〜2025）と広範囲に及ぶ。Check Point Researchの分析により、本脆弱性の悪用が北朝鮮系脅威アクターLazarus Groupによる「Operation Dream Job」キャンペーンの一環として確認されている。Microsoftは8月のPatch Tuesdayで本脆弱性を含む421件の脆弱性（うちCritical 62件、RCE 40件）をまとめて修正した。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン6（セキュリティの評価とテスト）／ドメイン7（セキュリティ運用）

**コラム:**
本件は国家支援型APTグループが公開前のゼロデイ脆弱性を偵察・侵入後の権限昇格に利用する典型例であり、ドメイン3のOSカーネル/ドライバレベルのメモリ安全性設計の重要性を浮き彫りにする。Lazarusの偽求人・偽転職オファーを起点とする「Operation Dream Job」は初期侵入にソーシャルエンジニアリングを用いる点でも示唆に富み、ドメイン7の脅威インテリジェンス活用とエンドポイント検知・対応(EDR)の必要性を裏付ける。CISSP実務者は月例パッチ適用だけでなく、KEV/CISA公表情報や脅威インテリジェンスフィードを参照し、緊急度に応じた優先パッチ適用（リスクベース脆弱性管理）を実践すべきである。

**参照:**
- [CVE-2026-68820 – Windows Ancillary Function Driver for WinSock Elevation of Privilege Vulnerability - Action1](https://www.action1.com/vulnerabilities/cve-2026-68820/)
- [August 2026 Patch Tuesday: Microsoft Fixes 421 CVEs, One Exploited Zero-Day - SecurityWeek](https://www.securityweek.com/august-2026-patch-tuesday-microsoft-fixes-421-cves-one-exploited-zero-day/)

## 4. SharePoint認証バイパス(CVE-2026-55040)とvCenterパストラバーサル(CVE-2026-59310)、PoC公開直後に悪用拡大

**概要:**
Microsoft SharePointの重大な認証不備CVE-2026-55040（CVSS 9.1）は、JWT（JSON Web Token）検証の欠陥を悪用し、未認証の攻撃者が管理者を含む任意のSharePointユーザーになりすませるトークン偽造を可能にする。本脆弱性は2026年7月のPatch Tuesdayで修正されていたが、Rapid7が8月11日に実証コード(PoC)を公開した数時間後には実環境での悪用が確認された。並行して、Broadcom VMware vCenterのパストラバーサル脆弱性CVE-2026-59310（CVSS 9.8）も悪用が拡大し、ネットワークアクセス権を持つ攻撃者による任意コード実行を許す。Broadcomは7月29日に修正版を提供済みだが、QUIRSO Threat Research（脅威分析チーム）は47か国361件の侵害済みIPアドレスを確認しており、ドイツ55件、米国41件、トルコ38件、イラン26件、フランス25件と報告している。CISAは両脆弱性を8月18日にKEVカタログへ追加し、連邦政府機関に対し8月21日までの是正を義務付けた。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン4（通信とネットワークセキュリティ）／ドメイン5（アイデンティティおよびアクセス管理）／ドメイン6（セキュリティの評価とテスト）

**コラム:**
JWT検証不備によるなりすましはドメイン5のトークンベース認証設計における実装検証の甘さを象徴する事例であり、署名検証・有効期限・発行者検証を怠った実装がいかに致命的かを示す。PoC公開から数時間で実悪用に至った事実は、パッチ適用の「猶予期間」がかつてないほど短縮している現状を突きつけ、ドメイン6の継続的脆弱性スキャンとパッチ適用の即応性を組織に求める。vCenterのようなハイパーバイザー管理基盤への侵害は仮想化基盤全体の完全性を脅かすため、ドメイン4のネットワークセグメンテーション（管理ネットワークの分離）が事前防御として不可欠である。

## 5. Giteaのコード実行脆弱性(CVE-2026-60004)、8,300台超が未パッチのままクリプトジャッキング被害に

**概要:**
オープンソースのGitホスティングソフトウェアGiteaに存在するコードインジェクション脆弱性CVE-2026-60004は、Salesforceのセキュリティ研究者Shai Rod氏により報告されたもので、認証済み攻撃者がdiffpatch APIエンドポイント経由で悪意あるパッチを送信することで、Giteaサービスアカウント権限で任意のシェルコマンドを実行できる。悪用にはリポジトリへの書き込み権限が必要だが、Giteaはデフォルトで自己登録（セルフサインアップ）が有効になっているため、未認証の攻撃者でもアカウント登録・リポジトリ作成を経て権限を取得し、脆弱性を突くことが可能となっている。修正版（v1.27.1）は2026年7月27日に公開されたが、8月28日時点でインターネットに露出した8,300台超のGiteaインスタンスが依然未パッチのまま放置されており、攻撃者はこれらのサーバーに暗号資産マイニングマルウェア（クリプトジャッキング）を展開していることが確認されている。CISAは本脆弱性を実悪用ありと分類し、連邦機関に8月28日までの是正を義務付けた。

**関連CBKドメイン:** ドメイン6（セキュリティの評価とテスト）／ドメイン7（セキュリティ運用）／ドメイン8（ソフトウェア開発セキュリティ）

**コラム:**
デフォルト設定（自己登録有効）が意図せぬ攻撃対象領域を拡大させた典型例であり、ドメイン8が重視するセキュアなデフォルト設定（secure by default）の原則が実務でいかに軽視されやすいかを示している。パッチ公開から1か月経過後も8,300台超が未対応という状況は、ドメイン6・7が扱う資産の可視化とパッチ適用プロセスの組織的な欠陥を露呈するものであり、社内開発基盤（Git、CI/CDツール）であっても外部公開資産としての継続的な脆弱性スキャン対象に含めるべきという教訓を与える。

**参照:**
- [Over 8,300 Gitea servers vulnerable to code execution attacks - BleepingComputer](https://www.bleepingcomputer.com/news/security/over-8-300-gitea-servers-vulnerable-to-code-execution-attacks/)
- [Critical Vulnerability advisory GHSA-8qw8-rq86-9pc2 - GitHub](https://github.com/go-gitea/gitea/security/advisories/GHSA-8qw8-rq86-9pc2)

## 6. ニチレイ、ランサムウェア被害で従業員個人情報の漏洩可能性を公表（RansomHouseが関与主張）

**概要:**
冷凍食品大手ニチレイは、2026年7月13日にグループ内システムへのサイバー攻撃を検知し、これに伴い出荷・受注業務の一部が停止する被害が発生した。復旧後の調査により、8月14日、攻撃を受けたサーバーの一部に国内グループの従業員に関する個人情報（氏名、生年月日、会社メールアドレス、従業員番号、人事・労務関連情報）が保管されており、これらが漏洩した可能性があると正式に発表した。恐喝グループ「RansomHouse」を名乗る集団は8月10日、窃取したと主張するデータ（20万件超のファイル）をダークウェブ上で公開しており、その中には従業員や取引先の電話番号等の個人情報が含まれるとされる。ただし、ニチレイ自身はRansomHouseの関与、ランサムウェアによる暗号化の有無、公開データの真正性、漏洩対象者の人数・範囲について現時点で確定情報を示しておらず、単一情報源（RansomHouse側の主張）に基づく部分が含まれる点に留意が必要である。

**関連CBKドメイン:** ドメイン1（セキュリティとリスクマネジメント）／ドメイン2（資産のセキュリティ）／ドメイン7（セキュリティ運用）

**コラム:**
基幹業務システムへの侵害が出荷・受注という事業継続に直結した点は、ドメイン1のBCP/DRP（事業継続・災害復旧計画）とサプライチェーン全体へのリスク波及を考える好例である。「業務は復旧しても漏洩した情報は取り戻せない」という構図は、ドメイン2のデータ資産分類とバックアップ・暗号化統制の重要性を再認識させる。攻撃者の主張のみが先行し企業側の確認が追いついていない状況は、ドメイン7のインシデント対応におけるフォレンジック調査の困難さと、対外広報のタイミング・正確性のバランスという実務上の課題を示している。

**参照:**

## 7. さくらインターネット、レンタルサーバーで不正アクセス　583アカウントに不正ログイン・マルウェア設置も判明

**概要:**
さくらインターネット株式会社は2026年8月9日、「さくらのレンタルサーバ」サービスにおいてサーバー環境の異常を検知し調査を開始、8月17日に公式発表を行った。調査の結果、第三者が同社の管理環境を経由して利用者環境に不正アクセスを行い、583アカウントへの不正ログインが確認された。一部のサーバーには攻撃者によりマルウェアが設置されており、サーバー領域内に保存された利用者データや利用者識別子など、電気通信事業法上の「通信の秘密」に該当する情報へアクセス可能な状態だったことも確認されている。現時点で顧客環境の改ざん等の被害報告は確認されていないが、個人情報漏洩の可能性が残るとして、対象利用者への個別対応が進められている。検知（8月9日）から公表（8月17日）まで約1週間を要しており、原因となった管理環境への侵入経路の詳細は継続調査中とされる。

**関連CBKドメイン:** ドメイン5（アイデンティティおよびアクセス管理）／ドメイン7（セキュリティ運用）／ドメイン4（通信とネットワークセキュリティ）

**コラム:**
「管理環境を経由した」不正アクセスという構図は、多数の顧客テナントを抱えるホスティング事業者において、管理者権限を持つ内部管理システムが侵害された場合の影響範囲の大きさを示しており、ドメイン5の特権アカウント管理（PAM）とゼロトラストの重要性を強く裏付ける。電気通信事業法上「通信の秘密」への抵触が疑われる点は、日本国内特有の法規制（ドメイン1のコンプライアンス要素）とも関連し、国内CISSP実務者にとって示唆が大きい。検知から公表までのタイムラインは、ドメイン7のインシデント対応における初動調査と適時開示のバランスを考える実例となる。

**参照:**

## 8. Medusaランサムウェア、被害500件超に　CISA・FBI・HHSが医療分野への注意喚起を更新

**概要:**
CISA、FBI、米保健福祉省（HHS）は2026年8月18日、Medusaランサムウェアに関する共同サイバーセキュリティ勧告を更新した。同勧告は元々2025年3月12日に初版が公表されたもので、今回のアップデートでは2026年4月までのFBI捜査結果を反映し、被害組織数が500件を突破したことが明らかにされた（2025年2月時点では約300件と報告されていた）。Medusaはランサムウェア・アズ・ア・サービス（RaaS）モデルで運営され、データを窃取・暗号化した上で身代金を支払わなければ情報を公開すると脅す二重恐喝(ダブルエクストーション)を常套手段とする。標的業種は医療・公衆衛生、教育、法律サービス、保険、技術、製造業など多岐にわたり、今回HHSが共同署名機関として初めて加わったことは、病院・医療システムが「頻繁に狙われる標的」として特に強調されたことを意味する。

## 用語解説

- **CVE（Common Vulnerabilities and Exposures）**: 個々の脆弱性に一意の識別番号を付与する国際的な採番制度。「CVE-2026-XXXXX」のように年と通番で表記され、脆弱性情報の共有・追跡を容易にする。
- **CVSS（Common Vulnerability Scoring System）**: 脆弱性の深刻度を0.0〜10.0の数値で表す業界標準の評価指標。攻撃条件や影響範囲などから算出され、対応優先度の判断材料となる。
- **ゼロデイ脆弱性**: ベンダーが修正パッチを提供する前（あるいは脆弱性の存在を認識する前）に悪用される脆弱性のこと。防御側が対策を講じる猶予がゼロであることからこう呼ばれる。
- **Use-After-Free（UAF、解放後使用）**: メモリ上で既に解放（free）された領域を誤って参照・使用してしまうプログラムの欠陥。攻撃者に悪用されるとコード実行や権限昇格につながる典型的な脆弱性クラス。
- **RCE（Remote Code Execution、リモートコード実行）**: ネットワーク経由で攻撃者が対象システム上で任意のコードを実行できてしまう脆弱性・攻撃手法。深刻度が最も高い脆弱性区分の一つ。
- **デシリアライゼーション（逆直列化）の脆弱性**: シリアライズされた（直列化された）データを復元する処理に不備があり、悪意あるデータを渡すことで意図しないコード実行を許してしまう脆弱性。
- **JWT（JSON Web Token）**: ユーザー認証やAPI連携で広く使われるトークン形式。署名検証や有効期限確認などの実装に不備があると、なりすましやトークン偽造の被害を招く。
- **パストラバーサル（ディレクトリトラバーサル）**: ファイルパスの指定を細工することで、本来アクセスが許可されていないディレクトリ・ファイルへ不正にアクセスする攻撃手法。
- **RaaS（Ransomware as a Service）**: ランサムウェアの開発者が攻撃ツールをアフィリエイト（実行犯）に貸与し、身代金の一部を分配するビジネスモデル。攻撃の分業化・スケール化を促進している。
- **二重恐喝（ダブルエクストーション）**: データを暗号化するだけでなく、事前に窃取したデータを「支払わなければ公開する」と脅す、ランサムウェア攻撃者の典型的な戦術。
- **KEV（Known Exploited Vulnerabilities）カタログ**: 米CISAが実際に悪用が確認された脆弱性をまとめて公開するリスト。連邦機関には収載された脆弱性への対応期限が課される。
- **Patch Tuesday**: Microsoftが毎月第2火曜日（米国時間）に定例のセキュリティ更新プログラムを一斉公開する慣行。多くのベンダーがこれに合わせてパッチをリリースする。
- **ヴィッシング（Voice Phishing）**: 電話や音声通話を用いて相手を騙し、認証情報や機密情報を聞き出す、あるいは不正操作をさせるソーシャルエンジニアリング手法。
- **Webシェル**: 侵害したWebサーバーに設置される、遠隔操作を可能にする不正なスクリプトファイル。攻撃者はこれを足がかりに永続的なアクセスや追加の攻撃を行う。
- **クリプトジャッキング**: 侵害したシステムのCPU・GPUリソースを不正に利用し、攻撃者のために暗号資産（仮想通貨）をマイニングさせる攻撃。
- **PoC（Proof of Concept、概念実証コード）**: 脆弱性が実際に悪用可能であることを示すために作成されたサンプルコード・実証コード。公開されると悪用リスクが急速に高まる。
- **通信の秘密**: 日本の電気通信事業法で保護される、通信の内容や当事者情報等の秘匿に関する法的概念。通信事業者による不適切な取り扱いや漏洩は法令違反となり得る。
