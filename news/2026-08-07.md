## 1. JetBrains TeamCityの未認証RCE脆弱性がCISA KEVに追加、悪用が進行中

**概要:** JetBrains TeamCity（オンプレミス版）に存在する重大な脆弱性CVE-2026-63077（CVSSスコア9.8）について、米CISAが実際の悪用を確認し、既知の悪用済み脆弱性（KEV）カタログに追加した。本脆弱性はTeamCityのエージェントポーリングプロトコルにおける信頼できないデータのデシリアライゼーション（CWE-502）に起因し、未認証の攻撃者がネットワーク経由でTeamCityサーバーにアクセスできれば、認証をバイパスしてTeamCityサーバープロセスの権限で任意のOSコマンドを実行できる。影響を受けるのはTeamCity On-Premisesの2025.11.7未満および2026.1.3未満の全バージョンで、JetBrainsは2026年7月にパッチをリリース済みである。CISAは2026年8月5日にKEVへ追加し、連邦政府機関に対して2026年8月8日という異例の短い修正期限を設定した。悪用の詳細な手口や攻撃者の身元、被害規模は現時点では公表されていないが、認証情報の窃取、サーバー設定の改ざん、ビルド成果物への不正コード混入によるソフトウェアサプライチェーン汚染につながるリスクが指摘されている。

**関連CBKドメイン:** ドメイン8（ソフトウェア開発セキュリティ）／ドメイン3（セキュリティアーキテクチャとエンジニアリング）

**コラム:** TeamCityはCI/CDパイプラインの中核を担うビルドサーバーであり、ここが侵害されるとビルド成果物への不正コード混入という形でソフトウェアサプライチェーン全体に影響が波及する。これはまさにドメイン8が扱うSDLCセキュリティの核心的リスクであり、開発基盤自体を「保護すべき資産」として扱う視点が欠かせない。またデシリアライゼーションの脆弱性は設計段階での入力検証・信頼境界の設計ミスに起因することが多く、セキュアアーキテクチャの原則（最小権限、攻撃対象領域の最小化）を再確認する好例である。CISSP実務者は、開発ツールチェーンについても本番システムと同等のパッチ管理・資産管理の優先度で扱うべきという教訓が得られる。

**参照:** [The Hacker News](https://thehackernews.com/2026/08/cisa-flags-teamcity-cve-2026-63077-rce.html) / [JetBrainsブログ](https://blog.jetbrains.com/teamcity/2026/07/cve-2026-63077/) / [Rapid7](https://www.rapid7.com/blog/post/etr-cve-2026-63077-critical-unauthenticated-remote-code-execution-in-jetbrains-teamcity/)

## 2. IBM Langflow（AIエージェント基盤）の未認証RCE脆弱性、CISAが緊急パッチを要請

**概要:** オープンソースのAIエージェント構築プラットフォームIBM Langflowに、CVSSスコア9.8の重大なコードインジェクション脆弱性CVE-2026-9198が発見され、CISAが2026年8月4日にKEVカタログへ追加、連邦機関に対し8月7日までの修正を求めた。本脆弱性は2つの問題を連鎖させたもので、まず未認証のエンドポイント`/api/v1/auto_login`を悪用してスーパーユーザー権限のベアラートークンを不正取得し、次にそのトークンを使って`/api/v1/validate/code`エンドポイントに攻撃者が用意したPythonコードを送信、`exec()`関数により任意コードを実行させる手口である。影響を受けるのはLangflow OSSバージョン1.0.0から1.10.0までで、IBMは1.10.1へのアップグレードを推奨しており、回避策（ワークアラウンド）は提供されていない。公開から約1週間後には概念実証（PoC）コードも公開されており、悪用のハードルはさらに下がっている。具体的な被害件数や攻撃グループ名は現時点で公表されていないが、デフォルト設定のまま公開されたLangflowインスタンスが標的になりやすいとされる。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン5（アイデンティティおよびアクセス管理）

**コラム:** 本件は「認証なしでも動く便利機能」を安易に実装した結果、認証バイパスとコード実行が一直線に繋がってしまった典型例であり、IAM設計における最小権限・デフォルト拒否の原則の重要性を浮き彫りにする。生成AI・AIエージェント基盤は急速に普及しているが、セキュリティレビューが追いついていないケースが多く、CISSP実務者は新規導入するAI関連ツールについても既存の脆弱性管理プロセス・セキュアバイデザイン原則を例外なく適用する必要がある。特に「自動ログイン」のような開発利便性のための機能は、本番環境では無効化・制限する運用ルールの徹底が求められる。

**参照:** [The Hacker News](https://thehackernews.com/2026/08/cisa-flags-langflow-rce-tomcat-and-n.html) / [SecurityWeek](https://www.securityweek.com/cisa-warns-of-exploited-langflow-n-central-and-tomcat-vulnerabilities/) / [securityvulnerability.io](https://securityvulnerability.io/vulnerability/CVE-2026-9198)

## 3. ランサムウェア「Ransom Cartel」創設者に禁錮16年の実刑判決

**概要:** 米バージニア州東部地区連邦裁判所は2026年8月5日、ランサムウェア・アズ・ア・サービス（RaaS）「Ransom Cartel」を2021年に立ち上げ運営していたベラルーシ国籍のMaksim Silnikau被告（40歳）に禁錮16年の判決を言い渡した。同被告は米国に対する共謀罪、電信詐欺共謀罪、加重身分窃盗罪で有罪判決を受けている。Ransom Cartelは2021年から2023年にかけて、米国カリフォルニア州・ニューヨーク州・ネブラスカ州の企業を含む少なくとも18社を標的にし、盗んだ認証情報や暗号化ツールを参加者に提供するRaaSモデルで運営されていた。被告は2005年頃からロシア語圏のサイバー犯罪フォーラムで活動し、「J.P. Morgan」「lansky」等の複数のエイリアスを使用、2011〜2016年には著名なサイバー犯罪サイト「Direct Connection」のメンバーでもあった。ポーランドから米国に身柄が引き渡され、今回の判決に至った。裁判記録には、攻撃を制御し被害者と交渉し身代金を分配するための隠しパネルの存在も記されている。

**関連CBKドメイン:** ドメイン1（セキュリティとリスクマネジメント）／ドメイン7（セキュリティ運用）

**コラム:** 本件はRaaSという「犯罪のサービス化」ビジネスモデルの実態と、それに対する法執行機関の国際連携（ポーランドからの身柄引き渡し等）による摘発事例として、ドメイン1が扱う法規制・サイバー犯罪の理解に直結する。CISSP試験では法的措置や国際協力の枠組みが出題対象となるが、実務上も「攻撃者は摘発され得る」という抑止効果と、それでもなお新たなRaaSグループが台頭し続ける現実の両方を踏まえたリスク評価が求められる。組織としては、たとえ運営者が摘発されても類似の攻撃基盤・手口が別グループに引き継がれる可能性を前提に、インシデント対応計画を継続的に見直すべきである。

## 4. アフラック生命保険、不正アクセスにより約440万人分の個人情報が漏洩

**概要:** アフラック生命保険は2026年6月30日、「アフラック よりそうネット」等の自社システムに対する第三者からの不正アクセスにより、顧客の個人情報を含む情報が漏洩したと公表した。当初発表では約438万人分の顧客情報が流出し、うち約23万人分は保険料振替のための銀行口座情報も含まれるとされたが、7月13日の第二報では対象件数が顧客約440万人、うち口座情報を含む顧客約22万人に更新された。漏洩した情報には氏名・住所・電話番号・銀行口座情報のほか、代理店約4万店の住所・代表者氏名などの情報も含まれる。時系列としては、2026年6月25日にシステムの高負荷を検知したことが調査の端緒となり、その後の調査で不正アクセスの発生自体は6月10日に遡ることが判明した（当初は6月15日発生と発表されていたが後日修正）。アフラックは金融庁への報告を行い、調査結果と再発防止策を提出している。攻撃者・攻撃グループ名は本稿執筆時点で公表されていない。

**関連CBKドメイン:** ドメイン2（資産のセキュリティ）／ドメイン7（セキュリティ運用）

**コラム:** 本件は日本国内の大手保険会社における大規模漏洩事例として、個人情報という「資産」の分類・保護（ドメイン2）と、異常検知から報告までのインシデント対応プロセス（ドメイン7）の両面で学びが多い。特に「システムの高負荷検知」が調査の発端になった点は、平時からのログ監視・異常検知（SIEM等）体制の重要性を示している。また不正アクセスの発生日が当初発表から後日修正された点は、フォレンジック調査には時間を要し初期発表が変更されうることを踏まえ、危機管理広報や規制当局への段階的報告プロセスをあらかじめ設計しておく必要性を示唆する。金融業界における顧客口座情報の漏洩は、なりすまし詐欺等の二次被害にも直結するため、影響範囲の特定と顧客通知の迅速性が特に重要である。

**参照:** [アフラック公式発表(6/30)](https://www.aflac.co.jp/static/corp/profile/news/2026/20260630.pdf) / [アフラック公式発表(7/13第二報)](https://www.aflac.co.jp/static/corp/profile/news/2026/20260713.pdf) / [日本経済新聞](https://www.nikkei.com/article/DGXZQOUB3046P0Q6A630C2000000/)

## 5. VMware vCenter Serverに認証バイパス・RCEの重大脆弱性2件、パッチ公開

**概要:** Broadcomは2026年7月29日、セキュリティアドバイザリVMSA-2026-0006を公開し、VMware vCenter Serverに影響する2件の重大な脆弱性、CVE-2026-59309（認証バイパス、CVSS 9.8）とCVE-2026-59310（ディレクトリトラバーサル、CVSS 9.8）を修正した。CVE-2026-59309はVMware Directory Serviceに起因し、ネットワークアクセス可能な攻撃者が認証を完全にバイパスして管理プレーンへの不正アクセスを獲得し、仮想インフラ・データ・接続先ワークロードを完全に掌握できる可能性がある。CVE-2026-59310はvCenterのSyslogサーバーにおけるディレクトリトラバーサルの脆弱性で、任意コード実行につながりうる。いずれも未認証での悪用が可能であり、回避策は存在しないためベンダー提供のアップデート適用が唯一の対策となる。修正版はVMware Cloud Foundation/vSphere Foundation 9.1.0.0300、同9.0.2.0100、およびvCenter Server 8.0 U3kで提供されている。Broadcomは本稿執筆時点で実際の悪用や探索活動の証拠は確認されていないとしているが、CVSS9.8かつ未認証攻撃という条件は極めて悪用されやすい部類に入る。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン4（通信とネットワークセキュリティ）

**コラム:** vCenterは仮想化基盤全体の管理プレーンであり、ここへの侵害は個々のサーバーではなくデータセンター全体の可用性・機密性・完全性を左右する「王冠の宝石」的資産である。管理インターフェースをネットワークセグメンテーションで隔離し、インターネットから直接到達不能にすることは、ドメイン4が扱うネットワークアーキテクチャの基本原則そのものである。悪用実績が未確認の段階でも、CVSS9.8・未認証・ワークアラウンドなしという条件が揃った脆弱性は「悪用は時間の問題」と捉え、パッチ適用を待たずに管理インターフェースへのアクセス制御を見直すことが望ましい。仮想化基盤の脆弱性管理は影響範囲が広いため、変更管理プロセスとの整合を取りながら迅速に対応する体制整備が重要となる。

**参照:** [Rapid7](https://www.rapid7.com/blog/post/etr-critical-vmware-vcenter-vulnerabilities-allow-authentication-bypass-and-remote-code-execution-cve-2026-59309-cve-2026-59310/) / [The Hacker News](https://thehackernews.com/2026/07/three-critical-vmware-flaws-allow-auth.html) / [CSO Online](https://www.csoonline.com/article/4203947/broadcom-patches-vulnerabilities-all-over-vmware.html)

## 6. オープンソースAIエージェント基盤「Ruflo」、MCPブリッジの重大脆弱性「RufRoot」（CVSS 10.0）

**概要:** オープンソースのAIエージェントプラットフォームRufloに、CVSSスコア満点10.0の重大な脆弱性CVE-2026-59726（通称「RufRoot」）が発見された。RufloのMCP（Model Context Protocol）ブリッジは、ツール呼び出しを処理するExpress.jsサーバーであり、シェルコマンド実行・データベース操作・エージェント管理・メモリ保存など233個のツールをHTTP経由で認証なしのまま外部に公開していた。攻撃者はポート3001宛に単一の未認証HTTP POSTリクエストを送るだけで、コンテナ内で任意コードを実行でき、LLMのAPIキー窃取、ユーザー会話の閲覧、AIエージェントの乗っ取り、永続化されたAIメモリの改ざんまで可能になる。本脆弱性は2026年6月30日に責任ある開示（レスポンシブル・ディスクロージャー）の手順で報告され、プロジェクトのメンテナーであるReuven Cohen氏が24時間以内に修正を配布、バージョン3.16.3でMCPブリッジに認証を必須化する形で対応した。影響を受けるのは3.16.3より前の全バージョンで、悪用による具体的な被害件数は本稿執筆時点で報告されていない。

**関連CBKドメイン:** ドメイン5（アイデンティティおよびアクセス管理）／ドメイン8（ソフトウェア開発セキュリティ）

**コラム:** 本件は「デフォルトで認証なしのAPIを大量に外部公開する」という、IAMの基本原則を無視した設計ミスがCVSS満点という最悪の結果を招いた事例であり、AIエージェント基盤特有の新たなリスク（モデル・メモリ・APIキーの窃取、エージェントの乗っ取り）を象徴している。SDLCにおいてMCPのような新しいプロトコル・アーキテクチャを採用する際も、「デフォルトで安全（secure by default）」の原則を適用し、認証・認可を後付けではなく設計段階から組み込む必要性を強く示す事例である。一方でメンテナーが開示から24時間で修正版を配布した対応の速さは、オープンソースプロジェクトにおける脆弱性開示プロセスの模範例としても参考になる。CISSP実務者は、組織内でAIエージェント関連ツールを採用する際、公開ポート・デフォルト設定・認証要件を必ず個別に検証すべきである。

**参照:** [The Hacker News](https://thehackernews.com/2026/07/ruflo-mcp-flaw-lets-unauthenticated.html) / [Noma Security](https://noma.security/blog/rufroot-the-mcp-bridge-vulnerability-that-turns-agents-into-rogue-admins-cve-2026-59726/) / [CSO Online](https://www.csoonline.com/article/4203408/critical-ruflo-flaw-lets-attackers-hijack-ai-agents-through-exposed-mcp-bridge.html)

## 7. Hyundai トルコ法人、ランサムウェア集団「CRPx0」による侵害を主張される

**概要:** ランサムウェア集団「CRPx0」は、Hyundai自動車のトルコ法人から採用候補者の評価データを含む約1.5GBのデータを窃取したとダークウェブ上の恐喝用ポータルで主張した。窃取されたとされるデータには、候補者の面接回答・評価スコア・採用トラッキング記録に加え、監視付きオンライン試験時の写真・動画、経営層候補者向けの心理検査・性格分析を含む評価レポート、採用・人事評価に関する社内メールのやり取りなどが含まれるとされる。同グループのポータル上のリスティングでは対象地域をトルコ・イスタンブールとし、公開から本稿執筆時点で3,143件以上の閲覧数を記録、身代金交渉用にToxIDおよびセッションIDが提示され、全データ公開までのカウントダウンタイマーが設置されていた。CRPx0は同時期にA101、ASELSAN、Anadolu Sigorta、Doğan Holding、Turkish Airlines、Anadolubank、QNB Türkiye、Kuveyt Turkなど、トルコを拠点とする複数の大手企業を標的リストに追加しており、トルコ企業を狙った集中的なキャンペーンを展開しているとみられる。侵害の初期侵入経路や検知日、Hyundai側の公式コメントは本稿執筆時点で確認されていない。

**関連CBKドメイン:** ドメイン7（セキュリティ運用）／ドメイン1（セキュリティとリスクマネジメント）

**コラム:** 本件は人事・採用データという、企業が見落としがちなが機微性の高い情報資産（候補者の心理検査結果や評価データ等）がランサムウェア恐喝の材料にされた点で、資産分類の見直しを迫る事例である。単一の攻撃グループが短期間に同一国・同一業界の複数企業を連続して標的にする手口は、業界横断的な脅威インテリジェンス共有の重要性（ドメイン1のリスクマネジメント文脈）を裏付けている。ダブルエクストーション型（データ窃取＋暗号化＋公開威嚇）の恐喝手口が定着している現状を踏まえ、セキュリティ運用（ドメイン7）としてはバックアップだけでなく、データ流出そのものを防ぐDLPや、採用管理システムのような周辺業務システムへのアクセス制御強化も検討課題となる。なお本件は攻撃側の主張に基づく情報であり、被害の事実関係についてはHyundai側の公式発表など複数情報源での裏付けが取れていない点に留意されたい。

## 用語解説

- **CVE（Common Vulnerabilities and Exposures）**: 公開されているソフトウェア・ハードウェアの脆弱性に一意の識別番号を付与する国際的な仕組み。「CVE-年-連番」の形式で表記される。
- **CVSS（Common Vulnerability Scoring System）**: 脆弱性の深刻度を0〜10の数値で表す業界標準の評価指標。9.0以上は「Critical（緊急）」に分類されることが多い。
- **CISA KEV（Known Exploited Vulnerabilities）カタログ**: 米国土安全保障省傘下のCISAが管理する、実際に悪用が確認された脆弱性の一覧。米連邦政府機関には掲載された脆弱性への対応期限が課される。
- **RCE（Remote Code Execution／リモートコード実行）**: 攻撃者がネットワーク経由で対象システム上に任意のプログラム・コマンドを実行させられる脆弱性の種類。深刻度が最も高い部類に分類される。
- **未認証脆弱性（Unauthenticated Vulnerability）**: ログインや認証情報なしに、外部の攻撃者が悪用できる脆弱性。認証済みでしか使えない脆弱性より一般に危険度が高い。
- **デシリアライゼーション（Deserialization）の脆弱性**: シリアル化（直列化）されたデータをプログラムが復元する際、信頼できないデータを検証せず処理してしまうことで、意図しないコード実行を許してしまう脆弱性の一種（CWE-502）。
- **CWE（Common Weakness Enumeration）**: ソフトウェアの脆弱性の「原因となる欠陥の種類」を分類する共通の枠組み。CVEが個別の脆弱性を指すのに対し、CWEはその脆弱性のパターン・カテゴリを指す。
- **認証バイパス（Authentication Bypass）**: 本来必要な本人確認の手続きを経ずに、システムやサービスへの正当なアクセス権を得てしまう攻撃・脆弱性。
- **ディレクトリトラバーサル（Directory Traversal）**: 「../」等の相対パス指定を悪用し、本来アクセスが許可されていないディレクトリ・ファイルに不正にアクセスする攻撃手法。
- **ランサムウェア（Ransomware）**: システムやファイルを暗号化する、あるいはデータを窃取して公開すると脅す等の手段で、被害者に金銭（身代金）を要求するマルウェアの一種。
- **RaaS（Ransomware-as-a-Service）**: ランサムウェアの開発者が攻撃ツールや基盤を第三者（アフィリエイト）に提供し、身代金の分け前を得るビジネスモデル。攻撃の実行主体と開発主体が分離するのが特徴。
- **ダブルエクストーション（二重恐喝）**: ランサムウェア攻撃において、データの暗号化に加えてデータを窃取し、身代金を支払わなければ公開すると脅す手口。
- **AIエージェント（AI Agent）**: 大規模言語モデル（LLM）を用いて、外部ツールの呼び出しや複数ステップのタスクを自律的に実行するソフトウェアの総称。
- **MCP（Model Context Protocol）**: AIモデルが外部のツールやデータソースと連携するための標準化されたプロトコル。近年急速に普及しているが、新しい技術ゆえにセキュリティ対策が追いついていないケースが多い。
- **不正アクセス（Unauthorized Access）**: 正当な権限を持たない者がシステムやネットワークに侵入する行為。日本の不正アクセス禁止法における法的用語でもある。
- **フォレンジック調査（Digital Forensics）**: サイバーインシデント発生後に、侵入経路・被害範囲・証拠を技術的に解析する調査活動。裁判や規制当局への報告の根拠ともなる。
- **DLP（Data Loss Prevention／データ漏洩防止）**: 機密情報が組織外部に不正に流出することを検知・防止するための技術・運用の総称。
- **SIEM（Security Information and Event Management）**: ログやイベントデータを一元的に収集・相関分析し、セキュリティ上の異常を検知するためのシステム・仕組み。
- **サプライチェーンリスク（Supply Chain Risk）**: 自組織だけでなく、取引先・委託先・利用しているソフトウェア／サービスの提供元を経由してセキュリティ被害が及ぶリスク。CI/CDパイプラインの侵害はその典型例。
- **セキュアバイデザイン（Secure by Design）**: システムやソフトウェアの設計段階からセキュリティ対策を組み込む考え方。後付けの対策よりも根本的にリスクを低減できるとされる。
