## 1. Windowsカーネルドライバのゼロデイ脆弱性（CVE-2026-68820）を北朝鮮系Lazarusが悪用

**概要:** Microsoftは2026年8月のPatch Tuesday（8月11日）において、Windowsの Ancillary Function Driver for WinSock（afd.sys）に存在するUse-After-Free（解放済みメモリ使用）の脆弱性CVE-2026-68820を修正した。この脆弱性はCVSSv3スコア7.0（重要）と評価されているが、実際に悪用が確認されているゼロデイである点が重大視されている。攻撃者はローカルで低権限のアカウントから特別に細工したアプリケーションを実行し、レースコンディションを引き起こすことでSYSTEM権限への昇格が可能になる。セキュリティ企業Check Pointの調査（単一情報源であり今後の追加検証が待たれる）によれば、本脆弱性は北朝鮮系とされる脅威アクターLazarusによって悪用され、同グループのカーネルモード・ルートキット「FudModule」の新バージョンを展開するために使われたとされる。Microsoftは全体で398〜421件（情報源により件数の記載に差異あり）のCVEを本パッチで修正しており、うち3件がゼロデイとして悪用確認済みとされる。パッチは8月11日付で提供されている。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン7（セキュリティ運用）

**コラム:** カーネルドライバの脆弱性はOSの最も深い層で権限昇格を許すため、境界防御だけでなくエンドポイントでの異常検知や特権アクセス管理が問われる典型例である。国家関与とされる攻撃グループがゼロデイを実運用で使うケースは、パッチ適用の即応性（Patch Tuesday後の迅速な展開）とEDR/カーネル保護機構の両輪が不可欠であることを再確認させる。CISSP実務者としては、脆弱性情報の「単一情報源」段階での帰属判断には慎重さを保ちつつ、CVSSスコアの数値だけでなく実際の悪用有無（Exploited in the wild）を優先してパッチ適用の優先順位付け（リスクベースパッチマネジメント）を行う姿勢が求められる。

## 2. Clop、金融サービス大手FIS Globalから874GBのデータを窃取したと主張

**概要:** ランサムウェア／データ恐喝グループClop（Cl0p）が2026年8月5日、金融サービス大手FIS Global（fisglobal.com）への侵害を公表し、Projects、CADファイル、Windchill関連データ、ソフトウェア資産などを含む874GBのデータを窃取したと主張した。報道によれば本件はCVE-2026-12569という脆弱性の悪用に関連しているとされるが、詳細な技術的悪用経路については情報源が限定的であり、単一情報源の域を出ない点に留意が必要である。Clopは過去に多重恐喝（データ窃取＋暴露脅迫、場合により暗号化を伴わない純粋なデータ恐喝）の手法で世界的に5億ドル以上の身代金を得てきたとされる著名なサイバー犯罪組織であり、MOVEitやGoAnywhere等のファイル転送ソフトのゼロデイ悪用を通じた大規模サプライチェーン型攻撃でも知られる。FIS Globalは銀行・証券会社向けの決済処理・コアバンキングシステムを提供しており、侵害が確認された場合は金融セクター全体への波及リスクが懸念される。

**関連CBKドメイン:** ドメイン1（セキュリティとリスクマネジメント）／ドメイン7（セキュリティ運用）

**コラム:** Clopは単一企業ではなく、サードパーティ製ソフトウェアの脆弱性を突いてサプライチェーン全体に影響を及ぼす手口を得意とする。金融サービスの基幹システムベンダーが標的となった場合、影響は同社の直接の顧客企業だけでなく、その先の一般利用者にまで及ぶ可能性がある。CISSP実務者にとっては、サードパーティ／サプライヤーリスク管理（TPRM）と、契約上のセキュリティ要件（SLA、通知義務、監査権）の整備がドメイン1のリスクマネジメントの核心であることを改めて示す事例である。

## 3. Everestランサムウェア集団、日本のネットワーク機器大手Allied Telesisへの侵害を主張

**概要:** ランサムウェア／データ恐喝グループEverestは2026年8月5日、東京に本社を置く世界的ネットワーク機器メーカーAllied Telesisへの攻撃を公表し、機密データの暴露をちらつかせて交渉を迫っていると報じられた。Allied Telesisはスイッチ、ルーター、無線アクセスポイント、ネットワーク管理ソフトウェアを企業・政府・医療・教育機関向けに40カ国以上で展開する大手ベンダーである。Everestは2020年12月頃から活動する恐喝グループで、当初は強力な暗号化を用いた典型的なランサムウェア攻撃を行っていたが、近年は暗号化を伴わない「データ窃取＋暴露脅迫」型の純粋恐喝へと手口をシフトしている。政府、医療、製造、IT サービスなど幅広いセクターを標的とし、北米・欧州・アジアに被害が確認されている。本件についても、データ窃取の規模や具体的な侵入経路（悪用された脆弱性やアクセス手法）は現時点で公式発表がなく、報道は攻撃者側のリークサイトでの主張に基づく単一情報源段階であることに留意が必要である。

**関連CBKドメイン:** ドメイン1（セキュリティとリスクマネジメント）／ドメイン7（セキュリティ運用）

**コラム:** ネットワーク機器ベンダー自体が侵害された場合、同社の製品を利用する下流の企業・組織にも波及するサプライチェーンリスクとなり得る。日本企業が国際的なランサムウェア集団の標的になっている点は、国内組織にとっても対岸の火事ではないことを示す。CISSP実務者は、インシデント対応計画（IRP）における「攻撃者側リークサイトでの主張」段階での初動対応手順（事実確認、法務・広報連携、取引先への通知要否判断）をあらかじめ明文化しておくことが望まれる。

## 4. スイス連邦IT庁（FOITT）、SharePoint脆弱性悪用によりアカウント約200件が侵害

**概要:** スイス連邦情報技術通信局（FOITT）は、オンプレミス版Microsoft SharePointサーバーに対する不正アクセスにより、ユーザーアカウントおよびテクニカルアカウント約200件が侵害されたと公表した。異常の検知は2026年7月28日、侵害の確認は同月31日とされる。攻撃にはMicrosoftが2026年7月中旬に報告した脆弱性が悪用されたとみられ、報道ではCVSSスコアが高いCVE-2026-50522（リモートコード実行、CVSSv3.1で9.8のクリティカル）が関連付けられている。同脆弱性はSharePoint Server Subscription Edition、SharePoint Server 2019、2016 Enterpriseに影響し、信頼できないデータのデシリアライゼーション（逆シリアル化）に起因する。認証なし・ユーザー操作なしで悪用可能であり、Microsoftは2026年7月14日のPatch Tuesdayで修正パッチを提供、CISAは同年7月22日にKEV（悪用が確認された脆弱性）カタログへ追加している。攻撃者はSharePointがトークンの署名・検証に使う暗号鍵（IISマシンキー）を窃取するため、パッチ適用だけでは窃取済み鍵によるアクセス持続を防げない点が専門家から指摘されている。FOITTは影響を受けたパスワードのリセット、外部からのSharePointアクセス遮断、サーバーの完全再構築などの対応を実施し、国家サイバーセキュリティセンター（NCSC）およびMicrosoftの支援を受けて調査中。現時点でこれ以上のデータ漏えいの証拠は確認されていないが、機密情報や特に機微な個人情報は当該SharePoint基盤に保存されない運用だったとされる。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン4（通信とネットワークセキュリティ）／ドメイン7（セキュリティ運用）

**コラム:** 本件は、パッチ適用のタイミングと実際の侵害検知タイミングのギャップ（パッチ公開が7月14日、異常検知が7月28日）が示すように、既知の脆弱性が公開されてから悪用されるまでのウィンドウが極めて短いことを物語る。加えて、暗号鍵窃取を伴う攻撃はパッチ適用だけでは根本対処にならず、鍵のローテーションや持続的侵害の痕跡調査（フォレンジック）が不可欠であるという教訓を含む。CISSP的には、脆弱性管理（ドメイン7）とセキュアな鍵管理・暗号アーキテクチャ（ドメイン3）が連動して初めてインシデントの再発を防げることを示す好例である。

## 6. Cisco Secure Endpoint、ClamAVエンジンの複数脆弱性でDoS攻撃のリスク（PoC公開済み）

**概要:** Ciscoは2026年8月7日付（8月10日更新）のセキュリティアドバイザリ（cisco-sa-clamav-WuuvVd26）で、オープンソースのマルウェア対策エンジンClamAVに存在する複数の高深刻度脆弱性がSecure Endpoint Connector（Windows／Linux／macOS）に影響すると発表した。脆弱性はCVE-2026-20337〜20339およびCVE-2026-20345〜20348として採番され、ZIP、GPT、PESpin、PDF、Mach-O、XARといった各種ファイル形式のパーサーに存在するメモリ破壊・境界外読み取りの問題である。特にCVE-2026-20346とCVE-2026-20347はそれぞれPDFおよびMach-Oファイル処理時の境界外バッファ読み取り、CVE-2026-20348はXARアーカイブ処理における不適切な境界チェックに起因する。認証不要の遠隔攻撃者が細工したファイルをスキャン対象に送り込むことで、ClamAVのスキャンプロセスをクラッシュさせるサービス拒否（DoS）状態を引き起こし得る。Windows版Secure Endpoint Connectorの影響度は「高（High）」、Linux・macOS版は「中（Medium）」と評価されている。ClamAV 1.5.0〜1.5.3が影響を受け、うち一部の脆弱性は1.5.4（8月7日リリース）で修正済みだが、CVE-2026-20337とCVE-2026-20338には現時点で回避策がなく、Ciscoは8月内にSecure Endpoint Connector向けの修正版を別途提供予定としている。CVE-2026-20337とCVE-2026-20338についてはPoC（概念実証コード）がすでに公開されているが、実際の悪用は確認されていない。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン6（セキュリティの評価とテスト）

**コラム:** セキュリティ対策製品自体（EDR／アンチウイルスエンジン）が攻撃対象になるという「守る側のツールが弱点になる」典型例であり、防御レイヤーの多重化（Defense in Depth）の重要性を示す。PoCが公開済みで悪用のハードルが下がっている状況では、CVSSの深刻度評価だけでなく「悪用の容易さ」「公開情報の有無」を加味したパッチ優先順位付けがドメイン6（脆弱性診断・評価プロセス）の実務として求められる。DoSはデータ漏えいを伴わなくても、マルウェア検知機能の停止という形で組織のセキュリティ体制そのものを弱体化させ得る点にも注意したい。

## 7. Windows Deployment Services TFTPサーバーにCVSS 9.8の未認証RCE脆弱性（CVE-2026-62893）

**概要:** 2026年8月のPatch TuesdayでMicrosoftが修正したCVE-2026-62893は、Windows Deployment Services（WDS）のTFTP（Trivial File Transfer Protocol）サーバーコンポーネントに存在するリモートコード実行脆弱性で、CVSSv3スコア9.8（クリティカル）と評価されている。原因は、オブジェクトに対する操作を行う前にその存在を検証していないことにあり、認証もユーザー操作も不要な遠隔の攻撃者が細工したパケットをTFTPサービス（UDPポート69）へ送信するだけで任意コード実行が成立し得る。TFTPプロトコル自体に認証機構がないため、PXEブート（ネットワーク経由のOS展開）用にWIM（Windows Imaging Format）ファイルを配信しているWDSサーバーは標的になりやすい。Microsoftはこの脆弱性を「悪用の可能性が高い（Exploitation More Likely）」と評価しており、ZDI（Zero Day Initiative）プログラム経由でTrendAI ResearchのNikolai Skliarenko氏から報告された。組織のネットワーク境界でUDPポート69をブロックすることが推奨される一方、内部ネットワークに侵入済みの攻撃者による水平移動（ラテラルムーブメント）の手段として悪用される懸念も指摘されている。

**関連CBKドメイン:** ドメイン3（セキュリティアーキテクチャとエンジニアリング）／ドメイン4（通信とネットワークセキュリティ）

**コラム:** WDSは企業内でOSの大量展開に使われる管理系サービスであり、境界防御の内側に置かれることが多いため、外部公開されていなくても油断はできない。認証機構を持たない古典的プロトコル（TFTP）を内包する管理サービスは、ネットワークセグメンテーションと最小権限の原則（ドメイン4）を徹底しなければ、一度の侵入が全社的なイメージ配布基盤の乗っ取りにつながりかねない。CISSP実務者は、CVSSスコアの高さだけでなく「攻撃面がどこに露出しているか」（インターネット公開かイントラネット限定か）を踏まえたリスク評価を行うべきである。

## 用語解説

- **CVE（Common Vulnerabilities and Exposures）**: 公開された個々の脆弱性に一意の番号を付与し、世界共通で識別できるようにする仕組み。「CVE-2026-XXXXX」の形式で表記される。
- **CVSS（Common Vulnerability Scoring System）**: 脆弱性の深刻度を0〜10の数値で表す業界標準の指標。数値が高いほど悪用の容易さや影響が大きいことを示す。
- **ゼロデイ（Zero-day）**: 開発者が脆弱性を把握し修正パッチを提供する前に、攻撃者がその脆弱性を悪用すること。パッチが存在しないため防御が特に難しい。
- **Use-After-Free（解放済みメモリ使用）**: 一度解放（無効化）したメモリ領域を誤って引き続き参照・操作してしまうプログラムの欠陥。攻撃者に悪用されると任意コード実行や権限昇格につながることがある。
- **特権昇格（Privilege Escalation）**: 攻撃者が本来許可されていない高い権限（例: 一般ユーザーからSYSTEM/管理者権限）を不正に取得すること。
- **ランサムウェア（Ransomware）**: ファイルを暗号化する、またはデータを窃取した上で、復旧や非公開と引き換えに金銭を要求するマルウェア・攻撃手法。
- **二重恐喝（Double Extortion）**: データを暗号化するだけでなく、事前に窃取したデータの公開をちらつかせて金銭を要求する、ランサムウェア攻撃者の典型的な手口。
- **RCE（Remote Code Execution／リモートコード実行）**: 攻撃者がネットワーク越しに標的システム上で任意のコードを実行できてしまう脆弱性の種類。深刻度が非常に高いことが多い。
- **デシリアライゼーション（逆シリアル化）の脆弱性**: プログラムがシリアル化（保存・転送用にデータ構造を変換）されたデータを復元する際、信頼できないデータを検証せずに処理してしまうことで、任意コード実行などにつながる脆弱性クラス。
- **TFTP（Trivial File Transfer Protocol）**: 認証機構を持たないシンプルなファイル転送プロトコル。UDPポート69を使用し、主にネットワークブート（PXE）用途で使われる。
- **PXEブート**: ネットワーク経由でOSイメージを配信し、ハードディスクではなくネットワーク越しに端末を起動する仕組み。企業のPC大量展開などで利用される。
- **DoS（Denial of Service／サービス拒否）**: システムやサービスを過負荷・異常終了させることで、正規利用者が利用できない状態に追い込む攻撃。
- **PoC（Proof of Concept／概念実証コード）**: 脆弱性が実際に悪用可能であることを示すために作成された実証用コード。公開されると悪用のハードルが下がる。
- **CISA KEVカタログ（Known Exploited Vulnerabilities Catalog）**: 米国CISA（サイバーセキュリティ・インフラセキュリティ庁）が、実際に悪用が確認された脆弱性を一覧化した公式リスト。掲載された脆弱性は優先的なパッチ適用が強く推奨される。
- **EDR（Endpoint Detection and Response）**: エンドポイント（PCやサーバーなど）上での不審な挙動を検知し、調査・対応を支援するセキュリティ製品カテゴリ。Cisco Secure Endpointなどが該当する。
- **ルートキット（Rootkit）**: システムに深く潜伏し、自身の存在やマルウェアの活動を隠蔽する目的で使われる悪意あるソフトウェア。カーネルモードで動作するものは検知・除去が特に困難。
- **ダークウェブ（Dark Web）**: 通常の検索エンジンやブラウザではアクセスできない、匿名性の高いネットワーク上のウェブ空間。ランサムウェア集団が窃取データの暴露やリークサイトの運営に利用することが多い。
