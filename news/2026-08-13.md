## 1. Windows AFD.sysのゼロデイ脆弱性（CVE-2026-68820）をLazarusグループが悪用、偵察・防衛産業を標的に

**概要**: Microsoftは2026年8月11日（August Patch Tuesday）に、Windows Ancillary Function Driver for WinSock（AFD.sys）に存在するUse-After-Free型の脆弱性CVE-2026-68820を含む計398件のCVEを修正した。CVSS基本値は7.0とされているが、今回のPatch Tuesdayで「悪用が確認された」唯一のゼロデイである点が重要である。攻撃者はローカルで低権限を持つ状態から、細工したアプリケーションを実行してレースコンディションを引き起こすことでSYSTEM権限への昇格を達成できる。セキュリティ研究者は本脆弱性の悪用を北朝鮮系とされるLazarusグループに帰属させており、偽の採用担当者を装ったスピアフィッシングメールで悪意あるPDFまたはトロイの木馬化されたPDFビューアーを開かせ、新型バックドア「Troy」を展開したうえで本脆弱性によりSYSTEM権限を取得し、FudModuleルートキットを展開する手口が確認されている。標的は欧州・インドを含む複数国の防衛・航空宇宙・航空関連セクターとされる。Microsoftは同日付で正式パッチを公開済みであり、該当システムでは速やかな適用が推奨される。

**関連CBKドメイン**: ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン6（セキュリティの評価とテスト）、ドメイン7（セキュリティ運用）

**コラム**: OSカーネル/ドライバレベルの権限昇格脆弱性は、初期侵入後の「横展開・権限奪取」フェーズにおける典型的な足がかりとなるため、パッチ管理（ドメイン7）とセキュアな脆弱性評価プロセス（ドメイン6）の両輪が問われる事例である。加えて、国家支援型攻撃グループが採用詐欺のようなソーシャルエンジニアリングを侵入起点に用いている点は、技術的統制だけでなく人的要因への継続的な教育（ドメイン1のセキュリティ意識向上プログラム）の重要性を再確認させる。CISSP実務者は、ゼロデイ公表後のパッチ適用までの「露出期間」をいかに短縮するかという運用上の課題として本件を捉えるべきである。

## 2. AIエージェントによる脆弱性研究から発見されたSharePoint認証バイパス（CVE-2026-55040）と非認証RCEチェーン

**概要**: CVE-2026-55040は、Microsoft SharePoint ServerのJWTトークン検証パイプラインに存在する認証バイパスの脆弱性で、CVSSスコアは9.1（一部報道では9.8）とされ、SharePoint Server Subscription Edition、SharePoint Server 2019、SharePoint Server 2016が影響を受ける。攻撃者は対象ユーザーのActive Directoryセキュリティ識別子（SID）またはユーザープリンシパル名（UPN）さえ把握していれば、資格情報なしに管理者を含む任意ユーザーになりすますことが可能となる。本脆弱性で特筆すべきは発見プロセスで、セキュリティ企業Rapid7が実施した研究では、96セッション・24日間にわたりAIエージェントに256のプロンプトを与え、約8万回のエージェント型ツール呼び出しを実行させる「AI支援型脆弱性研究」を実施し、本バイパスと別のリモートコード実行（RCE）欠陥を連結させることで、資格情報なしにサーバー上で任意コードを実行できる攻撃チェーンを構築した。Microsoftは2026年7月のPatch Tuesdayで本脆弱性を修正済みであり、修正プログラムはKB5002882として提供されている。8月に入り、この攻撃チェーンの詳細と実際の悪用事例が公開され、注目を集めた。

**関連CBKドメイン**: ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン5（アイデンティティおよびアクセス管理）、ドメイン6（セキュリティの評価とテスト）

**コラム**: JWTトークン検証の実装不備が認証バイパスに直結する点は、IAM実装における「信頼境界の検証漏れ」の典型例であり、ドメイン5の観点で設計・実装レビューの重要性を示す。さらに本件は、攻撃側・防御側双方でAIエージェントによる脆弱性研究が実用段階に入ったことを示す象徴的事例であり、セキュリティテスト（ドメイン6）の手法そのものが今後大きく変化していく可能性を示唆する。CISSP実務者は、AIによる自動化された脆弱性発見のスピードに、自組織のパッチ適用サイクルが追いついているかを再点検する契機とすべきである。

## 5. Azure SRE Agentに権限昇格の重大脆弱性（CVE-2026-62830、CVSS 9.9）

**関連CBKドメイン**: ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン5（アイデンティティおよびアクセス管理）

**コラム**: クラウドサービスプロバイダーが提供する運用自動化エージェント自体が攻撃対象になり得るという点は、クラウド環境における「共有責任モデル」の中でも特にプロバイダー側の実装品質への信頼が前提となる領域のリスクを示している。認可制御の欠落は典型的なアクセス制御設計の不備であり、最小権限の原則（Least Privilege）がエージェントやサービスアカウントにも一貫して適用されているかを検証する重要性を再認識させる。CISSP実務者は、自組織が利用するクラウドネイティブな運用ツール群についても、通常のIAM統制と同水準の評価・監査対象とすべきである。

## 8. IT企業シーイーシー、データセンターサービス障害の原因がランサムウェア攻撃と確認、個人情報保護委員会へ報告

**概要**: 株式会社シーイーシーは、2026年8月5日午前11時頃に東京第二データセンターで発生した不正アクセス事案について、当初はサービス障害として公表していたが、調査の結果8月7日にランサムウェアによる攻撃であったことを確認したと発表した。同社は本件について警察へ通報するとともに、個人情報漏洩の可能性について個人情報保護委員会へ報告を行った。現時点までの調査では情報漏洩の事実は確認されておらず、また攻撃を受けた領域は顧客から預かっているシステムやデータとは別系統であったことが判明しているとされる。データセンター事業者という性質上、影響が自社にとどまらず委託元企業のサービス継続性にも波及するリスクをはらんでいたが、現時点では顧客システムへの直接的な影響は確認されていない。

**関連CBKドメイン**: ドメイン7（セキュリティ運用）、ドメイン2（資産のセキュリティ）

**コラム**: データセンター事業者は多数の委託元企業の資産を預かる立場にあり、自社インフラと顧客システムとのネットワーク・システム的な分離（セグメンテーション）が機能していたかどうかが被害拡大を防ぐ分水嶺となる。本件は結果的に顧客系システムへの影響が確認されていない点で「分離設計が奏功した可能性がある」事例として参考になるが、公式な原因調査報告（侵入経路、悪用された脆弱性等）は本稿執筆時点で十分に公開されておらず、単一情報源に基づく速報段階の情報である点に留意が必要である。個人情報保護委員会への報告は、日本の個人情報保護法に基づく漏洩等報告義務（ドメイン1の法規制対応）の実務例としても参考になる。

## 用語解説

- **CVE（Common Vulnerabilities and Exposures）**: 世界共通で脆弱性を識別するための番号体系。「CVE-2026-XXXXX」のように年と通し番号で表され、脆弱性情報の共有・管理を容易にする。
- **CVSS（Common Vulnerability Scoring System）**: 脆弱性の深刻度を0.0〜10.0のスコアで表す業界標準の評価基準。攻撃の難易度や影響範囲などから算出され、パッチ適用の優先順位付けに用いられる。
- **ゼロデイ（Zero-Day）**: ベンダーが修正パッチを提供する前に、脆弱性が発見・悪用されている状態、またはその脆弱性自体を指す。防御側の対応猶予が実質ゼロであることから名付けられた。
- **Use-After-Free（解放後使用）**: 一度解放（free）されたメモリ領域を、解放されたことを認識しないまま再度使用してしまうプログラムの不具合。攻撃者に悪用されるとコード実行や権限昇格につながることがある。
- **権限昇格（Privilege Escalation）**: 攻撃者が本来持つべきでない高い権限（例: 一般ユーザーからSYSTEM/管理者）を不正に取得する攻撃手法。侵入後の横展開・被害拡大の重要なステップとなる。
- **RCE（Remote Code Execution／リモートコード実行）**: 攻撃者がネットワーク越しに標的システム上で任意のコードを実行できる脆弱性・攻撃手法。深刻度が非常に高い脆弱性区分の一つ。
- **認証バイパス（Authentication Bypass）**: 本来必要な認証プロセスを経ずにシステムやサービスへのアクセスを許してしまう脆弱性。JWTなどのトークン検証実装の不備が原因となることが多い。
- **JWT（JSON Web Token）**: ユーザー認証やセッション管理に広く用いられる、JSON形式の情報を電子署名付きでやり取りするためのトークン規格。検証ロジックの不備が認証バイパスの原因になることがある。
- **二重恐喝（Double Extortion）**: ランサムウェア攻撃において、データを暗号化するだけでなく事前に窃取したデータを公開すると脅すことで身代金支払いの圧力を強める手口。近年は暗号化を伴わない「データ恐喝のみ」の手口も増えている。
- **OT（Operational Technology／運用技術）**: 工場やプラント、発電所などの物理的な機器・プロセスを制御するための技術・システムの総称。IT環境とは異なるセキュリティ上の考慮点（可用性最優先、レガシー機器の多さ等）を持つ。
- **ICS（Industrial Control System／産業用制御システム）**: 製造業やインフラ事業者などで用いられる、PLCやSCADAを含む産業プロセス制御システムの総称。OTの中核をなす。
- **PLC（Programmable Logic Controller）**: 工場やプラントの機械・設備を自動制御するための産業用コンピュータ。ICS/OT環境における主要な制御機器の一つ。
- **APN（Access Point Name）**: 携帯電話網を通じてインターネットや専用ネットワークに接続する際の接続先を識別する設定情報。企業が専用契約する「プライベートAPN」は閉域網として扱われることが多い。
- **サプライチェーンリスク（Supply Chain Risk）**: 自社が直接管理しない取引先・委託先・ソフトウェア供給元等を経由して生じるセキュリティリスク。近年のランサムウェア攻撃の主要な侵入経路の一つとなっている。
- **IAM（Identity and Access Management／アイデンティティおよびアクセス管理）**: 利用者やシステムの識別・認証・認可を一元的に管理する仕組み・体系。CISSP CBKドメイン5の中核テーマ。
- **最小権限の原則（Principle of Least Privilege）**: ユーザーやシステム・サービスアカウントに対し、業務遂行に必要な最小限の権限のみを付与すべきとするセキュリティ設計上の基本原則。
- **DLP（Data Loss Prevention／データ漏洩防止）**: 組織内の機密データが不正に外部へ流出することを検知・防止するための技術・運用の総称。
- **インシデントレスポンス（Incident Response）**: セキュリティインシデント発生時の検知・封じ込め・根絶・復旧・事後対応を体系的に行うプロセス。CISSP CBKドメイン7の主要テーマの一つ。
