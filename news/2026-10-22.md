## 1. 【続報】PHP「PHP2Shell」緊急セキュリティリリース公開、各研究者が技術詳細とWordPress/Drupal/Joomlaへの実証RCEを公表

**概要**
2026-10-20にPHPセキュリティチームが事前告知した緊急セキュリティリリースが、予告（10/21 14:00 UTC）より前倒しされ、10/21の米東部時間午前9時30分頃（Huntress報告）に PHP 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 として公開された。修正対象は、いずれもCVSS v4.0で9.2の2件である。CVE-2026-109618は、リクエスト設定中のメモリ不足（OOM）により半初期化データが残り、クリーンアップ処理がそれを有効とみなすことでコード実行に至る。CVE-2026-109619は、リクエスト固有の状態が解放後も残り、同一ワーカー上の後続リクエストが参照して use-after-free、メモリ開示、Webワーカー権限でのRCEに至る。PHP側は mod_php のデフォルト設定で認証不要のHTTP経由RCEを検証済みとし、PHP-FPM、php-cgi、FrankenPHP、LiteSpeedも影響を受けるとしている（完全な緩和策はなく更新が唯一の完全対処）。10/21午後にはCalifが追加RCE経路を、WizがWordPress・Drupal・Joomlaに対する認証不要RCEの実証を公表した。Sansecは「PHP 5.4以降のWebサーバーが影響」と記載するが、正確な影響範囲は公式には確認されていない。悪用状況は情報が割れており、Huntressは10/21 16:30 ET時点でパートナー環境での野生の悪用を未観測と報告する一方、PHPは悪用コードの存在を示している。暫定緩和は `memory_limit=-1`（php_admin_valueで固定）、`post_max_size=8M`、`session.upload_progress.enabled=0`（PHP 8.5では `fatal_error_backtraces=0` も）で、いずれも php.ini／プール設定で行い、全ワーカー再起動が必要。PHP 7.4/8.0/8.1は公式サポート外で最小限のバックポートのみ。PHP 8.2は2026-12-31にEOL。

**関連CBKドメイン**: ドメイン7（セキュリティ運用）／ドメイン8（ソフトウェア開発セキュリティ）／ドメイン6（評価とテスト）

**コラム**
実行基盤そのものの欠陥は、アプリ側のコード品質では防げないため、資産棚卸し（CMS、コントロールパネル、ベンダー製品に同梱されたPHPを含む）とパッチ管理の成熟度が直接問われる（ドメイン7）。事前告知から修正版公開、PoC級の技術公開までが約1日で進んだ点は、「公開＝攻撃開始」とみなす脆弱性対応SLAの設計が必要であることを示す。暫定緩和策は「完全ではない」とPHP自身が明言しており、補完的統制（WAFでのmultipart/form-data制限、VPN背後への退避、PHPワーカーが子プロセスとしてシェルを起動する挙動の検知）を多層で組むのが実務的である（ドメイン6・8）。EOL版PHPを抱える組織は、延命ではなく移行計画を経営レベルのリスク受容事項として扱うべきである。

## 2. GitHub Actionsワークフロー注入キャンペーン「GhostAction」再燃、数万リポジトリでCI/CDシークレットを窃取

**概要**
2025年9月に初報があったGhostActionの新たな波が2026年10月に開示された。Socketによれば、10/7以降に500超のGitHubアカウントが悪性ワークフローを数万のリポジトリにコミットした。StepSecurityは、著名メンテナ2アカウント（pyxel: 27リポジトリ、henrywoo: 318リポジトリ）が計340超に反映したと報告し、GitGuardianは8/31〜9/30に373ユーザー／組織の公開772リポジトリで確認した（Kasetaのまとめでは3,000ユーザー／組織・3万超とされるが二次情報）。手口は、漏えい済みPAT（インフォスティーラーのログ等が有力）で正規アカウントとしてログインし、既存ワークフローから参照されるシークレットを偵察、「セキュリティ監査」を装った `security-audit.yml` / `github_actions_security.yml` をデフォルトブランチへpushする。ワークフローは `workflow_dispatch` と無条件pushで起動し、`fetch-depth: 0` で履歴全体をチェックアウトして13種類の認証情報パターンを走査、AWSキーIDとシークレットを対にして平文HTTPで 193.32.204[.]199 へcurl送信する。狙いはAWS、Anthropic/OpenAI/OpenRouter等のAIプロバイダ、GitHub、GitLabの認証情報。現時点で窃取した公開用認証情報による悪性パッケージ公開は未確認だが、StepSecurityは「悪用未観測は安全を意味しない」と注意している。GitGuardianが見つけたkuafuai/DevOpsGPTのXMRigマイナーは同一アカウント経由だがGhostActionとの関連は未確認。

**関連CBKドメイン**: ドメイン8（ソフトウェア開発セキュリティ）／ドメイン5（IAM）／ドメイン7（セキュリティ運用）

**コラム**
侵入の起点は「正規の開発者認証情報」であり、コードの脆弱性ではない。長寿命のPATを使い続ける運用や、CI/CDを高権限のシークレット保管庫として扱う設計が弱点になる（ドメイン5・8）。実務では、細粒度の短寿命トークン、OIDCによるクラウド連携（静的キー廃止）、ワークフロー変更へのブランチ保護とCODEOWNERSレビュー、Actionsの権限最小化を標準とすべきである。検知面では、IoC（上記ファイル名、外部エンドポイント）に加え、8/31以降のワークフロー追加履歴とフォークの継承を点検対象に含める。侵害が疑われる場合はコミット履歴内の過去の秘密情報も含めた全面ローテーションが前提となる（ドメイン7）。

## 3. 【続報】ConnectWise Cloud Backup供給網攻撃: バックアップアプリのサービスプリンシパルを悪用しM365テナントへ侵入（Huntressは162テナント超を確認）

**概要**
ConnectWise Cloud Backup（旧SkyKick）のEntra ID上のアプリ識別情報（サービスプリンシパル）が悪用された。攻撃者はアプリのシークレットを使って直接アプリとして認証するスクリプトを実行したため、ユーザーのログインがなくMFAが適用されなかった。同アプリに事前付与された広範な権限（メール、OneDrive、SharePoint、Teams、Microsoftは Directory.ReadWrite.All の悪用を示唆）により、テナント内の情報にアクセスされた。時系列は、10/13〜14に最初のスクリプト型サインイン試行（Huntress）、10/15にIP 144.172.64.128 からの不審活動（Microsoft/Huntress/Todyl）、10/16に管理者の報告とHuntressの侵害確認、10/17 05:01 UTCにConnectWiseがサービス停止を告知し7つのアプリ識別情報を無効化、10/18時点でバックアップ停止とアーカイブ不可が継続。Huntressは自社監視下で162以上の侵害テナント、約50テナントでのディレクトリロール変更を確認した。一部テナントでは Cloud Management のサービスプリンシパルが自ら Exchange Administrator（1テナントでは Global Administrator）を付与し、MSPツール等の認証情報を追加していた。全体の被害数は不明、攻撃者も未特定、ベンダー認証情報の取得経路は未開示。ConnectWiseは保存済みバックアップの侵害の証拠はないとするが追加調査中としている。

**関連CBKドメイン**: ドメイン5（IAM）／ドメイン1（セキュリティとリスクマネジメント）／ドメイン7（セキュリティ運用）

**コラム**
非人間ID（アプリ／サービスプリンシパル）はMFAの対象外になりやすく、一度過剰な権限を同意すると事実上の特権アカウントとして残る（ドメイン5）。サードパーティ連携アプリの権限棚卸し、シークレット／証明書の追加監視、条件付きアクセスのワークロードID対応は、サプライヤー管理（ドメイン1）の実装手段でもある。無効化しても発行済みトークンは期限まで有効で、ユーザーセッション失効ではアプリ経由のアクセスは止まらない点は、インシデント対応手順に明記すべき教訓である（ドメイン7）。確認すべき指標はアプリID 506e08f9-6e9a-4da4-942b-a099a03644ae のサインインと、10/13以降に追加された認証情報である。

## 4. 【国内】リクルート「カーセンサー」等に不正アクセス、最大約371万件の個人情報が漏えいの可能性

**概要**
リクルートは、10/17に関連システムへの不審なアクセスを検知し、同日夕方（17時頃）に関連サービスを全面停止したと公表した（10/21報道）。漏えいの可能性があるのは最大3,709,551件で、内訳はカーセンサーnet問い合わせ者約321万件（大半は氏名・住所で約318万件、問い合わせ内容・年齢・性別が約3.3万件、電話番号／メールアドレスが799件、番地まで含む可能性が最大約44.8万件）、クチコミ投稿者5,289件、販売店向け「C-MATCH」登録事業者約48.3万件（代表者氏名・電話番号・古物商許可番号・ログインID、個人事業主は事業所住所や銀行口座情報の可能性）、従業員・委託先等10,673件。クレジットカード情報とログインパスワードは含まれないとしている。原因と影響範囲は調査中で、個人情報保護委員会へ報告済み。10/21時点で二次被害は未確認。侵入経路や攻撃者は未公表（ITmedia NEWSの単一情報源）。

**関連CBKドメイン**: ドメイン2（資産のセキュリティ）／ドメイン1（セキュリティとリスクマネジメント）／ドメイン7（セキュリティ運用）

**コラム**
氏名・住所の組み合わせは、カード番号を含まなくてもフィッシングや不審電話の素材として価値が高く、「機微性が低い」との判断は危うい（ドメイン2）。事業者向けデータ（古物商許可番号、口座情報の可能性）は、取引先なりすましや請求詐欺に直結しうる。検知から全面停止までの意思決定が同日中に行われた点は、事前に定義された停止基準とインシデント指揮系統が機能した例として評価できる（ドメイン7）。個人情報保護法に基づく委員会報告・本人通知を見据え、データ保持期間の最小化と、問い合わせ履歴を長期保存する設計の見直しが実務上の論点となる（ドメイン1）。

## 5. 【国内】大阪大学の7万7,851人分の個人情報、NEC委託業務のクラウドストレージから漏えい（未報告の協力会社が関与）

**概要**
大阪大学は10/21、重複を除く計77,851人（卒業生59,014人、在学生15,035人、教職員3,802人）の個人情報が漏えいしたと公表した。時系列は、9/26に第三者が個人情報を含むファイルをダウンロード、10/9にNECが大学へ報告、10/20にNECが委託先に関するサイバー攻撃事案を公表（複数顧客に関わる）、10/21に大学が公表。漏えいした情報は氏名、大学個人ID、大学発行メールアドレス、学籍番号／職員番号、所属情報（対象者により異なる）。流出元は大学システムではなく、NECが委託業務で使っていたクラウドストレージであり、NECが契約に基づかず協力会社との共有のために個人情報入りファイルを保管していたこと、大学に未報告の協力会社が業務の一部に関与していたこと、業務終了後に削除すべきファイルが残っていたことが原因とされる。現時点で不正利用や二次被害は未確認。以上はセキュリティ対策Labの単一情報源に基づく。

**関連CBKドメイン**: ドメイン1（セキュリティとリスクマネジメント）／ドメイン2（資産のセキュリティ）

**コラム**
技術的な突破ではなく、委託・再委託の統制不備とデータライフサイクル管理の失敗が根本原因である。契約外のクラウド保管、未承認の再委託先、業務終了後のデータ残存はいずれも、サプライチェーン・リスク管理（ドメイン1）とデータの保持・廃棄（ドメイン2）の基本統制の欠落を示す。委託元は、再委託の事前承認、データ取扱場所の限定、業務終了時の削除証跡の取得、委託先の定期監査を契約と運用の両面で実装する必要がある。報告遅延（9/26から10/9まで）に備え、委託先に対する報告期限（SLA）の設計も重要である。

## 用語解説

- **CVE**: 脆弱性に付与される共通の識別番号。製品や情報源をまたいで同じ脆弱性を指すために使う。
- **CVSS**: 脆弱性の深刻度を0〜10で示す共通評価方式。9.0以上は一般に「緊急（Critical）」とされる。
- **RCE（リモートコード実行）**: 外部の攻撃者が対象システム上で任意のコードを実行できる脆弱性。
- **OOM（メモリ不足）**: プログラムが使えるメモリを使い切った状態。処理中に起きると想定外の挙動を招くことがある。
- **use-after-free**: 解放済みのメモリを後から参照してしまう不具合。メモリ破壊やコード実行につながりうる。
- **mod_php / PHP-FPM / php-cgi / FrankenPHP / LiteSpeed**: PHPをWebサーバー上で動かす各種の方式・実行環境。
- **EOL（サポート終了）**: ベンダーが更新や修正の提供を終了すること。脆弱性が修正されなくなる。
- **WAF**: Webアプリケーションへの不正な通信を検査・遮断するファイアウォール。
- **KEV**: CISAが管理する「悪用が確認された脆弱性」のカタログ。連邦機関に修正期限が課される。
- **ゼロデイ**: 修正版が存在しない、または公表前に悪用される脆弱性。
- **サプライチェーン攻撃**: 取引先、ソフトウェア、サービス提供元を経由して最終的な標的を攻撃する手法。
- **GitHub Actions / ワークフロー**: GitHub上でビルドやテストを自動実行する仕組みと、その手順を記述したファイル。
- **CI/CD**: ソフトウェアの統合・配布を自動化する開発手法とその基盤。
- **PAT（Personal Access Token）**: GitHub等でパスワードの代わりに使う個人用アクセストークン。漏えいすると本人になりすませる。
- **インフォスティーラー**: 端末から認証情報やブラウザの保存情報を盗むマルウェア。
- **OIDC**: 認証連携の標準規格。CIから静的なクラウドキーなしで一時的な権限を得るのに使える。
- **IoC（侵害指標）**: 攻撃の痕跡を示すファイル名、IPアドレスなどの手がかり。
- **XMRig**: Monero（仮想通貨）を採掘するマイナー型ソフトウェア。攻撃者が不正に設置することがある。
- **Entra ID**: Microsoftのクラウド型IDおよびアクセス管理サービス（旧Azure AD）。
- **サービスプリンシパル**: アプリケーションがEntra ID上で持つ識別情報。人のログインなしで認証でき、MFAが適用されにくい。
- **MFA**: 複数の要素（知識・所持・生体）で本人確認する認証方式。
- **MSP**: 顧客企業のIT運用を請け負うマネージドサービスプロバイダ。
- **OAuthグラント / Directory.ReadWrite.All**: アプリに付与する権限の同意と、ディレクトリ全体を読み書きできる強い権限。
- **Global Administrator / Exchange Administrator**: Microsoft 365の最上位管理者ロールとメール基盤の管理者ロール。
- **SFTP**: SSHを用いた暗号化ファイル転送プロトコル。
- **Section 504**: 米国で障害のある生徒への配慮を定める連邦法の規定。
- **個人情報保護委員会**: 日本の個人情報保護法を所管する行政機関。漏えい時の報告先となる。
- **古物商許可番号**: 中古品販売業者に付与される許可番号。事業者のなりすましに悪用されうる。
- **フィッシング**: 偽のメールやサイトで認証情報や個人情報を詐取する手口。
- **Mark of the Web（MotW）**: インターネットから入手したファイルに付く印。Windowsが警告表示などの保護を行う根拠になる。
- **再委託**: 委託先がさらに第三者へ業務を委託すること。管理が及びにくくなる。
