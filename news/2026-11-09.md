## 1. DigiCert、サーバ移行ミスで社内業務システムが露出 — 顧客の身分証明書類を含む「アーカイブデータ」が閲覧された

**概要**: 認証局（CA）大手の DigiCert は、2025年2月のサーバ移行時に、従来 VPN 内限定だった社内業務システムが誤ってインターネットから到達可能になっていたと公表した（BleepingComputer、2026-11-05付）。当該システムにはセルフ登録機能があり、外部者が作成したアカウントに認可（authorization）上の欠陥があったため、読み取り専用ながらアーカイブされた顧客データを閲覧できた。時系列は、2026年6月に不正アカウントを発見→当初は「アカウント作成の問題」として扱い、外部のマネージドセキュリティ研究者の報告を受けて修正を展開したが、アーカイブデータへのアクセス可能性は当時認識されなかった→10月19日の調査で、2026-06-27〜07-02 に1つの不正アカウントが顧客データへアクセスしたことを確認、というもの。流出対象は氏名・業務用メール・電話番号・住所で、一部は運転免許証・パスポート・公共料金明細などの身分証明書類を含む。影響人数は未公表。DigiCert によれば CA サービス、CertCentral、DigiCert ONE、顧客のログイン資格情報、発行済み証明書は影響を受けておらず、当該アカウントは読み取り専用で証明書発行や検証承認はできなかったとされる。CVE・攻撃グループの情報はなし（単一情報源＋同社説明）。

**関連CBKドメイン**: ドメイン3（セキュリティアーキテクチャとエンジニアリング）、ドメイン2（資産のセキュリティ）、ドメイン5（IAM）、ドメイン7（セキュリティ運用）

**コラム**: 移行・移設作業で「VPN内限定」という暗黙の境界が外れる典型的な構成変更リスクで、変更管理（ドメイン7）と移行後のアタックサーフェス再評価（ドメイン3）の欠落を示す。セルフ登録＋認可不備という組み合わせは、認証と認可を分けて検証する重要性（ドメイン5）を物語る。さらに、アーカイブデータの保持期間・最小化（ドメイン2）が不十分だったため古いデータが被害対象になった。インシデント対応では、初動で「アカウント作成問題」と分類し、データアクセスの可能性を見逃した点が教訓で、根本原因分析の深さが被害範囲の把握を左右する。

**参照**: [BleepingComputer: DigiCert data breach exposes customer information, identity documents](https://bleepingcomputer.com/news/security/digicert-data-breach-exposes-customer-information-identity-documents) / [The Record: DigiCert reports data breach](https://therecord.media/digicert-certificate-authority-reports-data-breach)

## 2. Apache OFBiz 24.09.08 が46件の脆弱性を修正 — ログインページ経由の未認証RCE（CVE-2026-83542, CVSS 9.8）を含む

**概要**: ERP/EC基盤の Apache OFBiz がバージョン 24.09.08 をリリースし、46件の脆弱性を修正した（Daily Security Review 2026-11-06付、Security NEXT も同日報道）。24.09.08 より前の全バージョンが影響を受ける。主な項目は、ログインページのウィジェットインジェクションによる未認証RCE（CVE-2026-83542, CVSS 9.8）、画面定義の読み込みを攻撃者が制御できる未認証RCE（CVE-2026-68524）、保存ビューの認可バイパスからRCEに至る問題（CVE-2026-73578）、認証済みユーザーによる Groovy サンドボックス回避（CVE-2026-82912／82960, CVSS 8.8）など。ほかにSQLインジェクション、XXE、SSRF、ハードコードされた JWT 鍵による管理者権限取得の可能性も挙げられている。記事時点で悪用確認・公開PoCはないとされるが、OFBiz は過去に CVE-2024-32113／38856／45195 が CISA KEV に登録された実績があり、パッチ公開後の差分解析で悪用が始まりやすい製品である。Apache 公式アドバイザリは本稿では未確認（二次情報）。

**関連CBKドメイン**: ドメイン8（ソフトウェア開発セキュリティ）、ドメイン7（セキュリティ運用）、ドメイン6

**コラム**: ウィジェット／テンプレートエンジンへのインジェクションは「入力を実行可能な式として解釈する」設計の典型で、入力検証と出力エンコーディング、サンドボックスの設計（ドメイン8）の重要性を示す。実務では、悪用未確認でも過去に KEV 入りした製品ファミリーの未認証RCEは優先度を引き上げ、資産台帳（ドメイン2/7）で OFBiz を使う社内外システムを特定して早期にパッチ適用する。インターネット公開の管理・ログイン画面へのアクセス制限も暫定策として有効。

**参照**: [Daily Security Review: Apache OFBiz 24.09.08 Fixes 46 Flaws](https://dailysecurityreview.com/?p=45466) / [Security NEXT 2026/11/06 一覧](https://www.security-next.com/192441)

## 3. 【国内】消防庁「武力攻撃事態等安否情報収集・提供システム」に不正アクセス — 委託先（富士ソフト）からの報告でサービス停止

**概要**: 消防庁は2026-11-05、同庁の安否情報システムに第三者による不正アクセスがあったと公表した（消防庁報道発表PDF、Security NEXT／ScanNetSecurity 等も報道）。運用保守を担う委託事業者の富士ソフトから報告を受けたもので、現時点で個人情報の漏えいは確認されていない。原因・侵入経路・侵入日時・影響範囲は調査中で、外部アクセスを遮断しサービスを停止して影響を調査している。再開時期は未公表。CVE・攻撃者は不明。同様に、ScanNetSecurity は同日付でシステム業者経由の不正アクセスが続く旨を報じており（大分県の防災メール配信システム新規登録停止は10月16日に報道）、委託先・保守ベンダー経由の侵害が公共分野で続いている可能性がある（ただし相互の関連は未確認）。

**関連CBKドメイン**: ドメイン1（セキュリティとリスクマネジメント）、ドメイン7（セキュリティ運用）

**コラム**: 重要インフラに近い公共システムで、侵入の最初の通知が委託先から届いた点は、サードパーティリスク管理（ドメイン1）の契約・報告義務・ログ共有の事前取り決めが機能したと見ることもできるが、同時に委託先環境の可視性不足も示す。有事用システムは「使われない時期の保守アクセス」が長期間放置されやすく、特権アクセス管理（ドメイン5/7）と保守回線の棚卸しが要点。インシデント時の事業継続（BCP）の観点では、停止を決断する判断基準と代替手段を平時に定義しておく必要がある。

**参照**: [消防庁 報道発表（PDF）](https://www.fdma.go.jp/pressrelease/houdou/items/261105_kokuun_1.pdf) / [ビジネス+IT](https://www.sbbit.jp/article/cont1/188127) / [ScanNetSecurity 2026-11-09 記事一覧](https://scan.netsecurity.ne.jp/)

## 4. OpenAI「GPT-6 Cyber」発表 — Linux LPE エクスプロイト948件・Firefox脆弱性81件・Brotli CVE-2026-111497（CVSS 9.2）を報告、Preparedness Framework で「Critical」

**概要**: OpenAI は2026-11-05（米国時間木曜）、サイバー向けモデル「GPT-6 Cyber」を発表した（The Hacker News 11-06付）。ベンチマーク ExploitGym で 48.5%（GPT-5.6 Cyber は 32.1%）、スコープ遵守率は 99.93%（従来 94.49%）とされ、OpenAI の Preparedness Framework では「Critical」に分類された。自律パイプラインにより 948件の Linux ローカル権限昇格エクスプロイトを生成し、Firefox の未知の高深刻度脆弱性81件、さらに Brotli の重大な脆弱性 CVE-2026-111497（CVSS 9.2、境界外書き込み）を発見したと主張している。当面は API と Codex 経由で「Daybreak Red」の選抜顧客に提供される。一方、ScanNetSecurity（11-09）は英国政府機関が「AI製マルウェアが2028年までに重要インフラ向けランサムウェアに使われる可能性が非常に高い」と警告したと報じている（会員限定のため見出しのみ確認）。数値は発表元の主張で、第三者検証は未確認。JPCERT/CC Weekly Report（11-05）にも Brotli CVE-2026-111497 が掲載されている。

**関連CBKドメイン**: ドメイン1（セキュリティとリスクマネジメント）、ドメイン6（セキュリティの評価とテスト）、ドメイン8（ソフトウェア開発セキュリティ）

**コラム**: AIによる脆弱性発見・エクスプロイト生成の自動化は、「公開から悪用までの時間（time-to-exploit）」をさらに圧縮する前提で、パッチ管理SLAと脅威モデリング（ドメイン1/7）を見直す根拠になる。防御側にとっても、自社コードのAI支援ファジング・レビューをテスト計画（ドメイン6）に組み込む余地が生じる。Brotli のような圧縮ライブラリはブラウザ・サーバ・CDN に広く組み込まれるため、SBOM による依存関係の把握（ドメイン8）が即応性を決める。

**参照**: [The Hacker News: OpenAI launches GPT-6 Cyber](https://thehackernews.com/2026/11/openai-launches-gpt-6-cyber-after-ai.html) / [JPCERT/CC Weekly Report 2026-11-05](https://www.jpcert.or.jp/wr/2026/wr261105.html) / [ScanNetSecurity](https://scan.netsecurity.ne.jp/article/2026/11/09/56711.html)

## 5. Claude Code の許可設定ファイル（.claude/settings.local.json）に秘密情報 — 公開GitHub上の1,122件のコピーに認証情報（Apiiro）

**概要**: Apiiro の調査として The Hacker News（2026-11-07付）が報じたもの。Claude Code の「今後確認しない（Don't Ask Again）」で許可したコマンド等が記録される `.claude/settings.local.json` が公開 GitHub リポジトリにコミットされ、確認された 1,122件のファイルのすべてに少なくとも1つの秘密情報（パスワード・API キー等）が含まれていた。通知を受けた企業の1社は、鍵が有効であったと確認している。原因は、許可リストに認証情報付きのコマンド文字列（例: 環境変数や引数に鍵を含む呼び出し）が保存され、`.gitignore` 設定漏れでコミットされる構造と報じられている。CVE は付与されておらず、ベンダー脆弱性ではなく利用慣行・設定の問題である。単一情報源（The Hacker News）であり、Apiiro の原レポートは未確認。

**関連CBKドメイン**: ドメイン8（ソフトウェア開発セキュリティ）、ドメイン5（IAM）、ドメイン2（資産のセキュリティ）

**コラム**: AIコーディングツールのローカル設定・履歴ファイルは、機密情報を含み得る新しい成果物（アーティファクト）であり、リポジトリのコミット前スキャン（pre-commit のシークレット検出）と `.gitignore` の標準化（ドメイン8）が必須。漏えいした鍵はローテーションと失効が前提で、IAM（ドメイン5）では短寿命トークン・最小権限への移行が被害を限定する。ポリシー面では、AIツールの利用標準（何を許可リストに入れてよいか）を策定し、教育に含めるべきである。

**参照**: [The Hacker News: Claude Code's "Don't Ask Again" file exposes passwords and keys](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html)

## 用語解説

- **CA（認証局）**: TLS証明書など電子証明書を発行・管理する組織。信頼の起点となる。
- **認可（Authorization）**: 認証済みの主体に、どの資源へどの操作を許すかを決める仕組み。
- **セルフ登録**: 利用者が自分でアカウントを作成できる機能。公開範囲の設定を誤ると悪用される。
- **CVE / CVSS**: 脆弱性の共通識別番号／深刻度の共通評価尺度（0〜10）。
- **RCE（遠隔コード実行）**: 攻撃者が遠隔から任意のコードを実行できる脆弱性。
- **ウィジェットインジェクション**: 画面部品の定義に悪意ある入力を差し込み、サーバ側で実行させる攻撃。
- **Groovy サンドボックス**: スクリプト実行環境を制限する仕組み。回避されると任意コード実行につながる。
- **XXE / SSRF / SQLインジェクション**: XML外部実体の悪用／サーバに内部への要求を行わせる攻撃／DB問い合わせの改ざん。
- **JWT**: JSON Web Token。署名鍵が固定値だと偽造により権限を奪われ得る。
- **KEV**: CISAの「悪用が確認された既知の脆弱性」カタログ。
- **PoC**: 脆弱性の実証コード。
- **SBOM**: ソフトウェア部品表。依存コンポーネントの把握に使う。
- **ExploitGym**: AIのエクスプロイト生成能力を測るベンチマーク（本稿では記事の記述に基づく）。
- **Preparedness Framework**: OpenAIのリスク評価枠組み。「Critical」は最上位のリスク区分。
- **LPE（ローカル権限昇格）**: 一般ユーザーが管理者権限を得る攻撃。
- **Brotli**: Web等で使われる圧縮ライブラリ。
- **ファジング**: 異常な入力を大量に与えて脆弱性を探すテスト手法。
- **シークレット検出（pre-commit）**: コミット前に鍵・パスワードの混入を検査する仕組み。
- **パスワードリスト型攻撃（クレデンシャルスタッフィング）**: 流出済みID・パスワードを他サービスで試す攻撃。
- **多要素認証（MFA）**: 複数の要素を組み合わせる認証。
- **サードパーティリスク管理**: 委託先・取引先に起因するリスクの管理。
- **BCP**: 事業継続計画。
- **能動的サイバー防御**: 攻撃の兆候を平時から把握し、被害前に対処する政府の取り組み。
- **重要インフラ**: 電力・金融・交通など停止すると社会に重大な影響が出る分野。
- **JPCERT/CC / JVN**: 日本のCSIRT／脆弱性情報データベース。
- **アタックサーフェス**: 攻撃者が到達可能な接点の総体。
- **GA（一般提供）**: 製品の正式リリース。
